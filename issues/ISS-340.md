## Description
`Basic.Io` records a need for `panic`, but Lane has no source-level contract
for an intentionally non-returning fatal operation. The default command
runtime registers only `println`. The current runtime-import ABI accepts
monomorphic direct results and has no `Never` or non-returning result shape;
Basic's ordinary nominal `Void` cannot cross that ABI.

A minimal `(String) -> Unit ! Io = extern("panic")` declaration could be made
to terminate through runtime-import failure, but its type falsely exposes a
normal `Unit` return, cannot inhabit an arbitrary expression result, and makes
every embedding responsible for a conventional symbol. Declaring the extern
pure would be worse because an optimizer may remove an unused pure call.

Fatal panic is also distinct from the recoverable typed host failures deferred
by ISS-216. It terminates execution and is not a `Result` value or a handled
Lane effect.

## Design
Make one explicit language and runtime decision before adding the Basic API.
The preferred general contract is a source-callable fatal primitive with a
bottom result, expressible as either `[T](String) -> T ! Io` or
`(String) -> Never ! Io`, and lowered to a backend-independent fatal
terminator. A closed intrinsic such as `%panic` may provide the source seam;
the compiler must validate its signature structurally rather than recognize a
Basic declaration by name.

The ADR must specify bottom typing, observability, optimization barriers,
cleanup during fatal unwinding, artifact compatibility, interpreter behavior,
Wasm behavior, and CLI error presentation. If the accepted scope is only a
statement-position abort, document why the smaller Unit-returning runtime
import is sufficient and standardize its host registration across supported
embeddings.

Recoverable failure remains ordinary `Result` or algebraic-effect design and
is out of scope.

## Acceptance Criteria
- [ ] An accepted ADR defines whether source panic uses a bottom/fatal primitive or a deliberately statement-only Unit-returning runtime import.
- [ ] The source type, effect contract, optimizer observability, and non-returning semantics agree.
- [ ] Interpreter and Wasm executions terminate with the same structured fatal outcome and do not continue after panic.
- [ ] Fatal unwinding and owned-value cleanup behavior are specified and covered at both production backend boundaries.
- [ ] The default Lane command and documented embedding seam support the chosen Basic API without symbol-specific compiler guessing.
- [ ] Panic in discarded statement position remains observable.
- [ ] If the general bottom contract is chosen, panic can typecheck at least two distinct result types without unsafe casts.
- [ ] Recoverable host failures remain outside this issue and no second implicit failure channel is introduced.
- [ ] `moon info`, `moon fmt`, `moon test --target native`, and the integration gate pass.
