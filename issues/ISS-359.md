## Description
LoisVM function-table canonicalization reorders bodies and merges duplicate
runtime imports. A provenance array created before this boundary would drift
unless the canonicalization owner remaps and merges it with the image.

## Design
Canonicalization produces one product containing the canonical VM CFG image and
its canonical function provenance. VM CFG finalization preserves FunctionId
order and passes the sidecar unchanged to the final bytecode observation. The
persisted bytecode image remains free of exploration metadata.

## Acceptance Criteria
- [ ] Canonicalized VM CFG functions and origins have identical cardinality and
      FunctionId indexing.
- [ ] Runtime import sorting and deduplication preserve all relevant origins.
- [ ] Final bytecode functions retain the canonical VM CFG provenance exactly.
- [ ] No artifact or bytecode schema change is introduced.
- [ ] Tests cover reordering, duplicate imports, bodies, and failure paths.
