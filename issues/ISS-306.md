# ISS-306: Make alpha equivalence transitive and shadowing-consistent

## Metadata

## Description
Definitional equality is not an equivalence relation, and the alpha kernel's two
engines disagree about what a shadowed binder means. Both defects are measured,
not argued.

Intransitivity: `push_unique_effect_term` (buslane.mbt:901) deduplicates the
terms of ONE side's row using the cross-side oriented binding context. Under a
binding `(X, Y)` with `X != Y`, comparing the left side's `Parameter(X)` with
itself consults the binding and returns false, so duplicates survive and the
term counts diverge:

- `Forall([x], () -> Unit ! {x ∪ x})` ≡ `Forall([x], () -> Unit ! {x})` — true
- `Forall([x], () -> Unit ! {x})` ≡ `Forall([y], () -> Unit ! {y})` — true
- `Forall([x], () -> Unit ! {x ∪ x})` ≡ `Forall([y], () -> Unit ! {y})` — false

Shadowing inconsistency: `alpha_equal_parameter` (buslane.mbt:997) scans
bindings first-match-first, so a rebound id resolves to the OUTERMOST binding,
while `substitute_with_bound` (buslane.mbt:1323) blocks on membership, giving
the INNERMOST binder ownership. The same shadowed name means two different
things depending on which engine reads it.

## Reproduction
```moonbit
let metadata = MetadataRegistry::MetadataRegistry()
let x = metadata.define_type_parameter("X", Effect)
let y = metadata.define_type_parameter("Y", Effect)
let left : Type = Forall(
  [x],
  Function([], Primitive(Unit), Union([Parameter(x), Parameter(x)])),
)
let same : Type = Forall([x], Function([], Primitive(Unit), Parameter(x)))
let right : Type = Forall([y], Function([], Primitive(Unit), Parameter(y)))
assert_true(metadata.types_definitionally_equal(left, same))
assert_true(metadata.types_definitionally_equal(same, right))
assert_false(metadata.types_definitionally_equal(left, right)) // intransitive
```

## Design
Same-side deduplication must not consult the cross-side context: canonicalize
each side under an identity view (or a same-side context) before pairing terms.
Binding lookup must resolve innermost-first (iterate bindings in reverse) so the
alpha reading of shadowing agrees with substitution's. Fix the relation for all
inputs; do not exclude shadowed or duplicated rows by convention.

## Acceptance Criteria
- [x] The three-way comparison above is transitive.
- [x] A shadowed binder resolves identically under `alpha_equal_with` and `substitute_with_bound` (regression test pinning both engines on one term).
- [x] Existing equality, subeffect, and consumability tests stay green.

## Close Notes
Two one-owner fixes in `modules/buslane/buslane.mbt`, no pub surface change:

- `canonical_effect_terms` now collects each row under `AlphaContext::same_side`
  (cross-side bindings dropped, binder compatibility kept), so a side's
  canonical form no longer depends on what it is being compared against.
  Same-side sameness is plain alpha equivalence; the oriented context
  participates only in cross-side pairing.
- `alpha_equal_parameter` scans bindings innermost-first (`rev_iter`), giving a
  rebound id to its nearest enclosing binder — the same reading
  `substitute_with_bound`'s bound-list enforces.

Regressions in `buslane_test.mbt`, red/green measured against the pre-fix
relation: "definitional equality dedupes a row without the cross-side bindings"
(the issue's three-way repro) and "alpha equality gives a rebound id to its
innermost binder" both fail before and pass after; "substitution and alpha
equality agree on shadowed binders" pins the substitution half (beta hands an
argument to a rebound binder, substitution blocks, equality reads the result as
the inner binder) and guards against a future capture regression.

Verified: `moon test --target native` — Milky2018/buslane 64/64, workspace
1432/1432; `moon info && moon fmt` — no `.mbti` drift. ISS-307 is now unmasked
as predicted: a type captured by `synthesize_type_apply` no longer alpha-reads
as the intended one. No suite failure surfaced because the pipeline mints fresh
ids and never rebinds an in-scope id; ISS-307 remains open.
