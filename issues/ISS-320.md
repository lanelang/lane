## Description
Which values a literal admits depends on which literal it is: an `INT` is an
`I64` on its own, an `I32` inside `i32(..)`, a Unicode scalar inside
`char(..)`, and a name's unique after `#`. A semantic action cannot report an
error, so those checks lived in `validate_literal_tokens`, a pass over the
token stream that re-derived each position from its neighbours — and the
actions then called `validated_literal`, which aborted if the pass and the
grammar ever disagreed.

So the fact "which spelling is which literal" had two owners: the grammar's
productions and the pre-pass's neighbour tests. They agree today, which is why
the abort is unreachable, but nothing makes them agree, and a disagreement
crashes rather than reports. `parse_text_int` had the quieter version of the
same problem: a unique that did not fit became `0`.

## Design
Give the lexer the whole spelling. Every literal but the unit becomes one
token carrying the value it denotes, read where the wrapper that names it is
recognised — which is the only stage that both knows the position and can
refuse a value. The grammar then has nothing to classify.

The pieces of a wrapped literal are read through the same trivia rule the main
loop uses, so the notation accepts exactly what it accepted before, including
whitespace and a comment between a wrapper and its payload.

Superseded alternatives: a screening pass between the lexer and the parser,
which keeps the classification in one place but leaves the raw tokens declared
as terminals no production reduces; and folding the check into the actions,
which the generated parser cannot express.

## Acceptance Criteria
- [x] One stage decides which spelling is which literal.
- [x] Every rejection is reported, not asserted.
- [x] The accepted notation is unchanged, trivia included.
- [x] A unique that does not fit is an error rather than a different unique.

## Close Notes
`read_word` and `read_quoted` in `modules/buslane/text/lexer.mbt` own the
literal vocabulary. `Token` lost `INT`, `FLOAT_BITS`, `STRING`, `HASH`, `TRUE`,
`FALSE`, and the four wrapper keywords, and gained `LITERAL(Literal)` and
`NAME((String, Int))`; the `literal` production is now the unit and that token.
`validated_literal`, `validate_literal_tokens`, its three neighbour tests, and
`parse_text_int` are deleted. Net 141 lines removed against 132 added, and 13
fewer terminals in the package's public interface.

The value parsers stay where they were and now report through `lexer_fail`, so
every message a caller used to receive is unchanged — the existing rejection
test asserts all eight verbatim and needed no edit.

Two things this makes observable that were not: a name's unique that does not
fit an `Int` is now an error rather than silently `0`, and the trivia a wrapped
literal admits is now pinned by a test rather than implied by the pre-pass
having worked on tokens.

Verified: `moon check --target native --warn-list +73` clean (0 warnings);
`moon test --target native` 1475/1475; examples gate exit 0 against the pinned
fixture; the generator still reports exactly one shift-reduce conflict. The
round-trip matrix from ISS-313, which covers all 24 literal payloads including
every IEEE value class and both integer extremes, is what made the change safe
to attempt.
