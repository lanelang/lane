# ISS-372: Make Explore stage and scale facts single-owned

## Description
Explore repeats its stage catalog in `ExploreStageId`, an eighteen-field
`ExploreStages` record, `ordered`, `index`, `explore_stage_ids`, fixed builder
storage, and positional `finish` reconstruction. Adding or removing a stage
requires coordinated edits that independently reproduce order, key, title,
domain, text format, and storage position.

The driver also traverses Buslane, the open effect-lowering AST, Runtime ANF,
VM CFG, and Bytecode to define structural scale facts. Wasm already produces
its scale in the backend owner. The driver therefore depends on every IR
constructor and becomes another traversal owner whenever an IR changes.

Explore additionally publishes empty scale arrays for Syntax, Resolved,
Checked, Buslane Module, and Buslane Linked stages. For the Coroutine Scheduler,
the rendered Buslane Module grows from 144 lines and 4,992 bytes to a 499-line,
14,485-byte linked program, but no typed metric explains that growth.

This leaves ISS-357's stated fixed-metric-set contract incomplete and prevents
Explore from attributing link-time growth or specialization cleanup without
ad-hoc text parsing. These tree IRs do not own stable per-function identities,
but they can and should expose deterministic aggregate facts.

## Design
Define one ordered Explore Stage Catalog whose descriptors own identity, key,
title, domain, text format, and protocol order. Store report stages as one
ordered collection rather than a parallel record with one field per stage.

One exhaustive observation analysis produces every reconstructible structural
fact. A public IR does not gain a scale interface merely because Explore is its
only consumer. Source compilation produces detached source-stage aggregates;
Buslane exposes one reused query across its many stages; Explore privately
measures Runtime ANF, VM CFG, and bytecode. Transformation owners produce only
facts that cannot be reconstructed: function identity and provenance, private
effect-lowering snapshots, link retention, and Wasm emission facts.

Define a fixed metric set appropriate to each stage family. Syntax, Resolved,
and Checked should cover declarations and expression/type structure; Buslane
Module and Linked should cover top terms, functions, nodes, calls, runtime
generic structure, externals, and per-module contribution where the link owner
has that information. Metadata allocation totals must not be presented as live
declaration counts. Emit meaningful zero values in stable order.

Do not parse pretty text, invent traversal-order function IDs, recover module
ownership from names, expose private effect-lowering time-state ASTs, or make
the presentation layer traverse compiler IR.

## Acceptance Criteria
- [x] One Stage Catalog is the sole producer of stage identity, order, key,
      title, domain, and text format.
- [x] `ExploreStages` no longer duplicates the catalog as one field per stage;
      builder and protocol output consume the ordered catalog.
- [x] Syntax, Resolved, Checked, Buslane Module, and Buslane Linked snapshots
      publish deterministic nonempty fixed metric sets.
- [x] Reconstructible public-IR metrics have one observation producer; public
      single-consumer Scale interfaces are absent.
- [x] Identity-less tree IRs publish aggregate metrics without fabricated
      per-function identities.
- [x] Link metrics attribute retained top terms and value bindings to their
      input modules using linker-owned facts.
- [x] One black-box Explore report explains the Module-to-Linked growth and the
      subsequent specialization reduction with structured metrics.
- [x] Repeated exploration produces identical metric names, order, and values.
- [x] Effect-lowering observations remain available without exposing the
      private transitional AST as an Explore dependency.
- [x] Ordinary compilation, linking, effect lowering, and Wasm generation do
      not construct disabled observations through no-op callbacks.
- [x] ISS-357 and ISS-361 documentation is updated so their delivered scope and
      this follow-up are consistent.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

  irrecoverable transformation facts and avoids single-consumer public seams.

## Close Notes

- 2026-08-17: Replaced the repeated stage record, switches, positional builder,
  and finish reconstruction with one ordered Stage Catalog and an opaque
  `ExploreStages` collection. Explore protocol v6 publishes the catalog
  projection directly.
- 2026-08-17: A design audit rejected public single-consumer Scale interfaces.
  Source scale is private to compilation observation; Buslane retains one reused
  structural query; Runtime ANF, VM CFG, and Bytecode are measured privately by
  Explore. Effect-lowering, link retention, provenance, and Wasm emission remain
  transformation-owned because those facts cannot be reconstructed later.
- 2026-08-17: Added linker-owned per-module input/retained top-term and
  value-binding observations at the reachability boundary without caching
  derived scale in `LinkedProgram`. Black-box Explore coverage demonstrates
  module-to-link growth and removal of generic binders/type applications during
  specialization.
- 2026-08-17: Split observed and ordinary execution paths around one canonical
  implementation so disabled observation no longer renders or traverses stage
  snapshots. Removed misleading constructor/operation totals derived from the
  unpruned metadata registry.
- 2026-08-17: Verified `moon info`, `moon fmt`,
  `moon check --target native --warn-list +73`, `moon test --target native`, and
  all 6 Lane Wasm package tests.
