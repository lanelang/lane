## Description
Module exports, imports, and linked exports represent one symbol reference with
a separate kind plus five optional identity fields. This admits missing,
conflicting, and extra identities and duplicates shape validation throughout
lowering, artifact encoding, and linking. The binary format independently
encodes all five options, so impossible in-memory states are also serializable.

## Design
Replace the kind-plus-options representation with one closed symbol-reference
enum whose variants carry the correct identity:

- type;
- data constructor;
- effect;
- operation;
- field selector;
- value.

Keep the authored/exported name and module/fingerprint metadata outside the
enum. Use the same symbol-reference model for lowered exports, artifact
imports, and linked exports. Hard-switch the artifact schema and remove the old
shape validators and compatibility representation.

## Acceptance Criteria
- [ ] Export and import values cannot contain zero, multiple, or kind-mismatched symbol identities.
- [ ] Lowering, artifact models, binary codecs, fingerprints, validation, and linking use one closed symbol-reference enum.
- [ ] Field selectors and ordinary values remain semantically distinct even though both carry a Buslane value identity.
- [ ] Old kind-plus-five-options fields and their shape-matching helpers are deleted.
- [ ] Artifact schema versions are updated once and old payloads fail with the normal unsupported-schema diagnostic.
- [ ] Roundtrip and malformed-tag tests cover every symbol-reference variant.
- [ ] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
