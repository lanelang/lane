## Description
The root glossary still says floating and integer literals change width under an
expected F32 or I32 context and explicitly tells readers to avoid suffixed
syntax. The accepted language-surface glossary instead fixes unsuffixed forms to
F64 or I64 and defines `i32`, `i64`, `f32`, and `f64` suffixes. Both documents
currently claim to describe the active language.

## Design
Make the root glossary summarize the accepted suffix and unsuffixed-form rules,
with the language-surface context and current ADR as the detailed owners. Mark
historical context-directed behavior as superseded rather than leaving two
active definitions.

## Acceptance Criteria
- [x] Root definitions of integer and floating literals agree with current
      suffix and unsuffixed-form semantics.
- [x] No current context document describes explicit numeric suffixes as syntax
      to avoid.
- [x] The canonical detailed rule has one owner and other current documents link
      to or summarize it without introducing a second rule.
- [x] Documentation checks and `git diff --check` pass.

## Close Notes

The root glossary now summarizes the spelling-directed numeric model: bare
integer and floating forms select I64 and F64, while the four attached lowercase
suffixes select their named primitive directly. It no longer describes suffixes
as syntax to avoid or gives expected types authority over literal width.

The Language Surface glossary remains the canonical terminology owner and ADR
0127 remains the complete normative spelling and typing decision. Root entries
link to both instead of restating the full grammar. The former relationship
summary was updated to the same rule, and superseded ADRs remain explicitly
historical rather than competing current context.
