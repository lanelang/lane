# ISS-313: Give the core syntax one renderer across pretty and text

## Metadata
- Type: task
- Status: closed
- Priority: 2
- Labels: area/buslane, cleanup, docs, agent
- Assignee: -
- Created: 2026-08-03
- Updated: 2026-08-04
- External ref: modules/buslane/pretty.mbt, modules/buslane/text/core.mbt

## Description
Two complete, independent renderers own the Buslane surface syntax: pretty.mbt
implements `Pretty` for every core type (753 lines), and text/core.mbt defines
its own `type_doc`/`effect_doc`/`expr_doc` family (757 lines, 49 Document
builders, zero calls into the Pretty impls). Even the effect-flavor prefix
logic is written twice (`type_parameter_flavor_prefix` in pretty.mbt:178,
`type_parameter_flavor_doc` in text/core.mbt:361).

CONTEXT.md already states the law being violated: "Buslane display output and
canonical text should share one core-language syntax strategy rather than
defining separate expression languages." Under the one-owner-per-fact rule,
every future syntax change (as with the recent flavor addition) must be made
twice, and nothing tests that the two renderers agree.

## Design (decided)
Measurement first: the two files are not two implementations of one syntax.
`pretty.mbt` emits a readable infix notation that no parser accepts and that
drops identities (its declaration renderers ignore the id they are handed);
`text/core.mbt` emits a field-labelled prefix notation that the generated
parser accepts and that preserves name, unique, and id. They are two
languages with different jobs.

Human decision: unify them into one language, the readable one, made
parseable. Differences that remain are rendering options in one place, not a
second implementation.

The unified notation, which both surfaces emit and the parser accepts:

- Identities stay explicit: every metadata declaration names its id and its
  `name#unique`, so what a diagnostic prints can be pasted into a fixture.
  Declarations are flat rather than nested inside their owner, because a data
  constructor or operation may legally exist without its owner listing it and
  nesting would lose it.
- Types read as they do today in diagnostics: `(I64) -> String ! Io`,
  `forall[tparam#0]. body`, `type[tparam#0] => body`, `type#0[args]`.
- Effects: `{}`, `Io`, `effect#0[args]`, `tparam#0`, `{a, b}`.
- A generic argument is a type unless prefixed with `!`, which marks an
  effect. This keeps the one genuinely ambiguous case — a bare type parameter,
  which may stand for either — unambiguous without wrapping every argument.
- Literals carry their type where the spelling would otherwise be ambiguous:
  bare integers are `I64`, and `i32`, `char`, `f32`, `f64` are explicit.
  Floats always use their exact bit pattern, so the one notation round-trips
  without a second float spelling.

Superseded alternatives: keeping both notations while sharing only the spellings
they already agree on leaves every construct's structure decided twice, which
is what this issue is about. Deleting the text package outright is defensible
under the standard — nothing in this repository consumes it and the binary
codec already provides the decoder — but it removes a documented public API
and forecloses third parties producing Buslane by hand, which the module
advertises.

## Acceptance Criteria
- [x] One function family owns each construct's spelling; the other surface delegates.
- [x] The flavor prefix, and every future syntax addition, has exactly one definition site.
- [x] A round-trip test covers the canonical path (parse . render == id) for a program exercising flavors, hidden witnesses, and handlers.
- [x] The escape table has one definition that both directions read.
- [x] Parenthesization follows an explicit level model rather than a per-construct test.
- [x] The grammar can group an arbitrary expression, as it already could a type.
- [x] Every AST constructor round-trips in every position it can occupy, checked as a matrix rather than by sample.

## Close Notes
Buslane now has one text language. The `Pretty` implementations own every
construct's spelling and `CanonicalTextWriter` renders through them, so what a
diagnostic prints is what the parser accepts; `text/core.mbt` lost its 600-line
second renderer and is now the parse boundary plus token labels. Net −901 lines.

Three changes made the display notation parseable without losing what
round-trip needs:

- Declarations carry their id and `"occurrence"#unique`, and are flat rather
  than nested in their owner. The old display renderers took an id and ignored
  it, which is exactly what made them unparseable; nesting cannot round-trip
  because an entity may legally exist without its owner listing it.
- A generic argument is a type unless prefixed with `!`. A bare type parameter
  is the one spelling that could mean either, so the marker sits on the effect
  side rather than wrapping both.
- Literals name themselves where a bare spelling would be ambiguous, and
  floats always use their exact bit pattern, so one spelling round-trips every
  IEEE value class instead of one readable and one exact.

A real ambiguity surfaced under measurement rather than review: `(A) -> (B) ->
C ! E1 ! E2` does not say which arrow performs which effect, and the generated
parser rejected it. A function-typed result is now parenthesized, and the
grammar shares one `paren_types` production between a parameter list and a
parenthesized type so the decision stays LALR(1). Pinned by a test that also
checks a parenthesized type with no arrow after it still reads as that type.

One shift-reduce conflict remains, reported by the generator without a
location. It is the `paren_types` decision — shift on `->` (parameter list)
rather than reduce (parenthesized type) — and shifting is the correct reading;
both branches are covered by the disambiguation test above.

Verified: `moon check --target native --warn-list +73` clean (0 warnings);
`moon test --target native` 1460/1460; examples gate exit 0 against the pinned
fixture; the comprehensive round-trip test covers flavors on types, type
parameters and effects, hidden witnesses on both construct and perform,
handlers with operation alternatives and resume, match with all three
alternative forms, and a polymorphic recursive binding.

### Reopened close (2026-08-04)

The notation now round-trips as a matrix rather than a sample. Four changes,
one per cause:

- One escape table, `text_string_escapes` in `modules/buslane/pretty.mbt`. The
  renderer reads it forwards and the lexer backwards, so a spelling cannot be
  added to one direction alone. Before this the reader accepted five escapes
  and the writer emitted none, so any name or string literal carrying a quote
  or a backslash — which generated binders do carry — was unreadable.
- An explicit level per position, `TypeLevel` and `ExprLevel`, ordered as the
  grammar's own chains. A construct is parenthesized when its level exceeds
  what its position admits. This replaces the single hand-written test for a
  function-typed result, which covered one of the eight type shapes that need
  it, and it is what makes `Apply(Forall(..), ..)` and `Call(Let(..), ..)` read
  back as themselves.
- Parenthesized grouping for expressions, which types already had. Without it a
  binding form could not be a callee at all, so the level model had nothing to
  emit there.
- A construct's own list always writes its brackets; a list that only adorns
  one writes them when it has members. `Apply(c, [])` and `TypeLambda([], b)`
  are values the AST admits and were rendering as `c` and as an unparseable
  `fn { .. }`. The grammar now accepts an empty list wherever a construct
  requires the brackets.

Two shapes could not be settled inside the notation, for different reasons:

- `Effect::Union([])` and `Effect::Empty` are one row with two encodings —
  `canonicalize_effect_with` already collapses them — so no notation can tell
  them apart. The fix is one owner rather than a second spelling: the verifier
  rejects an empty union, and `{}` reads as `Empty`. Nothing in the compiler
  produced one; the whole suite and the examples gate pass with the rule on.
- `F64(NaN)` cannot be compared through the AST at all, because `Literal`
  derives its equality from `Double` and no NaN equals itself. The property is
  stated where it is observable, on the bit pattern.

The grammar still reports exactly one shift-reduce conflict, unchanged: adding
`"(" expr ")"` introduced none, because `()` is decided by one token of
lookahead.

Regressions: `modules/buslane/text/roundtrip_test.mbt` is the matrix, and it is
black-box — it reaches the notation only through `CanonicalTextWriter` and
`parse_program_text`. Red measured before the fix at 88 failures (36 type, 4
effect, 40 expression, 8 literal, plus the declaration-name test), green after.

Verified: `moon check --target native --warn-list +73` clean (0 warnings);
`moon test --target native` 1473/1473; examples gate exit 0 in 1m45s against
the pinned fixture.
