# ISS-343: Verify compiler-produced bytecode before persistence

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: area/lanec, area/loisvm, bytecode, verifier, persistence, architecture, tests, agent
- Assignee: codex

- Updated: 2026-08-10
- External ref: modules/lanec/vmcfg/finalize.mbt, modules/lanec/artifact/linked_program.mbt

## Description
The VM CFG finalizer and LoisVM lowering return a directly constructed
`BytecodeImage`, and the artifact path can encode that image without first
calling the package-owned bytecode verifier. Decoder, interpreter, and Wasm
consumers verify later, but that allows a compiler defect to cross the
persistent-artifact boundary and be reported as a downstream load failure.

## Design
Make the compiler-owned image production boundary return only verified
bytecode. Reuse `loisvm/bytecode`'s existing verifier instead of duplicating its
rules, and translate a verification failure into a structured compiler-defect
result before an artifact or binary payload is exposed. Keep the lower-level
trusted encoding helper package-private to malformed codec fixtures. Normal
persistence performs verification and encoding atomically inside the bytecode
package, so caller assertion cannot bypass the trust boundary. Do not introduce
an opaque verified-image wrapper while `BytecodeImage` contains mutable arrays;
without deep freezing, aliases could invalidate such a capability after
verification.

## Acceptance Criteria
- [x] Every production path from VM CFG finalization to a linked-program
      artifact verifies the complete `BytecodeImage` before returning or
      encoding it.
- [x] Verification failure is reported as a structured compiler defect and no
      artifact bytes or executable image are returned.
- [x] Directly constructed trusted-test images remain possible only through an
      explicitly named test or internal seam.
- [x] A regression injects an invalid finalized image at the boundary and proves
      that persistence is rejected there rather than by a later consumer.
- [x] `moon info`, `moon fmt`, `moon test --target native`, the integration gate,
      and `git diff --check` pass.

## Notes
- 2026-08-08: Review found `vmcfg.finalize` returning a raw image and
  `executable_to_loisvm_artifact` wrapping it directly, even though the bytecode
  verifier already exists and is mandatory at consumer boundaries.
- 2026-08-09: Reopened because `unchecked_bytecode_image_to_binary` remains a
  public package API and the production artifact encoder calls it across the
  package boundary. Naming a public bypass `unchecked` does not make it an
  internal test seam. The bytecode package must own an unforgeable
  verifier-accepted encoding boundary; malformed encoding belongs only to
  package-private codec fixtures.
- 2026-08-10: Implementation resumed after ISS-335 closed the verifier's exact
  object-shape gap. The selected design keeps one public atomic checked encoder,
  makes malformed semantic encoding a white-box-only seam, and lets the artifact
  layer wrap only verifier-accepted bytecode bytes.

## Close Notes

Closed after the bytecode package became the sole owner of semantic-image
encoding. Its public encoder verifies and encodes atomically; the raw encoder is
private and used only by white-box malformed-codec fixtures. Artifact framing
therefore receives only verifier-accepted bytecode bytes, while
`executable_to_loisvm_binary` preserves lowering failures and typed bytecode
verification defects as distinct `LoisvmBinaryError` variants.

The current artifact schema and valid encoded bytes are unchanged. Black-box
tests cover valid round trips and persistence rejection, white-box tests retain
malformed decoder fixtures without exposing a production bypass, all 1601
native tests pass, and the integration gate completes successfully.
