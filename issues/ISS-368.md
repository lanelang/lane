## Description
The Coroutine Scheduler still grows substantially across selective CPS and
runtime-representation lowering. In the current release Explore report, Core
optimized has 14 functions, 214 nodes, and 26 calls, while selective CPS has
44 functions, 396 nodes, and 55 calls. Post-CPS Core optimization only reduces
that to 38 functions, 353 nodes, and 49 calls. The selective-CPS text is 2.69
times the Core-optimized text.

The initial VM CFG still contains 22 physical callable-adapter functions, 56
closures, 57 environments, 15 erase operations, and 11 unerase operations.
Some growth is intrinsic to handlers and escaping continuations, but the
compiler does not yet prove which generated workers and representation bridges
are semantically necessary.

## Design
Complete the typed callable-instance plan from ISS-363, then make it the sole
producer of representation-worker demand. Classify every synthesized CPS
function, callable adapter, and erase/unerase boundary by the typed source or
ABI transition that requires it. Canonical runtime ABI keys produce at most one
worker, while open uses retain the generic implementation.

Eliminate generated functions and bridges that exist only because producer and
consumer representations were planned independently. Preserve adapters for
genuinely escaping values whose source and target runtime ABIs differ. Do not
recognize generated code from names, introduce size or frequency heuristics,
or infer specialization demand during emission.

## Acceptance Criteria
- [x] Explore attributes every remaining callable adapter and erase/unerase
      operation to a typed ABI transition owned by the specialization plan.
- [x] A canonical runtime ABI specialization key produces at most one worker,
      and the generic implementation remains available for open uses.
- [x] Closed producer-consumer paths with equal canonical runtime ABIs contain
      no callable adapter or erase/unerase bridge.
- [x] Escaping continuations and aggregates retain only the adapters required
      by an observable runtime ABI difference.
- [x] The Coroutine Scheduler shows a strict reduction from the recorded 22
      physical adapters and 26 erase/unerase operations without increasing its
      Core, VM CFG, bytecode, or Wasm scale to move the cost elsewhere.
- [x] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Close Notes

Closed on 2026-08-26 after replacing recursively embedded callable ABI trees
with a verified, nominal callable-contract graph. Recursive contracts are
reserved, filled, canonicalized by graph partition refinement, and verified
before Physical ANF emission. Exact callable interfaces retain their semantic
parameter/result projection and occurrence-local evidence morphism; physical
contract equality never licenses borrowing another endpoint's binder scope.

Representation transitions now have canonical typed identities and exact
produced/consumed VM CFG anchors. Adapter recipes derive evidence captures only
from operations that actually consume evidence, replacing the old free-binder
scan. VM CFG representative merging verifies each retained event against its
operation and requires equivalent transition streams. Explore protocol 7
exports the callable graph, transition catalog, occurrences, boundaries, and
adapter provenance.

The final Coroutine Scheduler report has 60 initial VM CFG functions, 300
instructions, 21 callable adapters, 14 erase operations, 11 unerase operations,
52 closures, 53 environments, 47 indirect calls, and 10,332 rendered Wasm
instructions. Relative to the sound baseline this removes four functions, 31
instructions, one adapter, one erase, four closures, four environments, and
four indirect calls without increasing a later-stage scale. JIT and interpreter
both print `1112211322`. The 73 lowering tests, 70 backend-conformance tests,
all 1,806 native tests, and the release examples corpus pass.
