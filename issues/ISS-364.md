# ISS-364: Preserve effect semantics until runtime ANF projection

## Metadata
- Type: bug
- Status: closed

## Description
Residual-effect erasure rewrites every function effect and nested effect
argument to `Empty`, then returns another ordinary Buslane program. It also
mutates shared metadata, so an observer retaining an earlier CPS stage can see
its effect facts silently changed by later lowering.

This overloads `Empty`: before erasure it means observational purity, while
after erasure the same syntax means that effect information is unavailable.
Analyses can no longer distinguish a semantic fact from discarded data.

## Design
Keep the verified post-CPS Buslane program effect-aware. Run the ordinary
effect-aware Core optimizer after monadic continuation lifting. Fuse the
one-way runtime type projection with Core-to-ANF lowering, snapshotting metadata
before projection, and return a distinct `RuntimeAnfProgram`. LoisVM lowering
consumes runtime ANF; no public phase exposes an effect-erased value as an
ordinary Buslane program.

Do not add an `Unavailable` effect, reinterpret `Empty` by phase, retain a
second residual-erasure pass, or let runtime layout lowering inspect source
effects.

## Acceptance Criteria
- [x] CPS Core and its observers retain authoritative residual effects through
      post-CPS optimization.
- [x] Handler-arm, final-clause, and continuation-suffix effects remain visible
      before runtime ANF projection and prevent invalid dead-code elimination.
- [x] Runtime ANF projection snapshots metadata and cannot mutate the source
      Buslane registry.
- [x] No public residual-effect erasure returns an ordinary Buslane program.
- [x] Executable and Explore expose effect-aware CPS Core, while LoisVM lowering
      consumes the distinct runtime ANF boundary.
- [x] Live architecture documents describe `Empty` consistently as
      observational purity.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Notes
- 2026-08-12: Independent audits of handler synthesis, selective CPS,
  continuation lifting, and verifier boundaries found no pre-erasure case where
  residual `Empty` ceased to mean observational purity. The defect is the
  erasure representation, not the CPS ABI.

## Close Notes

Deleted residual-effect erasure and kept verified CPS Core effect-aware through
the second ordinary Core optimization. Runtime projection now snapshots
metadata and constructs the nominal `RuntimeAnfProgram`; LoisVM consumes that
projected metadata as its sole type owner. Explore protocol v5 exposes the
effect-aware CPS stage instead of an ordinary Buslane value containing fake
`Empty` effects.

Black-box and stage-observer regressions cover handler-arm, final-clause, and
continuation-suffix residual `Io`. The full native suite passed 1679/1679; the
real example 37 interpreter run printed `1112211322`.
