## Description
The repository requires black-box tests by default, reserving white-box tests
for private invariants that cannot reasonably be observed through public APIs.
The current test layout does not meet that rule. The 2026-08-03 audit found 222
explicit black-box test declarations and 1166 white-box declarations across 38
and 128 files respectively. At least 318 white-box declarations exercise public
behavior and can move to black-box coverage directly or after a small split.

The highest-risk suites bypass the actual product boundary: LSP tests call the
private message handler instead of `run_server`, CLI tests call command helpers
instead of the executable, and compiler diagnostic tests use private request
and result adapters instead of the public compilation outcome.

## Design
Move public behavior tests to `_test.mbt` files and keep `_wbtest.mbt` only for
explicit private invariants. Split mixed files instead of broadening production
APIs for test convenience. Test compiler diagnostics through `CompilationOutcome`,
analysis through `SemanticWorkspace`, LSP protocol behavior through `run_server`,
and CLI behavior through the built executable. Move backend conformance tests
out of the executable package into a dedicated integration-test package that
imports stable public compiler, lowering, and runtime APIs.

Preserve focused white-box coverage for typechecker elaboration shapes,
specialization planning, CPS ABI ownership, VM CFG transforms, runtime ARC and
heap invariants, and other state that has no stable public observation.

## Close Notes

Rebalanced the repository around public test boundaries without widening
production APIs. Public Buslane, codec/text, diagnostics, lexer, types,
formatter/parser, analysis, artifact, compiler-facade, backend conformance, and
LSP behavior runs from black-box test packages. The LSP boundary executes a
complete framed editing and shutdown session through `run_server` and preserves
graceful, premature, and transport-closed termination as public results.

The integration gate builds Lane once and tests the real executable. Its
examples corpus covers `fmt`, `check`, `run`, `explore`, `compile`, `link`, and
`exec`. The dedicated CLI check now covers root and subcommand help, required
argument failures, invalid run targets, exact status codes, and fatal
statement-position `panic` behavior in both default and `--no-jit` execution.
The equivalent help, parser-failure, and panic assertions were removed from
white-box suites; `command_wbtest.mbt` retains only the private
argparse-to-`LaneCommand` mapping invariant.

`docs/whitebox-test-boundaries.md` records one concrete private invariant for
each of the 118 retained `_wbtest.mbt` files, including shared setup files.
`tools/check-whitebox-test-boundaries.sh` compares that exact allowlist with the
repository, and the integration gate rejects new, removed, duplicated, or
unjustified white-box files.

Verified 43 focused Lane tests, `moon check --target native --warn-list +73`,
`moon test --target native` (1598/1598),
`tools/check-lane-integration.sh`, `moon info && moon fmt`, tracker derivation,
and `git diff --check`.
