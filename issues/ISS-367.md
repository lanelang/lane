# ISS-367: Make Explore WAT faithfully render emitted instructions

## Description
Explore's WAT stage renders valid instructions from the executable Wasm module
as the invalid token `unsupported.instruction`. F32 load, store, constant,
arithmetic, comparison, and conversion instructions are one reproduced family;
the executable binary remains valid because the Wasm encoder consumes the
module directly.

This makes Explore's principal backend artifact unparsable and prevents it from
serving as trustworthy evidence when diagnosing runtime failures. The text
renderer and the executable encoder currently have different instruction
coverage.

## Design
Define the WAT renderer over every instruction Lane's Wasm compiler can emit.
Use exact standard mnemonics and immediates, including canonical float literal
spelling that preserves IEEE bits. Keep the existing fail-visible fallback for
instructions outside Lane's emitted subset; do not silently drop instructions
or render comments that describe a different module.

Extend the public round-trip tests with a compact bytecode image that exercises
the emitted numeric instruction families. Parse and validate the complete
rendered module so presentation is checked through the same public boundary
Explore consumes.

## Acceptance Criteria
- [x] Every instruction currently emitted by the LoisVM Wasm compiler has an
      explicit valid WAT rendering.
- [x] F32 operations in Explore contain no `unsupported.instruction` marker.
- [x] Focused WAT tests parse and validate representative F32 constants,
      memory operations, arithmetic, comparison, conversion, and bitcasts.
- [x] Unsupported future instructions remain visibly invalid rather than being
      dropped or disguised as comments.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Close Notes

Completed the WAT renderer over the full instruction subset currently emitted
by LoisVM. The 22 missing constructors covered F32 memory, constants,
arithmetic, comparisons, conversions, and reinterpretation, plus five integer
operations used by the same lowering paths. The invalid fail-visible fallback
remains for future instructions outside that subset.

F32 and F64 constants now use the shared deterministic float formatter for
finite values, infinities, and signed zero, while NaN sign and payload are
rendered explicitly in standard WAT syntax. A public round-trip regression
parses and validates the complete numeric module and checks both NaN payloads.

Verification passed `moon info`, `moon fmt`, strict native check, all 82 LoisVM
Wasm tests, and all 1,691 native tests. A release Explore run for
`84_f32_operations.lane:answer` contained valid F32 WAT and no
`unsupported.instruction` marker.
