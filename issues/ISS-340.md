# ISS-340: Define a source-level fatal panic contract

## Description
`Basic.Io` records a need for `panic`, but Lane has no source-level contract
for an intentionally non-returning fatal operation. The default command
runtime registers only `println`. The current runtime-import ABI accepts
monomorphic direct results and has no `Never` or non-returning result shape;
Basic's ordinary nominal `Void` cannot cross that ABI.

A minimal `(String) -> Unit ! Io = extern("panic")` declaration could be made
to terminate through runtime-import failure, but its type falsely exposes a
normal `Unit` return, cannot inhabit an arbitrary expression result, and makes
every embedding responsible for a conventional symbol. Declaring the extern
pure would be worse because an optimizer may remove an unused pure call.

Fatal panic is also distinct from the recoverable typed host failures deferred
by ISS-216. It terminates execution and is not a `Result` value or a handled
Lane effect.

## Design
Make one explicit language and runtime decision before adding the Basic API.
The preferred general contract is a source-callable fatal primitive with a
bottom result, expressible as either `[T](String) -> T ! Io` or
`(String) -> Never ! Io`, and lowered to a backend-independent fatal
terminator. A closed intrinsic such as `%panic` may provide the source seam;
the compiler must validate its signature structurally rather than recognize a
Basic declaration by name.

The ADR must specify bottom typing, observability, optimization barriers,
cleanup during fatal unwinding, artifact compatibility, interpreter behavior,
Wasm behavior, and CLI error presentation. If the accepted scope is only a
statement-position abort, document why the smaller Unit-returning runtime
import is sufficient and standardize its host registration across supported
embeddings.

Recoverable failure remains ordinary `Result` or algebraic-effect design and
is out of scope.

## Acceptance Criteria
- [x] An accepted ADR defines whether source panic uses a bottom/fatal primitive or a deliberately statement-only Unit-returning runtime import.
- [x] The source type, effect contract, optimizer observability, and non-returning semantics agree.
- [x] Interpreter and Wasm executions terminate with the same structured fatal outcome and do not continue after panic.
- [x] Fatal unwinding and owned-value cleanup behavior are specified and covered at both production backend boundaries.
- [x] The default Lane command and documented embedding seam support the chosen Basic API without symbol-specific compiler guessing.
- [x] Panic in discarded statement position remains observable.
- [x] If the general bottom contract is chosen, panic can typecheck at least two distinct result types without unsafe casts.
- [x] Recoverable host failures remain outside this issue and no second implicit failure channel is introduced.
- [x] The pinned Basic revision exports
      `panic : (String) -> Unit ! Io = extern("panic")`, and its gitlink is part
      of the Lane commit that closes this issue.
- [x] A black-box Basic or Lane command regression invokes the shipped
      `Basic.Io.panic` API and proves that execution does not continue.
- [x] `moon info`, `moon fmt`, `moon test --target native`, and the integration gate pass.

## Close Notes

- 2026-08-08: Accepted ADR-0130's deliberately statement-oriented contract:
  `panic : (String) -> Unit ! Io`. `Unit` is only the direct ABI carrier; the
  SDK binding always raises the existing structured runtime-import failure.
- 2026-08-08: Added `RuntimeBinding::fatal_string`, registered `panic` in the
  default command, and added the Basic declaration without compiler symbol
  guessing or an artifact change.
- 2026-08-08: The discarded-statement regression exposed that LoisVM's Wasmoon
  JIT hostcall dispatcher had not installed its global synchronization hooks.
  A failure was recorded in the Store but invisible to the active native Wasm
  globals, so execution continued. The backend now synchronizes globals around
  every JIT hostcall; interpreter and Wasm both stop before the continuation.
- 2026-08-08: Runtime SDK, command, backend-conformance, existing fatal-unwind,
  full native, and integration gates pass.
- 2026-08-10: Basic commit `56e30a1` exports the accepted statement-oriented
  `panic` API. The CLI regression now imports `Basic.Io.panic` from the pinned
  library in both default and `--no-jit` modes and proves that `println("after")`
  is unreachable. The bottom-result criterion is not applicable because
  ADR-0130 deliberately selected the Unit carrier contract.
