## Description
Turn Explore into a structured observability boundary that reports stable
stage-scale metrics and explicit function provenance from final Buslane through
ANF, VM CFG, LoisVM bytecode, and Wasm. The current rendered snapshots make
large functions visible only by manually parsing text and comparing unrelated
stage-local identifiers.

## Design
Explore protocol facts remain non-persisted sidecars. Metric collectors consume
typed IR rather than rendered text. Function identities are allocated by the
transformation that creates them, function planning atomically records every
FunctionId and its origin, canonicalization remaps the same provenance, and the
Wasm compiler records actual function indices as it emits them. Presentation
only consumes these structured facts.

The first provenance root is a value in the final effects-erased Buslane
program, or an explicitly classified synthetic function. Source-span lineage
is outside this epic because Buslane intentionally does not carry source spans.

## Acceptance Criteria
- [ ] Completed Explore stages expose deterministic typed scale metrics.
- [ ] Every initial VM CFG and final bytecode function has exactly one origin.
- [ ] Every emitted or imported Wasm function has an explicit source or
      synthetic role.
- [ ] Explore can trace a Wasm function through bytecode and ANF to a final
      Buslane value when one exists.
- [ ] JSON and native HTML consume the structured facts without parsing labels,
      text, spans, or numeric layout conventions.
- [ ] Explore schema evolution and metric definitions are documented.
- [ ] Ordinary bytecode, Wasm, and linked artifact output remain unchanged.
- [ ] Native tests and the repository integration gate pass.
