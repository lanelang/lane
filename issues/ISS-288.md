## Description
Effect lowering runs five stages. Only the two endpoints are Buslane programs;
the three in between carry `lanec`'s extended `Expr`, which adds `Bind`,
`Invoke`, `Install`, and `OpenContext`. The Buslane verifier cannot read those,
so nothing type-checks them.

| stage | representation | checked by |
| --- | --- | --- |
| effect-lowering input | Buslane | `verify_program`, since ISS-284 |
| handlers-elaborated | extended | nothing |
| monadic-transformed | extended | nothing |
| selective-CPS | extended | `validate_mon_trans_output` |
| open-contexts-resolved | extended | `validate_mon_trans_output` |
| monadic-lifted | Buslane | nothing yet, see ISS-284 |

`validate_mon_trans_output` is not a type checker. It walks for residual
`Invoke`, `Install`, `Bind`, concrete `OpenContext`, algebraic latent effects,
and algebraic effect parameters or arguments. It never compares a type against
the type a position requires, which is the class of defect ISS-283 and ISS-284
were both about.

It is also incomplete on its own terms: `validate_mon_trans_expr` skips a match
alternative's `type_binders`, which is why the two lowering paths could disagree
about them for as long as they did.

## Design
Extend the Buslane verifier to the extended IR rather than writing a second one.
The extended forms have declared semantics — an `Invoke` performs one operation,
an `Install` handles one effect, a `Bind` sequences a monadic computation — so
each has a typing rule, and the rest of the language is already covered.

A shared checker also removes the drift between `types_definitionally_equal` in
one checker and hand-written structural walks in the other.

## Acceptance Criteria
- [ ] Every effect-lowering stage is type-checked, not only walked for banned
      forms.
- [ ] A match alternative's type binders are checked.
- [ ] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.
