## Description
`OwnerExpression.owner` and `qualified_type_name` were typed as the whole
syntax `Type`, though the grammar can only ever build a bare or qualified name
there. Extending such a path with another segment therefore had to match a
type with seven shapes and answer for five it never sees:
`extend_owner_type_name` aborted on them and `extend_qualified_type_name`
returned its input unchanged, which would drop a segment.

Neither arm is reachable — an owner path has two productions, one producing
`Name` and one calling the extension, which maps `Name` to `QualifiedName` and
`QualifiedName` to itself — but the invariant lives in an induction across two
files rather than in the value's type.

## Design
Carry the path. `NominalTypeName` holds an optional module path, a name, and a
span; `extended` appends a segment and `to_type` produces the `Type` the rest
of the syntax expects. Both are total, so neither arm exists.

The two spans an extension writes differ by case and are preserved exactly: a
bare name has no earlier path to inherit from, so the extension's own span
stands for it, while a qualified one carries the span of the name being
demoted to a component.

## Acceptance Criteria
- [x] No arm answers for a shape no derivation reaches.
- [x] Spans are unchanged.
- [x] The grammar reports no new conflicts.

## Close Notes
`extend_owner_type_name` and `extend_qualified_type_name` are deleted, replaced
by `NominalTypeName::extended` and `NominalTypeName::to_type`.
`owner_path_expression` yields an `OwnerPathExpression` carrying the path, and
`owner_expression` converts once at the point where a type argument may be
applied — which is the only place an owner stops being a path.
`qualified_type_name` yields the path too, converted at its three use sites.

Spans were the risk, since the two extension sites wrote different ones for the
module path and a refactor that unified them would have moved every qualified
name's span. They are reproduced case by case, and the parser's span-fidelity
tests pass unchanged.

`moon test --target native` 1475/1475; examples gate exit 0 against the pinned
fixture; the generator reports the same single shift-reduce conflict as before.
