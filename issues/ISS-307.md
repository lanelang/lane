# ISS-307: Enforce binder freshness or make type substitution capture-avoiding

## Description
`Type::normalize` documents "capture-avoiding substitution" (buslane.mbt:1227),
but `substitute_with_bound` (buslane.mbt:1323) only blocks substitution of
shadowed parameters; it never renames a binder whose id occurs free in a
replacement. The safety of every substitution therefore rests on a
binder-freshness convention that no verifier checks — an invariant enforced by
comment.

The verifier itself is a victim: `synthesize_type_apply` (verify.mbt:598)
computes instantiated types with `body.substitute(...)`. When an in-scope
parameter id is also used as a nested binder inside the callee's type — legal
today, both ids come from ordinary `define_type_parameter` calls — the computed
type captures, and every downstream check runs against the wrong type. Measured:

```moonbit
// g : Forall([x], Forall([y], (x) -> Unit))
// expr = Λy. g[y]
let facts = query.synthesize(TypeLambda([y], TypeApply(Ref(g), [TypeArgument(Parameter(y))]))).unwrap()
assert_eq(facts.type_(), Forall([y], Forall([y], Function([Parameter(y)], Primitive(Unit), Empty))))
// The outer y was captured by g's inner binder.
```

Because of ISS-306's first-match lookup, alpha then reads the captured type as
the intended one — two defects composing to hide each other. Fixing either in
isolation will surface the other; land them together or in sequence with tests
covering the composition.

## Design
Decide where the law lives, then enforce it in exactly one place:
- Either the verifier enforces global binder freshness (each TypeParameterId
  bound at most once per program, never rebinding an id already in scope), and
  substitution may stay cheap; note that beta reduction can duplicate binders,
  so normalization output must be exempt from the uniqueness law or must
  refresh binders as it duplicates.
- Or substitution becomes genuinely capture-avoiding (rename binders on
  collision) and shadowing stays legal.
The doc comment must state whichever contract is real.

## Close Notes
Chose a third point in the design space: substitution is **capture-rejecting**.
The freshness law lives in the substitution engine itself and is enforced at
the one point every substitution flows through — `lookup_argument` raises
`CapturedTypeParameter(parameter~, binder~)` when a replacement's free
parameter would be bound by a binder the walk crossed. The two listed options
were rejected on measurement grounds: a global binder-uniqueness census flags
legitimate sharing (a declaration's Forall prefix and its implementation's
TypeLambda binders are one entity; the CPS dictionary schema quotes operation
binders in field types), and renaming-based capture avoidance would mint
registry ids inside equality queries. Shadowing stays legal: a replacement's
own binder planted under a same-id binder is bound inside the replacement,
not captured, and ISS-306's innermost-first reading keeps it correct — pinned
by "substitution keeps a replacement's own binder without renaming".

The verifier consumes the refusal as diagnostics: new
`VerifyDiagnosticKind::TypeSubstitutionFailure(TypeSubstitutionError)`, and
all five verifier substitution sites (TypeApply body, Construct payloads,
Perform payloads and result, handler-alternative payload and resume types) go
through one reporting helper that falls back to the uninstantiated type.
`Type::normalize`'s doc no longer claims capture avoidance; the beta path
reports through the existing `InvalidBetaSubstitution` plumbing unchanged.

Regression tests: engine-level refusal and benign-shadowing acceptance,
normalize-path rejection, and one verifier test per substitution site family
(TypeApply — the issue's reproduction, now Err; Construct; Perform;
handler-alternative via a hidden binder reusing the payload's inner binder).
Pre-fix behavior was already measured by this issue's reproduction (the
captured type synthesized cleanly); the new tests reference the new error
API, so they pin the fix by construction rather than by a red run.

Verified: `moon check --target native --warn-list +73` clean;
`moon test --target native` 1439/1439 (7 new); `.mbti` diff is exactly the
two new enum cases; `tools/check-lane-run-examples.sh` showed 5 failures
identical with and without this change — later measured transient: the gate
had raced a live mid-edit of Basic's `string.lane`, and a rerun exits 0 with
all examples passing (gate-hermeticity question filed as ISS-316). The pipeline
itself never captures: the whole suite passes with the engine now refusing,
which is the measured form of the freshness discipline the compiler already
follows.
