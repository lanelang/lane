## Description
`PhysicalProgram::RuntimeImport` still embeds the target-independent semantic
`lane_runtime.RuntimeImport`. The Wasm target then reconstructs physical import
types and adapters from semantic value kinds. This leaves the last compiler
trust seam dependent on the obsolete multi-target host protocol.

## Design
Make the Physical Program explicitly Wasm-specific. Its import entry owns the
core module name, field name, exact core-Wasm parameter/result contract, and
the callable identity required by physical call sites. Physical Lowering
produces that fact once; Wasm planning and emission only consume it. Establish
the canonical WASI Preview 1 catalog in the same owner package and certify
standard imports against it.

Do not preserve `RuntimeValueKind` as a parallel type universe and do not make
the Wasm emitter infer import shapes from Lane types.

## Acceptance Criteria
- [x] Physical import entries contain complete core-Wasm import identities and
      types without depending on `lane_runtime.RuntimeImport`.
- [x] One canonical WASI Preview 1 catalog owns standardized import signatures.
- [x] Physical verification rejects invalid module/field/type contracts.
- [x] Wasm planning and emission consume the verified physical import contract
      without reconstructing it.
- [x] Black-box emitted-module tests inspect the complete import section.
