## Description
VM CFG cleanup currently propagates aliases and duplicate constants only within
one block. Branch folding sees only constants defined in the same block, scalar
operations are not evaluated, and block parameters do not participate in a
whole-function constant lattice. Residual constants and dead control flow
therefore survive into ARC insertion, physical-slot allocation, and Wasm.

## Design
Make VM CFG the sole owner of conventional residual cleanup. Compute a sparse
constant fixed point over reachable blocks, instruction results, and block-edge
arguments. Rewrite scalar operations to canonical constants, fold branches and
switches, remove unreachable blocks, then reuse the existing use-definition
and liveness facts for dead pure instructions and block-parameter cleanup.

Constant evaluation must preserve WebAssembly/Lane numeric semantics. Trapping
integer division and remainder, floating-point arithmetic, calls, allocation,
ownership, projections, globals, and byte-sequence operations remain dynamic
unless their semantics can be proven without executing or suppressing a trap.
No call-count, function-size, iteration-budget, or Wasm-emitter heuristic may
decide the transformation.

## Acceptance Criteria
- [x] Constants propagate through aliases, block parameters, and dominated CFG
      regions to a structural fixed point.
- [x] Pure non-trapping integer and Boolean operations fold; potentially
      trapping operations retain their original execution behavior.
- [x] Constant branches and switches remove unreachable blocks before ARC and
      physical-slot planning.
- [x] Dominator-scoped scalar common subexpressions are reused; side-effecting
      and ownership instructions never become common-expression candidates.
- [x] Focused regressions cover joins, loops, conflicting incoming values,
      unreachable predecessors, traps, and CSE dominance.
- [x] Explore records before/after VM CFG, Physical, slot, and Wasm metrics for
      the scheduler and pinned Basic entry with unchanged output.
- [x] `moon info`, `moon fmt`, strict native check, native tests, valid examples,
      dual-engine representative executions, and Basic tests pass.

## Close Notes

- Replaced the local-only constant pass and its arbitrary iteration bound with
  a finite sparse constant lattice over executable CFG edges, block parameters,
  aliases, and scalar instruction results. Integer overflow follows the target
  representation; division and remainder fold only when doing so cannot
  suppress a WebAssembly trap.
- Added dominator-tree scalar CSE. It reuses only trivial, non-erased scalar
  expressions and leaves ownership, allocation, calls, globals, projections,
  byte sequences, representation bridges, and trapping conversions outside its
  contract.
- Focused tests cover unreachable and conflicting join predecessors, invariant
  loops, default switches, trapping division, dominance, and sibling branches.
- Scheduler metrics and output remain unchanged. Basic changes from 632 / 3,997
  / 6,332 initial VM CFG blocks / instructions / values to 628 / 3,917 / 6,323;
  Physical changes from 757 / 4,672 / 4,067 blocks / instructions / slots to
  752 / 4,588 / 4,033; Wasm changes from 38,480 instructions / 4,213 locals to
  38,133 / 4,177. Indirect calls fall from 120 to 118.
- Verified `moon info`, `moon fmt`, strict native check, all 1,736 native tests,
  all valid examples, JIT/interpreter scheduler and handler outputs, and all 12
  Basic test commands. The installed release completed `../basic/test.sh` in
  1.10 seconds on this host.
