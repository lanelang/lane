# ISS-429: Certify compiler-produced WebAssembly before persistence

## Metadata
- Type: bug
- Status: blocked
- Priority: 1
- Labels: architecture, wasm, artifact, verifier, correctness, agent
- Assignee: unassigned
- Created: 2026-08-31
- Updated: 2026-08-31
- External ref: modules/lanec/artifact/wasm_executable.mbt

## Description
The Wasm target returns a mutable `wasm_types.Module`, and the artifact package
encodes it directly into successful output. Production compilation does not run
the WebAssembly validator; validation occurs only in tests and when the runtime
later loads bytes. The compiler can therefore report success and persist an
invalid sole-target artifact whose backend defect is discovered only by a
consumer.

## Design
Make Wasm artifact construction the single trust boundary for module emission,
encoding, and validation. Return an opaque verified artifact or verified module
whose constructor validates the generated module and the exact encoded bytes.
Runtime loading must continue to validate untrusted external bytes, but it must
not be the first verifier for bytes produced successfully by the compiler.

Keep validation errors structured as compiler defects with target provenance.
Do not return partial bytes on failure, and do not duplicate Wasm validation
rules in Lanec.

## Acceptance Criteria
- [ ] Successful compiler output is represented by an opaque validated Wasm
      module or artifact rather than a raw mutable module.
- [ ] The exact encoded artifact bytes pass the canonical Wasm parser and
      validator before the compiler returns success.
- [ ] Invalid compiler-generated Wasm becomes a structured target compiler
      defect and produces no partial artifact.
- [ ] Runtime loading still validates arbitrary external bytes at its own trust
      boundary.
- [ ] A focused white-box regression injects invalid target output and proves
      that persistence rejects it before runtime loading.
- [ ] Existing raw-Wasm round-trip, execution, example, and Basic gates pass.

## Notes
- 2026-08-31: The Wasm validator is currently a test-only dependency of the
  target package, while the runtime loader owns the first production check.
- 2026-08-31: Validation against published `Milky2018/wasmoon@0.12.6` found an
  external packaging blocker. The canonical parser and validator execute on
  native, but their published module is native-only because they live beside
  JIT packages; depending on them makes Lanec fail dependency planning for
  `wasm`, `wasm-gc`, and `js`. Copying the exact parser and validator sources
  into an all-target test module passed parse, validation, and execution on all
  four targets, so the implementation itself is portable. This issue unblocks
  when Wasmoon publishes the pure parser/validator from an all-target module or
  package. Lane must not duplicate the validator, make the compiler native-only,
  or conditionally skip artifact certification.
