## Description
Artifact models, fingerprints, validation, inspection, binary encoding, and
link adapters are currently divided among `compile/artifact_core`,
`compile/artifact_binary`, `module/compile`, and `module/link`. As a result,
`module/compile` owns both compilation orchestration and a large part of the
persisted artifact boundary, while artifact packages live under the nominally
stable compiler facade.

## Design
Create one coherent top-level `lanec/artifact` ownership boundary for artifact
models, fingerprints, semantic validation, inspection, and the public
encode/decode surface. A subordinate binary implementation package is
acceptable if dependency analysis requires it, but callers should see one
artifact API.

`module/compile` should produce complete modules and convert them to artifacts
through the artifact boundary. `module/link` should consume validated link
objects without owning persisted codecs. Remove old package entrypoints after
callers migrate; do not retain compatibility wrappers.

## Acceptance Criteria
- [ ] Artifact models, schema versions, fingerprints, validation, inspection, and public codecs have one documented owner.
- [ ] `module/compile` no longer owns artifact schema or binary concerns.
- [ ] `module/link` remains independent of persisted encoding and execution targets.
- [ ] CLI and compiler callers import the stable artifact boundary rather than incidental internal packages.
- [ ] No package cycle or duplicate artifact model is introduced.
- [ ] Old artifact package paths and transitional forwarding APIs are removed after migration.
- [ ] Generated interfaces and artifact roundtrip tests reflect only the intended ownership move and schema changes.
- [ ] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
