## Description
Compose stage metrics and transformation-owned function provenance into the
public Explore report, JSON response, and native HTML viewer. Document the
stability contract and finish repository-wide validation.

## Design
Explore schema v2 added metrics to completed snapshots and a report-level
function provenance graph. Protocol v6 closes the remaining identity ownership
gap: a per-function scale observation must consume the same stage-local
identity emitted by the IR construction or function-emission owner. Stages
without such identities publish aggregate metrics only. JSON and HTML
presentation consume those fields directly. ADR-0132 records why observations
remain sidecars rather than persisted IR fields.

## Acceptance Criteria
- [x] Explore report schema version is 6 while entry discovery remains version 1.
- [x] JSON exposes ordered metrics and a complete structured provenance graph.
- [x] Native HTML shows per-stage metrics and source/synthetic function lineage.
- [x] Presentation contains no label, span, text, or ID-offset inference.
- [x] Every per-function scale observation names a provenance graph node and
      consumes its identity from the stage owner.
- [x] Identity-less Buslane and effect-lowering tree stages publish aggregate
      metrics without traversal-generated function IDs.
- [x] VM CFG and Physical Program metrics consume owner-produced provenance, and Wasm
      scale consumes the function-emission sidecar.
- [x] A black-box request traces a named function through ANF, VM CFG, Physical Program,
      and Wasm and covers a synthetic function.
- [x] The ADR and optimization priority document describe the delivered model.
- [x] `moon info`, `moon fmt`, `moon test --target native`, and the Lane Wasm
      package tests pass.
- [x] The release `lane.exe` passes `tools/check-lane-run-examples.sh`.
