# ISS-323: Record child positions in Buslane diagnostic provenance

## Description
Expression provenance records only each node's expression label. Sibling nodes
with the same shape and identity therefore produce identical paths, so a
diagnostic cannot locate which call argument, payload, alternative, or handler
arm failed.

## Design
Add structural child-role frames at the recursive verifier seam. Indexed
collections must carry their index; named children such as callee, body, and
initializer carry a domain role. Keep expression labels as the node identity
inside that path.

## Acceptance Criteria
- [x] Diagnostics from same-shaped sibling expressions have distinct paths.
- [x] The path identifies collection indexes and named child roles.
- [x] A black-box structured test covers two failing call arguments.
- [x] Verifier decisions and diagnostic kinds are unchanged.

## Close Notes
`VerifyFrame::Child` now carries an `ExprChild` domain value. Every recursive
expression-verification edge records its named role or collection index before
entering the child expression, including call arguments, payloads, recursive
bindings, match alternatives, handlers, and operation alternatives.

The black-box regression constructs two identically shaped invalid call
arguments and observes distinct `argument 0` and `argument 1` paths. Existing
structured snapshots were updated to include the more precise paths without
changing their diagnostic kinds.

Verified with `moon check --target native --warn-list +73`, `moon test
modules/buslane --target native` (87/87), the full `moon test --target native`,
`moon info`, and `moon fmt`.
