## Description
The Coroutine Scheduler still grows substantially across selective CPS and
runtime-representation lowering. In the current release Explore report, Core
optimized has 14 functions, 214 nodes, and 26 calls, while selective CPS has
44 functions, 396 nodes, and 55 calls. Post-CPS Core optimization only reduces
that to 38 functions, 353 nodes, and 49 calls. The selective-CPS text is 2.69
times the Core-optimized text.

The initial VM CFG still contains 22 physical callable-adapter functions, 56
closures, 57 environments, 15 erase operations, and 11 unerase operations.
Some growth is intrinsic to handlers and escaping continuations, but the
compiler does not yet prove which generated workers and representation bridges
are semantically necessary.

## Design
Complete the typed callable-instance plan from ISS-363, then make it the sole
producer of representation-worker demand. Classify every synthesized CPS
function, callable adapter, and erase/unerase boundary by the typed source or
ABI transition that requires it. Canonical runtime ABI keys produce at most one
worker, while open uses retain the generic implementation.

Eliminate generated functions and bridges that exist only because producer and
consumer representations were planned independently. Preserve adapters for
genuinely escaping values whose source and target runtime ABIs differ. Do not
recognize generated code from names, introduce size or frequency heuristics,
or infer specialization demand during emission.

## Acceptance Criteria
- [ ] Explore attributes every remaining callable adapter and erase/unerase
      operation to a typed ABI transition owned by the specialization plan.
- [ ] A canonical runtime ABI specialization key produces at most one worker,
      and the generic implementation remains available for open uses.
- [ ] Closed producer-consumer paths with equal canonical runtime ABIs contain
      no callable adapter or erase/unerase bridge.
- [ ] Escaping continuations and aggregates retain only the adapters required
      by an observable runtime ABI difference.
- [ ] The Coroutine Scheduler shows a strict reduction from the recorded 22
      physical adapters and 26 erase/unerase operations without increasing its
      Core, VM CFG, bytecode, or Wasm scale to move the cost elsewhere.
- [ ] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Notes
- 2026-08-15: Current release baseline recorded from a fresh Explore report for
  `37_coroutine_scheduler.lane:answer`. Earlier work reduced the physical
  adapter count from 30 to 17 and bridges from 48 to 26, but the remaining
  expansion still requires typed necessity evidence.
- 2026-08-18: Claimed after ISS-363 closed. A fresh post-ISS-363 Explore report
  is the authoritative baseline: 19 callable adapters, 17 erase, 11 unerase,
  49 closures, 49 environments, 63 functions, 425 instructions, and 50
  indirect calls in initial VM CFG. The older 17/26 counts predated subsequent
  ownership refactors and are retained above only as historical evidence.
- 2026-08-18: Blocked after tracing all 19 canonical adapter recipes to uniform
  nominal containers carrying existential CPS callables. A trial that classified
  the substituted answer type before the generic source ABI removed every
  adapter and reduced initial VM CFG to 41 functions and 203 instructions, but
  backend conformance proved that it merely hid an ABI mismatch: the generic
  source still accepted an erased existential while the rewritten call used a
  concrete value ABI. A scope-aware partial-worker trial reached the same
  boundary at `Task.task[A]`: the allocation site knows `A = I64`, but the
  declaration-owned `Task` family intentionally erases that equality after the
  value escapes. The worker cannot recover it without a distinct, complete
  representation-family identity. ISS-384 is therefore a real prerequisite,
  not an optional follow-up; local adapter cancellation would be unsound.
- 2026-08-18: ISS-384 now provides complete first-order specialized families.
  Corpus validation proved that the Scheduler's remaining carriers additionally
  store callables whose parameters or results carry nominal families. ISS-385
  now owns the total per-value Physical Representation Plan required to assign
  those callable, capture, and nominal ports consistently; until it closes,
  these fields deliberately retain the declaration family.
- 2026-08-21: Unblocked after ISS-385 and ISS-386 established a total physical
  plan and a canonical cleaned pre-ARC function table. The fresh sound baseline
  is 22 callable adapters, 15 erase, 11 unerase, 56 closures, 57 environments,
  64 functions, 331 instructions, and 51 indirect calls in initial VM CFG.
  A smaller intermediate 19-adapter plan was unsound and failed five backend
  conformance cases; it is not an optimization baseline.
- 2026-08-21: Blocked again on ISS-387 after the ISS-385 implementation audit
  found that representation ownership is expressed through a 4,461-line
  sidecar planner and repeated Runtime ANF interpretation. Adapter elimination
  must consume the replacement Physical ANF seam rather than deepen machinery
  scheduled for deletion.
