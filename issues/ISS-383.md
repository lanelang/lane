# ISS-383: Close the Runtime ANF backend ownership seam

## Description
ISS-382 removed Buslane type computation from Runtime ANF, but three residual
ownership leaks prevent the seam from being fully closed. LoisVM extends the
Runtime ANF type-expression catalog while substituting runtime arguments;
synthetic evidence binders use negative projected IDs that Runtime ANF must
reinterpret; and LoisVM recomputes retention from the CPS Core program after
Runtime ANF has already been constructed.

These behaviors are currently correct for the test corpus, but they make
Runtime ANF and LoisVM joint producers of runtime identities and require the
backend to consume two representations of the same executable.

## Design
Keep the Runtime ANF semantic catalog immutable after projection. LoisVM owns a
private runtime-type arena for derived substitution and beta-reduction nodes;
the arena is seeded from, but never writes back into, Runtime ANF.

Represent projected and lowering-synthetic evidence identities explicitly.
LoisVM allocates and describes its synthetic binders in a lowering-owned
catalog; Runtime ANF metadata never interprets a numeric sentinel chosen by a
consumer.

Compute executable retention once before runtime projection and record the
retained top-term fact in Runtime ANF. LoisVM plans only from Runtime ANF and
does not receive or traverse CPS Core for occurrence information. Initializer
order remains the canonical Runtime ANF term order established by ISS-377.

## Acceptance Criteria
- [x] Runtime ANF exposes a read-only runtime type-expression catalog and has no
      public mutating interning operation.
- [x] Runtime substitution and beta reduction intern derived nodes only in a
      private LoisVM lowering arena.
- [x] Evidence identities distinguish projected and synthetic origins without
      negative integer conventions.
- [x] Synthetic evidence arity is owned by LoisVM lowering and is never inferred
      by Runtime ANF metadata.
- [x] Runtime ANF records retained terms from the executable root set; LoisVM
      does not run occurrence analysis over CPS Core.
- [x] Existing public compiler, interpreter, JIT, generic, existential, adapter,
      and initialization regressions remain correct.
- [x] Focused tests prove Runtime ANF observation is unchanged by lowering and
      synthetic evidence cannot collide with projected evidence.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Close Notes

Runtime ANF metadata now exposes no interning operation and returns deep
snapshots, while LoisVM seeds a private `RuntimeTypeArena` for all substituted
and beta-reduced expressions. Runtime evidence identities explicitly distinguish
`Projected` and `Synthetic`; the lowering-owned synthetic catalog owns their
arity and cannot collide with projected binders.

Whole-Program Elaboration now produces one complete retained-value set. Runtime
ANF rejects duplicate or unknown retained identities, validates that the
retained program remains closed,
projects only those terms, and LoisVM plans directly from them. The backend no
longer imports or invokes occurrence analysis over CPS Core.

Focused tests cover deep metadata isolation, derived-arena isolation, identity
domain separation, missing retention dependencies, and dead top-term removal.
Existing generic, existential, callable-adapter, initialization, interpreter,
JIT, and Wasm conformance tests remain green.

Verified with `moon info`, `moon fmt`,
`moon check --target native --warn-list +73`, and
`moon test --target native` (1745/1745).
