## Description
The optimization priority document contains measurements from the deleted
semantic-runtime and bytecode architecture. It cannot identify the dominant
costs of the current raw-Wasm pipeline.

## Design
Use Explore's structured metrics rather than parsing rendered IR. Record a clean
baseline for the coroutine scheduler and pinned Basic suite, including stage
scale, Physical functions and slots, aggregate operations, ARC operations, and
Wasm functions and locals. Record the compiler pipeline and complete JIT and
interpreter command boundaries separately. Do not infer standalone JIT or
execution time by subtracting commands that perform different work.

Timing is contextual evidence, not a semantic threshold. Structural metrics
must be stable and owner-produced. Update the optimization priority document so
that active recommendations describe the current pipeline and historical
numbers are clearly labeled.

## Acceptance Criteria
- [x] A clean, pinned coroutine-scheduler baseline records all relevant
      structured Explore metrics.
- [x] A clean, pinned Basic baseline records image structure and explicitly
      separates the compiler-pipeline, complete JIT, and complete interpreter
      measurement boundaries.
- [x] The optimization priority document no longer presents deleted execution
      architecture as the current baseline.
- [x] The next transformation is justified by current aggregate and ownership
      facts rather than source names, rendered text, or magic thresholds.
