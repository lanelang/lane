# ISS-280: Bound Wasm control-flow nesting by program structure

## Description
CFG-to-Wasm restructuring emits a tower of nested `block`s whose depth grows with
the number of basic blocks in a function rather than with the program's actual
control-flow structure. `examples/valid/78_structural_derivation.lane` reaches
46 levels of nesting inside one function. Before the 2026-08-02 runtime
dependency upgrade it took 58s through the default Wasmoon tier, against 0.04s
through the LoisVM interpreter on the same bytecode.

The source that produces this is a straight-line sequence of statements with a
few `if`s and `match`es, nested at most two or three levels syntactically. At
the deepest point the generated module holds 45 nested `block`s and one `if` —
no loops, no exception regions. That is the shape produced by wrapping every
forward-branch target in its own `block` so `br N` can reach it.

Pre-upgrade measurements. Compiling was not the problem; only the Wasm tier was
slow:

| stage | time |
| --- | --- |
| `lane check` | 0.03s |
| `lane explore` (through Wasm generation, no execution) | 0.06s |
| `lane run --no-jit` (LoisVM interpreter) | 0.04s |
| `lane run` (Wasmoon) | 58s |

Module size does not explain it. `examples/valid/83_utf8_string_char_i32.lane`
emits a larger module and runs 24x faster:

| | 78 | 83 |
| --- | --- | --- |
| wasm text | 560KB | 786KB |
| functions | 145 | 253 |
| largest function | 3379 lines | 1378 lines |
| max nesting | 46 | 16 |
| Wasmoon | 58s | 2.4s |

Truncating example 78's entry body to its first N statements separates size from
depth. Size grows 2.6x while depth grows 4.2x and time grows 80x:

| statements | wasm | max nesting | time |
| ---: | ---: | ---: | ---: |
| 4 | 218K | 11 | 0.76s |
| 7 | 362K | 17 | 4.22s |
| 9 | 395K | 22 | 6.19s |
| 11 | 439K | 34 | 10.39s |
| 13 | 508K | 38 | 23.01s |
| 18 | 560K | 46 | 60.61s |

Structural derivation is not itself sufficient to reproduce the cliff: each
`derive` use measured alone costs 0.4-1.0s. The measurements correlate many
basic blocks in one function, deeper generated nesting, and longer Wasmoon
runtime, but do not isolate which generated property is the direct trigger.

## Design
Restructuring should produce nesting proportional to real loop and conditional
depth. Sibling forward-branch targets in a straight-line region should share one
enclosing level instead of each adding one, and a region with many targets
should fall back to the `loop` plus `br_table` dispatcher that ADR-0076 already
defines for irreducible CFGs, which the ADR explicitly permits selectively.

ADR-0076 says reducible CFGs are restructured into nested `block`, `loop`, and
`if` control but places no bound on depth. Whatever bound is chosen belongs in
that ADR.

Splitting large entry bodies into several functions would also cap depth, but
that changes lowering policy rather than fixing the restructurer, so treat it as
a fallback.

## Acceptance Criteria
- [x] Nesting depth for `examples/valid/78_structural_derivation.lane` is
      proportional to its syntactic nesting rather than its basic-block count.
- [x] The backend switches from linear restructuring to the balanced dispatcher
      at the documented 16-block boundary.
- [x] Regression tests verify the logarithmic dispatcher-depth bound over
      multiple CFG sizes.
- [x] The tests measure structured Wasm instructions rather than HTML markers,
      renderer indentation width, or later report text.
- [x] ADR-0076 states the depth bound.

## Close Notes

- 2026-08-08: CFGs above 16 bytecode blocks now use a loop with a balanced binary dispatcher. Dispatcher selection contributes logarithmic `if` depth instead of one nested `block` per forward target; small reducible CFGs keep structured control and small irreducible CFGs keep the compact `br_table` fallback.
- 2026-08-08: Added an executing 64-block regression that rejects generated control depth above 10. The public examples gate now explores every executable valid fixture and rejects complete rendered Wasm nesting above 23.
- 2026-08-08: Re-measured `78_structural_derivation`: maximum rendered WAT indentation depth fell from the old approximately 49 levels to 20. Scanning all 87 executable valid fixtures found the pinned maximum 23 at example 22.
- 2026-08-08: ADR-0076 records the 16-block cutoff, logarithmic dispatcher bound, and valid-corpus bound. `moon info`, `moon fmt`, 1580 native tests, integration/examples/LSP, and `git diff --check` pass.
- 2026-08-10: Replaced HTML indentation inference with the LoisVM Wasm package's
  structural `maximum_function_control_depth` query. The compiler regression
  and a workspace-native corpus gate share this single traversal; `lane
  explore` remains a separate public-command smoke test.
- 2026-08-10: Directly compiling all 88 executable fixtures measured a maximum
  structured control depth of 21 at
  `examples/valid/22_untyped_lambda_calculus.lane:answer`, below the bound 23.
- 2026-08-14: Removed the standalone valid-corpus executable and its corpus-derived
  depth limit. It duplicated the complete examples compilation pipeline and

  strategy transition at 16 blocks and logarithmic dispatcher depth across
