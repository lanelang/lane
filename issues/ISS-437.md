## Description
Physical match lowering emits projections for every alternative binder.
VM CFG dead-scalar elimination does not include BorrowField or BorrowCapture.
Consuming-projection selection can then promote even unused fields to owned
results, before ARC and physical-slot planning.

The ISS-434 baseline contains these final Physical getters:

```text
borrow_field result, object, 0
borrow_field result, object, 1
release object
return result
```

The first load is unused and overwritten. Another getter is:

```text
consume_fields report, [counts, failures]
release failures
return counts
```

Wasm consuming projection retains selected owned fields and releases the parent.
The unused failures field therefore acquires avoidable retain/release work.
Devirtualized calls also leave unused capture projections in observed bodies.

## Design
Use the authoritative use-definition facts to remove unused projections at the
appropriate VM CFG cleanup boundary, before consuming-projection selection can
promote them. Account for layout/evidence companion uses and multi-result
projections; instruction-text occurrence counts are not a production analysis.

Preserve owner lifetime, parent destruction, and cleanup of unselected fields.
A retained live field can be necessary when its parent is shared: this is not
permission to remove all retain-before-release operations. Use the existing
cleanup/finalization pipeline rather than another standalone use-fact producer.

## Acceptance Criteria
- [ ] Unused scalar field and callable-capture projections disappear before
      physical-slot planning, including projections made dead by devirtualization.
- [ ] An unused owned field is not promoted merely to be retained and released;
      parent destruction and cleanup remain correct.
- [ ] Evidence-only uses, partial multi-result use, shared parents, and returned
      live fields have explicit regression coverage.
- [ ] Ownership/ARC validation and public execution pass; private structural
      tests, if needed, do not encode slot allocation or function order.
- [ ] Record Basic projection and ownership-operation counts plus correctness.
