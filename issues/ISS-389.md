## Description
ISS-387 replaced physical sidecars with structural Physical ANF, but the
representation-specialization implementation still shares one `ImageLowerer`
with VM CFG emission. Physical ANF nodes retain semantic `RuntimeType`, runtime
substitutions, callable-instance queries, and materialization plans. Its
verifier calls back into `ImageLowerer` to reconstruct literal shapes, data
families, callable implementations, and capture contracts.

Consequently generic representation specialization behaves like a collection
of lowering modes rather than one monomorphization boundary. Calls, closures,
data construction, matching, evidence forwarding, and adapters all know how to
select or reconstruct representation variants. The `loisvm_lowering` package
contains more than twenty thousand production lines, and a new physical
operation can require synchronized changes across planning, verification, and
emission.

The old direct emitter is not a valid simplification. Real higher-kinded and
Scheduler regressions prove that the same semantic callable or nominal type
can require distinct generic and closed physical contracts. Those contracts
must remain explicit, but their selection must happen once before VM CFG
construction.

## Design
Treat runtime representation specialization as representation
monomorphization:

```text
Runtime ANF
  -> semantic callable flow
  -> finite representation demand solution
  -> verified Physical ANF
  -> mechanical VM CFG emission
```

The elaborator is the sole owner of generic fallback, canonical physical
specialization keys, one worker per key, representation-family variants,
callable producer and invocation contracts, evidence application, and explicit
representation bridges. Recursive SCC analysis proves the demand set finite;
no call-count, body-size, score, or other heuristic participates in semantics.

Physical ANF is a closed monomorphic execution IR. Every value port names one
physical contract; every callable allocation names one implementation,
invocation, environment, and capture contract; every nominal operation names
one representation family; every cross-contract flow names one explicit
bridge. It contains no semantic type substitution or query back into the
elaborator. Its verifier consumes only Physical ANF and produces a verified
program value.

VM CFG emission consumes only the verified value. It may project already
selected physical facts into VM CFG instructions, but cannot normalize runtime
types, select workers or families, rebuild callable ABIs, or materialize
unplanned adapters. Replace the current shared-state implementation as these
facts migrate; do not retain a compatibility emitter or a second lookup path.

The implementation may remain compiler-private, but its package boundary must
follow the dependency direction: Runtime ANF and target ABI facts enter the
elaborator; verified Physical ANF enters VM CFG construction. The boundary must
not expose the mutable `ImageLowerer` arena.

## Acceptance Criteria
- [x] Physical ANF verification depends only on the Physical ANF value and
      rejects duplicate or incomplete physical facts without querying
      `ImageLowerer`, Runtime ANF metadata, or mutable planning tables.
- [ ] Physical ANF contains no `RuntimeSubstitution`, unresolved representation
      demand, or semantic type whose outer shape must be inspected by VM CFG
      emission.
- [x] Each callable allocation structurally owns its implementation,
      invocation, environment, and capture contracts; references preserve their
      producer contract and unequal consumers name an explicit bridge.
- [x] Each construction, match, projection, and aggregate member names one
      exact nominal representation family selected before VM CFG emission.
- [ ] Generic fallback remains available, each canonical physical key produces
      at most one worker, and recursive demand SCCs are proven finite by the
      representation plan.
- [ ] VM CFG emission consumes only verified Physical ANF and contains no
      representation selection, runtime-type normalization, adapter discovery,
      or family reconstruction.
- [ ] Delete superseded `ImageLowerer` representation state and all duplicate
      planner/emitter query paths in the same migration; do not add a fallback
      lowering path.
- [ ] The higher-kinded identity, refined callable result, structural
      derivation, parser-combinator, data-types-a-la-carte, and Coroutine
      Scheduler black-box regressions pass under the interpreter and JIT where
      applicable.
- [ ] Scheduler Explore output is no worse than the sound ISS-387 baseline of
      64 VM CFG functions, 331 instructions, 22 adapters, 15 erase bridges, and
      11 unerase bridges.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      `moon test --target native`, and the complete valid examples gate pass.

## Notes
- 2026-08-25: A trial restoration of the pre-Physical-ANF direct emitter passed
  the local lowering package but failed the real higher-kinded identity example
  with unequal nominal family identities. It also increased Scheduler adapter
  materializations from 30 to 46. This falsifies semantic-type reconstruction
  as the long-term simplification and establishes explicit per-port physical
  contracts as necessary.
- 2026-08-25: The first migration slice made verification a method of
  `PhysicalAnfProgram`, introduced the verifier-produced
  `VerifiedPhysicalAnfProgram`, and replaced open Runtime ANF callable atoms
  with closed binding, literal, or selected-allocation producers.
- 2026-08-25: Construction and matching now carry immutable Physical ANF data
  family and constructor contracts. VM CFG emission no longer reads source
  constructor/type metadata, applies constructor substitutions, reconstructs
  hidden evidence, classifies matches from `RuntimeType`, or discovers a data
  family while emitting these operations. The private boundary regression
  suite contains 59 passing tests after this slice.
- 2026-08-25: Callable allocations now own the already-planned runtime evidence
  captured by their environment. Evidence application also has a closed
  `Identity | Deferred | Materialize` physical mode, so emission no longer
  reclassifies a source callable from its semantic type. The superseded
  witness equivalence search and semantic local-type classifier were deleted.
- 2026-08-25: VM CFG slot and block-parameter creation no longer applies
  representation substitutions to semantic types. A strict intermediate
  boundary that rejected every unresolved specialized parameter passed all
  1,792 native tests before the emitter-side normalization path was deleted.
- 2026-08-25: Physical functions now own preplanned erased evidence, closed
  representation-worker calls, and callable bridges that name an allocated
  adapter plan plus captured evidence. `FunctionLowerer` no longer carries a
  runtime substitution or specialized-parameter set, and match emission no
  longer changes a substitution scope.
- 2026-08-25: The mutable `ImageLowerer.physical_anf` side channel, deferred
  adapter/layout support lists, and emitter-side adapter/witness discovery were
  removed. Physical ANF is passed explicitly to emission; its adapter verifier
  checks the frozen worker identity, target ABI, and evidence arity. This slice
  is a net deletion of production code and reduces the concrete-answer Explore
  fixture from three runtime layouts to the two layouts that are actually
  materialized.
- 2026-08-25: The lowering package passes 59/59 tests. The complete native
  suite passes 1,792/1,792 after accepting the intentional Explore metric
  reduction. Scheduler, structural derivation, higher-kinded identity, data
  types a la carte, and both parser-combinator examples produce their expected
  results; Scheduler and higher-kinded identity also pass the interpreter.
- 2026-08-25: VM CFG emission no longer accepts a semantic `RuntimeType` when
  allocating a value. The `fresh_slot`, `slot_value`, emitter-side `result_abi`,
  and `slot_metadata` paths were deleted; constants, match parameters, direct
  intrinsics, and intrinsic wrappers consume canonical physical keys selected
  during planning. ByteSequence runtime-layout demand is likewise recorded by
  intrinsic planning instead of mutating the layout table while emitting an
  instruction.
- 2026-08-25: Physical ANF now owns the concrete layout and constant identities
  used by literals, data constructors, alternatives, capture environments,
  runtime evidence, and callable adapters. Adapter support is a verified closed
  set containing its static layouts, layout constructors, and nested adapters;
  VM CFG emission can no longer intern or discover any of those identities.
- 2026-08-25: Global runtime producers, including intrinsic wrapper plans and
  invocations, are now frozen and verified in Physical ANF. `FunctionLowerer`
  no longer holds `ImageLowerer`; function, initializer, intrinsic, adapter,
  and layout-constructor body emission are standalone consumers of the frozen
  program rather than methods with access to mutable planning state.
- 2026-08-25: Physical values and flows no longer retain a parallel semantic
  `RuntimeType`. Locals, globals, call arguments and results, function
  parameters, match payloads, data constructions, and callable bridges carry
  only their canonical physical contract plus an explicit bridge when needed.
  VM CFG emission therefore cannot recover representation decisions from an
  unnormalized source type; the former semantic fields and the always-true
  runtime-evidence classifier were deleted.
- 2026-08-25: Frozen nominal constructor contracts no longer copy semantic
  storage types from the data-family planner. Payload arity and VM CFG field
  projection are now certified entirely by the physical storage-shape vector;
  semantic storage types remain solely in representation planning.
- 2026-08-25: Verified Physical ANF now freezes the complete ordered function
  emission catalog together with globals, layouts, object shapes, constants,
  and the materialized data-family count. The top-level VM CFG emitter is a
  standalone consumer of that value; it no longer traverses `FunctionPlanTable`
  or reads any mutable `ImageLowerer` image state. The verifier rejects an
  emission order that disagrees with allocated function identities.
