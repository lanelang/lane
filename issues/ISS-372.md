## Description
Explore still publishes empty scale arrays for Syntax, Resolved, Checked,
Buslane Module, and Buslane Linked stages. For the Coroutine Scheduler, the
rendered Buslane Module grows from 144 lines and 4,992 bytes to a 499-line,
14,485-byte linked program, but no typed metric explains how many declarations,
functions, nodes, calls, imports, or module contributions produced that growth.

This leaves ISS-357's stated fixed-metric-set contract incomplete and prevents
Explore from attributing link-time growth or specialization cleanup without
ad-hoc text parsing. These tree IRs do not own stable per-function identities,
but they can and should expose deterministic aggregate facts.

## Design
Each frontend, module-compilation, and linking boundary produces its own typed
aggregate observation before the driver discards the typed IR. The Explore
driver and HTML/JSON presentation only transport and render those facts.

Define a fixed metric set appropriate to each stage family. Syntax, Resolved,
and Checked should cover declarations and expression/type structure; Buslane
Module and Linked should cover top terms, functions, nodes, calls, imports,
externals, constructors, operations, and per-module contribution where the link
owner has that information. Emit meaningful zero values in stable order.

Do not parse pretty text, invent traversal-order function IDs, recover module
ownership from names, or make the presentation layer traverse compiler IR.

## Acceptance Criteria
- [ ] Syntax, Resolved, Checked, Buslane Module, and Buslane Linked snapshots
      publish deterministic nonempty fixed metric sets.
- [ ] Metrics are produced from typed stage values by the stage owner and never
      parsed from rendered text.
- [ ] Identity-less tree IRs publish aggregate metrics without fabricated
      per-function identities.
- [ ] Link metrics attribute retained declarations and structural growth to
      their input module or linker-generated origin using linker-owned facts.
- [ ] One black-box Explore report explains the Module-to-Linked growth and the
      subsequent specialization reduction with structured metrics.
- [ ] Repeated exploration produces identical metric names, order, and values.
- [ ] ISS-357 and ISS-361 documentation is updated so their delivered scope and
      this follow-up are consistent.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
