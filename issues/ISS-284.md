## Description
`@buslane.verify_program` is never called on a real compilation. The only
caller is `assert_cps_ordinary_output` in the selective-CPS whitebox tests,
whose inputs are hand-built programs. Every stage after linking is therefore
unchecked, which is why ISS-283 could ship a representation that lied about
effects for as long as it did.

Running the verifier after `monadic-lift` over `examples/valid` measures the
gap. Counting distinct programs and diagnostics:

| stage | failing runs | UnknownTypeParameter | TypeMismatch | other |
| --- | ---: | ---: | ---: | ---: |
| effect-lowering input | 27 | 401 | 4 | 6 |
| after monadic-lift | 30 | 420 | 10 | 6 |

Three separate defects account for all of it, tracked as ISS-285, ISS-286, and
this issue. With ISS-285 applied the picture is:

| stage | failing runs | UnknownTypeParameter | TypeMismatch |
| --- | ---: | ---: | ---: |
| effect-lowering input | 1 | 0 | 4 |
| after monadic-lift | 7 | 19 | 12 |

The remaining input failure is ISS-286. The rest appear only after effect
lowering, and every one has the same shape:

```
expected = Function([Unit], Unit, Io)
actual   = Function([Unit], Unit, Empty)
```

A continuation whose row is *narrower* than the parameter it is passed to.

## Design
Buslane requires function types to match with definitionally equal effect rows:
`check_expr` uses `types_definitionally_equal`, and `alpha_equal_effect_with`
compares term sets exactly. That is deliberate — `CONTEXT.md` states effect
polymorphism uses row unification, "not effect subtyping", and **Function Effect
Widening** exists as an explicit source-level adapter.

Dictionary-passing CPS cannot satisfy it. A CPS'd callable takes a continuation
and a dictionary, both supplied by the caller, and its own row is the union of
what it performs with what they perform. Whatever row the continuation parameter
is declared at, some caller supplies a term with a different one:

- Declare it at `R_own ∪ residual`: an install site whose final branch is pure
  supplies a continuation with row `Empty`. This is the measured failure.
- Declare it at `residual` alone: inside the callee, invoking an operation
  passes the rest of the body as the operation's continuation, and that body
  performs `R_own`, so the argument's row is `R_own ∪ residual` against a
  parameter at `residual`.

No term can bridge the gap. A pure continuation cannot be given a row of `Io`,
because a Buslane `Function` expression's row is synthesized from its body and
there is no ascription form.

So accept subeffects where a value is consumed. `check_expr` checks an actual
type against an expected one, which is exactly a subtyping question:

- `Function`: parameters contravariant, result covariant, latent effect
  covariant — an actual row that is a subeffect of the expected row is fine,
  since the consumer only assumes the expected row.
- `Apply`: arguments stay invariant. A dictionary type mentions its residual in
  both a parameter row and its own row, so it is genuinely invariant in it.
- Everything else: unchanged, structural.

`types_definitionally_equal` stays as it is and keeps its existing callers;
this adds a separate relation rather than loosening equality.

Then call `verify_program` in `lower_effects` so the gap cannot reopen.

## Acceptance Criteria
- [x] Buslane exposes a subtyping relation with contravariant parameters,
      covariant results, covariant latent effects, and invariant type arguments.
- [x] `check_expr` uses it; `types_definitionally_equal` is unchanged.
- [x] Buslane tests cover accepting a narrower row at an argument, rejecting a
      wider one, and rejecting both directions under a contravariant parameter.
- [x] `lower_effects` verifies its input, and a failure is a compiler error
      rather than silence.
- [ ] `lower_effects` verifies its output the same way, and names the stage that
      produced a rejected program: effect specialization, monadic-lift, core
      optimization, and residual-effect erasure each end in plain Buslane.
- [x] Every `examples/valid` program verifies on the input.
- [ ] Every `examples/valid` program verifies after monadic-lift.
- [x] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.

  `examples/valid/37_coroutine_scheduler.lane` accounts for the 19
  `UnknownTypeParameter` and 2 of the mismatches. They are declarations that
  effect specialization left dead: it drops a specialized definition's terms but
  keeps its metadata, and selective CPS then rewrites the types under those
  declarations to mention companions while their binders stay as they were.
  Mapping the binders too was tried and is wrong on its own — the applied forms
  of those same dead types then fail kind checking, and mapping a data
  constructor's hidden parameters contradicts the erasure of effect-kind
  existentials that the LoisVM lowering test pins. The fix belongs with
  specialization not leaving inconsistent metadata behind, not with CPS
  rewriting it more.

  `examples/valid/45_async_effect.lane` accounts for the other 2. A CPS'd
  callable's committed type binds one answer-and-residual pair while its
  `%context` and `%continuation` parameter values are typed at another, so the
  second pair is free. The two pairs are allocated in order — binders at uniques
  404-407, the pair inside the dictionary at 414-415 — so the binders and the
  parameter values come from different `rewrite_type` generations of the same
  source type. `lower_cps_function` takes its binders from `expected_cps_type`
  and then defines the parameter values from those same binders, so the two
  cannot diverge on that path; the divergence is reached some other way, and the
  call site was not identified. This is the last thing between here and the
  output gate.
