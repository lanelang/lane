## Description
Explore repeats its stage catalog in `ExploreStageId`, an eighteen-field
`ExploreStages` record, `ordered`, `index`, `explore_stage_ids`, fixed builder
storage, and positional `finish` reconstruction. Adding or removing a stage
requires coordinated edits that independently reproduce order, key, title,
domain, text format, and storage position.

The driver also traverses Buslane, the open effect-lowering AST, Runtime ANF,
VM CFG, and Bytecode to define structural scale facts. Wasm already produces
its scale in the backend owner. The driver therefore depends on every IR
constructor and becomes another traversal owner whenever an IR changes.

Explore additionally publishes empty scale arrays for Syntax, Resolved,
Checked, Buslane Module, and Buslane Linked stages. For the Coroutine Scheduler,
the rendered Buslane Module grows from 144 lines and 4,992 bytes to a 499-line,
14,485-byte linked program, but no typed metric explains that growth.

This leaves ISS-357's stated fixed-metric-set contract incomplete and prevents
Explore from attributing link-time growth or specialization cleanup without
ad-hoc text parsing. These tree IRs do not own stable per-function identities,
but they can and should expose deterministic aggregate facts.

## Design
Define one ordered Explore Stage Catalog whose descriptors own identity, key,
title, domain, text format, and protocol order. Store report stages as one
ordered collection rather than a parallel record with one field per stage.

Each IR-owning Module produces its typed structural scale and function identity
facts. The Explore driver adapts those facts to protocol metric identifiers and
does not traverse foreign IRs. Frontend, module-compilation, and linking
boundaries produce aggregate observations before discarding typed values;
Wasm continues to report emitter-owned scale through the new function catalog.

Define a fixed metric set appropriate to each stage family. Syntax, Resolved,
and Checked should cover declarations and expression/type structure; Buslane
Module and Linked should cover top terms, functions, nodes, calls, imports,
externals, constructors, operations, and per-module contribution where the link
owner has that information. Emit meaningful zero values in stable order.

Do not parse pretty text, invent traversal-order function IDs, recover module
ownership from names, expose private effect-lowering time-state ASTs, or make
the presentation layer traverse compiler IR.

## Acceptance Criteria
- [ ] One Stage Catalog is the sole producer of stage identity, order, key,
      title, domain, and text format.
- [ ] `ExploreStages` no longer duplicates the catalog as one field per stage;
      builder and protocol output consume the ordered catalog.
- [ ] Syntax, Resolved, Checked, Buslane Module, and Buslane Linked snapshots
      publish deterministic nonempty fixed metric sets.
- [ ] Buslane, effect-aware CPS Core, Runtime ANF, VM CFG, Bytecode, and Wasm
      metrics are produced by their owning Modules; driver metric adapters do
      not traverse those IRs.
- [ ] Identity-less tree IRs publish aggregate metrics without fabricated
      per-function identities.
- [ ] Link metrics attribute retained declarations and structural growth to
      their input module or linker-generated origin using linker-owned facts.
- [ ] One black-box Explore report explains the Module-to-Linked growth and the
      subsequent specialization reduction with structured metrics.
- [ ] Repeated exploration produces identical metric names, order, and values.
- [ ] Effect-lowering observations remain available without exposing the
      private transitional AST as an Explore dependency.
- [ ] ISS-357 and ISS-361 documentation is updated so their delivered scope and
      this follow-up are consistent.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
