## Description
Demand-driven runtime-representation specialization sees only direct generic
calls. CPS callables commonly flow through continuations, effect dictionaries,
constructor fields, function parameters, and function results, so their
concrete answer ABI is lost before specialization planning. LoisVM lowering
then emits callable adapters and erased-value bridges that the later VM CFG
callable-flow analysis cannot soundly remove because source type applications
and higher-kinded companion relationships are no longer present.

The real Coroutine Scheduler fixture currently produces 19 physical callable
adapter workers, 29 erase/unerase instructions, and 52 indirect calls in its
initial VM CFG after exact adapter canonicalization.

## Design
Replace the direct-call seed scan with one typed ANF callable-instance plan.
The plan propagates callable identity and generic applications through values,
aggregates, parameters, results, recursion, and immutable globals. It is the
sole producer of runtime-representation worker demand.

Before demand planning, ANF owns a complete callable catalog. Every top-level
and nested function has a stable `AnfFunctionId`, lexical type binders,
captures, allocation site, and recursive-group identity before VM CFG emission
begins. Body emission only consumes the frozen catalog and instance plan; it
does not append functions or allocate identities while lowering expressions.

Call demand is keyed by caller instance plus ANF binding site. Aggregate flow
uses a finite graph of allocation sites and field edges rather than recursively
nesting aggregate facts. This gives aliases and recursive data finite identity
without widening, depth limits, or first-seen policies.

Representation workers may specialize concrete first-order `Type` binders
while retaining symbolic higher-kinded companion binders and their explicit
layout-constructor witnesses. Keys use canonical runtime ABI, generic
implementations remain available for open uses, and recursive demand is
accepted only when every SCC transformation is a projection or permutation of
caller binders, or selects from a finite set of closed constants. If that proof
fails, the whole SCC remains generic. VM CFG callable-flow remains
the sole owner of final physical target and environment facts and must
propagate call inputs and results interprocedurally.

Do not recognize CPS from generated names, reconstruct effects from layouts,
introduce size or frequency heuristics, add a packed-callable fallback opcode,
or infer specialization demand while emitting function bodies.

## Acceptance Criteria
- [x] A minimal concrete-answer CPS callback lowers without callable adapters or erase/unerase bridges on its closed path.
- [x] Callable-instance flow crosses aliases, parameters/results, constructor fields, and recursive continuation paths.
- [x] Concrete first-order answer binders can specialize while forwarded higher-kinded companions retain explicit witnesses.
- [x] One canonical runtime-ABI key produces at most one worker; open and incompatible multi-ABI uses retain the generic implementation.
- [x] Recursive CPS demand is specialized only when its instance set is proven finite.
- [x] VM CFG callable-flow propagates environment, witness, argument, and result facts without reconstructing specialization policy.
- [x] Explore records the post-change Coroutine Scheduler adapter, bridge, indirect-call, function, and instruction counts.
- [x] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and `moon test --target native` pass.

- 2026-08-12: Independent CPS ABI audits rejected the premise that post-CPS
  residual `Empty` is weaker than purity. Before runtime projection, the
  transformed row remains the authoritative observational-effect fact.
  Ordinary effect-aware Core optimization is therefore valid after monadic
  lift; the old effect-erasure pass is being removed under ISS-364.

- 2026-08-12: A consumer-only experiment that specialized deep callable ABI differences was rejected by the Explore gate: it removed one erase and one indirect call but added three closures/environments, two layouts, and about one hundred Wasm instructions. Producer and consumer instances must be planned as one typed ANF demand closure; the remaining criteria stay open.
- 2026-08-12: A first callable-flow prototype was deleted after review. It used
  top-level values instead of `AnfFunctionId`, recursively nested aggregate
  facts, discovered nested functions during emission, and bounded recursion by
  first-seen demand. Those mechanisms could not establish the finite,
  immutable plan required by this issue.
- 2026-08-17: Runtime ANF now owns a complete callable catalog. The immutable
  instance plan propagates callables and finite allocation identities through
  aliases, parameters, results, aggregate fields, matches, and recursion before
  any VM CFG body is emitted.
- 2026-08-17: A closed higher-kinded CPS regression fell from 11 functions and
  44 instructions with three callable adapters and two erase plus two unerase
  operations to eight functions and 16 instructions with no adapter or bridge
  on the closed path. A direct recursive Bool/I32 demand produces one canonical
  worker; an expanding `Box[T]` recursion produces none and retains its generic
  SCC.
- 2026-08-17: Data storage specialization is allocation-proven rather than
  nominally guessed. The existential callable-container conformance regression
  keeps its uniform generic family, while a closed one-allocation handler
  dictionary uses its concrete field ABI.
- 2026-08-17: Final Coroutine Scheduler initial VM CFG records 63 functions,
  425 instructions, 50 indirect calls, 19 callable adapters, 17 erase and 11
  unerase operations. JIT and interpreter both print `1112211322`.

## Close Notes

Implemented the Runtime ANF callable catalog and one immutable typed
callable-instance fixed point as the sole producer of runtime representation
demand. Function workers use canonical first-order and alpha-normalized
higher-kinded evidence keys, retain symbolic witnesses, and accept recursive
demand only after a finite SCC proof. The same allocation graph safely removes
closed handler dictionary adapter round trips without changing existential data
ABI. Generic fallbacks remain available for every open or incompatible path.
