## Description
The WebAssembly-only migration removed the legacy semantic runtime and made raw
Wasm the sole executable contract. The previous optimization measurements now
describe a different backend architecture and cannot justify the next rewrite.

Establish a reproducible post-migration baseline, then remove residual aggregate
allocation at the earliest owner that can prove the rewrite. Core analysis must
own static value facts; downstream simplification may consume them, while
Runtime ANF and Physical Lowering must not rediscover source-level constructor
identity.

## Design
Complete the work in dependency order:

1. certify the Wasm-only release boundary against pinned Basic and Wasmoon;
2. record current Explore structure and separated compile/JIT/execution timing;
3. make `CoreAnalysis` own conservative closed pure-value summaries;
4. scalar-replace only aggregates whose complete use and ownership facts prove
   that no object identity or escape remains; and
5. remeasure the same programs and derive any later optimization from the new
   evidence.

Do not introduce numeric optimization heuristics, a second escape analysis, a
Wasm peephole for source aggregates, or a fallback representation. Preserving
behavior and one-owner invariants is more important than any particular metric.

## Acceptance Criteria
- [ ] ISS-408 through ISS-412 are closed with independent commits and evidence.
- [ ] The post-migration release and Explore baselines are reproducible.
- [ ] Static constructor knowledge has one producer and no downstream syntax
      guessing.
- [ ] Proven non-escaping aggregate traffic is removed before Wasm emission.
- [ ] Final measurements distinguish semantic-IR changes from backend/runtime
      changes and record any remaining work as separate issues.
