# ISS-377: Make executable initialization facts canonical

## Description
Executable Program retains the complete CPS Core program, copies every eager
initializer body or recursive group into a second array, and constructs a third
execution-root array containing initializer indices plus the already stored
entry. LoisVM lowering ignores the copied initializer expressions, rescans
Runtime ANF terms, and reconstructs the actual initializer schedule.

## Design
Let `program.terms` remain the sole owner of initializer bodies and source
execution order. Executable elaboration records only the initializer ValueIds
that must act as retention roots; the selected entry remains its existing typed
field. LoisVM planning scans Runtime ANF terms exactly once and emits steps in
that canonical term order.

Remove `TopLevelInitializer`, `ExecutionRoot`, initializer indices, copied AST
bodies, and reverse index-to-ValueId lookup. Module-path display information is
not execution semantics and should live in an observation/report if it still
has a consumer.

## Acceptance Criteria
- [x] Executable Program contains one CPS Core program, one entry, externals,
      and initializer retention roots without copied initializer expressions.
- [x] Initializer order comes only from program term order and recursive groups
      remain atomic.
- [x] LoisVM planning consumes the recorded roots and scans ANF terms once; it
      does not reconstruct or compare a second schedule.
- [x] Entry is not duplicated inside an execution-root variant.
- [x] Pretty and Explore output derive initializer descriptions from the
      canonical program and roots.
- [x] Black-box tests cover no initializer, multiple dependent initializers,
      recursive groups, dead initializers, and initializer-before-entry runtime
      behavior.
- [x] Old initializer/root models and their structural tests are deleted.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
