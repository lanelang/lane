## Description
Demand-driven runtime-representation specialization sees only direct generic
calls. CPS callables commonly flow through continuations, effect dictionaries,
constructor fields, function parameters, and function results, so their
concrete answer ABI is lost before specialization planning. LoisVM lowering
then emits callable adapters and erased-value bridges that the later VM CFG
callable-flow analysis cannot soundly remove because source type applications
and higher-kinded companion relationships are no longer present.

The real Coroutine Scheduler fixture establishes the whole-program size gate;
focused concrete-answer fixtures establish whether a closed CPS path retains
representation-only workers and bridges.

## Design
Replace the direct-call seed scan with one typed ANF callable-instance plan.
The plan propagates callable identity and generic applications through values,
aggregates, parameters, results, recursion, and immutable globals. It is the
sole producer of runtime-representation worker demand.

Before demand planning, ANF owns a complete callable catalog. Every top-level
and nested function has a stable `AnfFunctionId`, lexical type binders,
captures, allocation site, and recursive-group identity before VM CFG emission
begins. Body emission only consumes the frozen catalog and instance plan; it
does not append functions or allocate identities while lowering expressions.

Call demand is keyed by caller instance plus ANF binding site. Aggregate flow
uses a finite graph of allocation sites and field edges rather than recursively
nesting aggregate facts. This gives aliases and recursive data finite identity
without widening, depth limits, or first-seen policies.

Allocation identities propagate callable-flow facts only. They do not select a
nominal data-storage ABI: constructors and matches continue to consume the one
declaration-owned family. Any future generic data representation specialization
requires the explicit family identity tracked by ISS-384.

For a closed, non-escaping aggregate such as a generated handler dictionary,
the optimization path is scalar replacement. A separate immutable use proof,
owned by callable-instance planning, proves a single allocation-to-match path
through aliases and exact representation workers. The representation plan owns
the corresponding logical-to-physical parameter projection. If either proof
fails, the allocation keeps the ordinary uniform nominal representation. It
never changes storage under an existing family identity and lowering never
reboxes a failed plan.

Representation workers may specialize concrete first-order `Type` binders
while retaining symbolic higher-kinded companion binders and their explicit
layout-constructor witnesses. Keys use canonical runtime ABI, generic
implementations remain available for open uses, and recursive demand is
accepted only when every SCC transformation is a projection or permutation of
caller binders, or selects from a finite set of closed constants. If that proof
fails, the whole SCC remains generic. VM CFG callable-flow remains
the sole owner of final physical target and environment facts and must
propagate call inputs and results interprocedurally.

Do not recognize CPS from generated names, reconstruct effects from layouts,
introduce size or frequency heuristics, add a packed-callable fallback opcode,
or infer specialization demand while emitting function bodies.

## Acceptance Criteria
- [x] A minimal concrete-answer CPS callback lowers without callable adapters or erase/unerase bridges on its closed path, without changing a nominal data family's declaration-owned ABI.
- [x] Callable-instance flow crosses aliases, parameters/results, constructor fields, and recursive continuation paths.
- [x] Concrete first-order answer binders can specialize while forwarded higher-kinded companions retain explicit witnesses.
- [x] One canonical runtime-ABI key produces at most one worker; open and incompatible multi-ABI uses retain the generic implementation.
- [x] Recursive CPS demand is specialized only when its instance set is proven finite.
- [x] VM CFG callable-flow propagates environment, witness, argument, and result facts without reconstructing specialization policy.
- [x] Explore records the final post-change Coroutine Scheduler adapter, bridge, indirect-call, function, and instruction counts.
- [x] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and `moon test --target native` pass.

## Close Notes
Closed aggregate scalar replacement is now a planned physical representation
variant rather than a nominal data-family specialization. The immutable
callable-instance plan proves the complete allocation-to-match carrier path;
the immutable representation plan materializes one flattened worker ABI; VM
CFG lowering only consumes both plans. Unproved components keep the uniform
nominal ABI without an emission-time fallback or a second family identity.

Verified with `moon info`, `moon fmt`,
`moon check --target native --warn-list +73`, `moon test --target native`, the
complete examples gate, focused Explore snapshots, and Coroutine Scheduler runs
under both JIT and `--no-jit`.
