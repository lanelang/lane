## Description
Replace definition-global runtime-polymorphic retention with a demand-driven
worklist rooted at the executable entry and initializer roots. The same source
definition must be able to receive both `RetainGeneric` and `Specialize`
demands.

## Design
Build an immutable `SpecializationPlan` from canonical demand keys. Planning
reads source metadata and expressions but allocates no target identities and
rewrites no expressions. Deduplication of demand keys provides the fixed point
for recursion.

## Acceptance Criteria
- [x] The planner records generic and concrete callable demands independently.
- [x] Mixed generic/concrete uses retain the original and request concrete clones.
- [x] Dead definitions do not contribute demands.
- [x] Plan ordering is deterministic.
- [x] Planner white-box tests inspect the complete small plan.

Added a read-only worklist planner rooted at the selected entry. It records
