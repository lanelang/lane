## Description
Linker identity remapping stores six arrays of mapping entries and implements
six pairs of copy-pasted linear `find` and `bind` operations. Module lookup,
duplicate detection, and traversal membership also repeatedly scan arrays.
Linking therefore performs avoidable quadratic work as module and symbol counts
grow.

## Design
Use a hashable key containing canonical module path and source identity index.
Keep distinct typed maps for type, type-parameter, value, constructor, effect,
and operation targets so namespace safety remains explicit. Index modules by
path and exports by reference kind/name, and use sets for traversal membership
where order is not semantic.

Preserve existing deterministic module order and target identity allocation;
maps are lookup structures, not output-order authorities.

## Acceptance Criteria

- [x] Six identity namespaces remain statically separated.
- [x] Binding an already mapped identity preserves the existing target behavior.

- [x] Duplicate modules and import cycles retain structured diagnostics.
- [x] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
