## Description
Replace on-demand instance creation during expression rewriting with two
explicit execution steps: deterministic target allocation followed by a
mechanical rewrite that consumes an immutable plan and allocation table.

## Design
Allocation owns every new value, type, and constructor declaration and commits
each target metadata type once. Rewriting may apply substitutions and validate
definition-equivalent or consumable bodies, but cannot overwrite declaration
metadata or extend the plan.

## Acceptance Criteria
- [x] Planning performs no metadata writes.
- [x] Allocation commits every planned target declaration exactly once.
- [x] Rewriting creates no new specialization instances or target identities.
- [x] Mixed demand emits the generic source plus exactly the planned clones.
- [x] The specialized output verifies before effect lowering.

## Close Notes

Switched production specialization to the immutable plan. Allocation now
creates all planned data type identities before constructor payload rewriting,
then creates every callable instance before expression rewriting. Callable and
data lookups report a missing-plan error instead of allocating on demand.
Local rewrites resolve preallocated instances by lexical site, ambient
bindings, and concrete instance bindings. The old runtime-polymorphic
forwarding scan was deleted.
