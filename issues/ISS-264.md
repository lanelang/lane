## Description
The public object-artifact link path validates schema versions and fingerprints
but does not validate complete Buslane referential integrity or every side-table
reference. A caller can construct an artifact with an internally consistent
fingerprint and unknown Buslane identities, after which the linker remapper
aborts. Object-only linking also ignores an imported reference whose provider
has no export with the requested name.

Persisted or public input must produce structured diagnostics rather than
reaching internal aborts.

## Design
Introduce an opaque validated link-object state that can only be constructed
after schema, fingerprint, Buslane metadata/term, external, entry, export,
import, and interface-fingerprint checks succeed. The remapper should accept
only that validated state. Reuse Buslane verification where its contract fits
and add module-object checks for side tables and cross-module references.

Do not fix this by catching aborts at the public entrypoint. Keep invariant
aborts only behind a validator that proves the invariant.

## Acceptance Criteria
- [x] Every public artifact-link entrypoint returns diagnostics for malformed object contents and never aborts on caller-provided artifacts.
- [x] Unknown type, type-parameter, value, constructor, effect, and operation identities are rejected before remapping.
- [x] Entries, externals, exports, imports, and imported-interface fingerprints are checked against the object metadata and provider objects.
- [x] A missing provider export for an imported reference produces a structured diagnostic instead of being ignored.
- [x] Tests construct correctly re-fingerprinted malformed artifacts and cover every identity namespace and side-table family.
- [x] Existing valid artifact roundtrips and object-only linking remain deterministic.
- [x] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.

## Close Notes

- Closed on 2026-07-31 after inserting the private `ValidatedLinkModuleObject` boundary between validation and identity remapping.
- Validation now uses a module-object identity walker over metadata, terms, type/effect arguments, and side-table types, checks external/entry/export/import references against metadata, and validates imported fingerprints and provider exports before remapping. It deliberately does not apply complete-program scope or kind rules to pre-link module fragments.
- Missing provider exports now produce E4205 instead of being ignored; malformed local object contents produce E4208 with the exact failed invariant.
- `artifact_link_validation_wbtest.mbt` re-fingerprints malformed objects and covers all six identity namespaces, side-table references, and object-only missing-export linking.
- Focused native validation passed: `modules/lanec/compile` 168/168, `moon check --target native --warn-list +73`, formatting, `git diff --check`, and the complete runnable-example smoke. Repository-wide gates are re-run as the final validation for this issue batch.
