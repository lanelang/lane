## Description
The Linux native suite previously aborted while the Wasm backend propagated an
intentional runtime-import failure from an entry function. The failing public
backend regression is `Wasm entry failures clean initialized global roots`:

```text
*** longjmp causes uninitialized stack frame ***: terminated
RUNTIME ERROR: abort() called
.../wasmoon_jit/native_context_execution.mbt:226 at NativeJITContext::call_trampoline
.../wasmoon/jit/ffi_jit.mbt:346 by JITContext::call_multi_return
.../wasmoon/jit/jit_runtime.mbt:521 by JITModule::call_with_context
```

The failure reproduces on native Linux/aarch64 and Linux/x86_64 under QEMU,
while the same suite passes on macOS. It prevents the Ubuntu native gate from
validating unrelated cross-platform changes. The intended result is the typed
`RuntimeImportFailure` followed by initialized-global cleanup; the host process
must not abort while transporting that failure.

## Design
The minimized upstream reproduction established two distinct Wasmoon-owned
control-transfer invariants. Top-level traps must return through a guarded
native fiber only after restoring the host stack. Within generated Wasm control
flow, every non-local edge leaving a `try_table` must first unlink exactly the
handlers whose lexical scopes it exits. A plain `return` previously violated
the second invariant and left a stale `sigjmp_buf`; a later throw selected that
dead handler and glibc rejected the resulting `longjmp`.

Wasmoon now records lexical handler depth on structured targets and emits exact
handler cleanup for returns, tail calls, branches, catch targets, and supported
`br_on_*` edges. Lane consumes the published fix through the coordinated
Wasmoon `0.12.5` dependency family; it does not catch SIGABRT, skip Linux,
disable JIT, or introduce an interpreter fallback.

The Lane execution runtime exposes one typed execution outcome. Cleanup of
initialized globals must run after a failed entry without changing the original
failure classification, leaking roots, or invoking a second execution path.

## Acceptance Criteria
- [x] A minimized Linux reproduction identifies the invalid control-transfer boundary.
- [x] Wasm/JIT returns the original typed `RuntimeImportFailure` on Linux instead of aborting the host process.
- [x] Initialized global roots are released after the failed entry.
- [x] Interpreter and Wasm/JIT preserve the same failure classification and cleanup result.
- [x] No Linux skip, signal catch, interpreter fallback, or test-only runtime path is introduced.
- [x] The regression passes on native Linux/aarch64, Linux/x86_64, and macOS.
- [x] `moon info` and `moon fmt` pass; `moon test --target native` and the release examples gate pass.

## Notes
- 2026-08-10: Reproduced with MoonBit nightly `d9c7c01` and the repository's
  pinned dependencies on native Linux/aarch64. The same test aborts under
  Linux/x86_64 QEMU; the complete macOS native suite passes.
- 2026-08-27: Wasmoon issue #507 minimized the remaining defect to a plain
  `return` leaving a `try_table` without unlinking its handler. Upstream commit
  `c985aef5` generalized handler-depth cleanup across non-local control-flow
  edges. This is distinct from PR #505, which repaired top-level trap transport
  through native fibers; the published `0.12.5` sources contain both changes.

## Close Notes

Updated every direct Wasmoon-family dependency owner to the coordinated
`0.12.5` release: `milkir`, `wasm_core`, `wasmoon`, and `wasmoon_jit`. The
resolved backend family is uniformly `0.12.5`; no unrelated dependency moved.

The public regression `Wasm entry failures clean initialized global roots`
returns the typed `RuntimeImportFailure` and observes the initialized root
count returning to zero. The previously recorded Linux/amd64, Linux/aarch64,
and macOS runs cover the exact published repair; the current WebAssembly-only
branch revalidated the regression on macOS after migrating it to
`modules/lanec/wasm_target`.

Current-branch validation: targeted regression 1/1; `moon check --target native
--warn-list +73`; `moon test --target native` 1721/1721; release `lane.exe`
build; and the complete pinned-Basic examples gate. No signal handling,
platform skip, alternate execution path, or runtime fallback was introduced.
