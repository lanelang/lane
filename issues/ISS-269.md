## Description
The public compiler facade exposes result records built from optional values
plus diagnostics and leaks source, module-compilation, link, and lowering types
from internal packages. Those records admit invalid combinations and the facade
does not provide enough leverage for tools to avoid importing pipeline
packages directly.

## Design
Define a closed compilation outcome that distinguishes successful values plus
warnings from failures plus errors. Give the facade ownership of its public
source-set and request types. Consolidate redundant text/input wrappers around
one canonical implementation while retaining only convenience entrypoints that
materially improve ordinary use.

Migrate CLI, LSP, Wasm, and library consumers to stable `compile`, `artifact`,
and `driver` boundaries. Do not preserve old internal-type signatures through
compatibility wrappers solely to avoid caller migration.

## Acceptance Criteria
- [x] Public check, compile, module-compile, and link results cannot represent success/failure combinations forbidden by the compiler contract.
- [x] The facade owns the public request/input types required by ordinary compiler consumers.
- [x] Public signatures do not expose incidental `module/frontend`, `module/compile`, or `module/link` types without an explicit boundary reason.
- [x] Redundant wrapper entrypoints are removed or justified by distinct user workflows.
- [x] Lane CLI, LSP, and Wasm callers use stable facade, artifact, or driver APIs where applicable.
- [x] Black-box tests cover public success-with-warnings, parse/resolve/type failures, module compilation, and linking outcomes.
- [x] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
