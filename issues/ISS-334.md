# ISS-334: Centralize numeric suffix syntax and complete literal patterns

## Description
Numeric suffix recognition and canonical spelling are reproduced across the
lexer, parser, and three pretty-printers. The pattern grammar also accepts
negative integer literals but not negative floating literals, contrary to
ADR-0127's uniform expression/pattern rule.

## Design
Make `NumericLiteralSuffix` the sole owner of canonical suffix spelling and
make the lexer produce structured numeric token data through one suffix parser.
All syntax printers consume that owner instead of repeating switches. Extend
floating literal pattern construction to carry immediate negation using the
same authored body and suffix semantics as expressions.

## Acceptance Criteria
- [x] Numeric suffix recognition has one implementation and canonical spelling has one owner.
- [x] Syntax, resolve, and desugar printers consume the shared canonical spelling operation.
- [x] Negative F32 and F64 literal patterns parse, typecheck, and format according to ADR-0127.
- [x] Parser/formatter black-box round trips cover all suffixes and negative expression/pattern positions.
- [x] Invalid suffix forms retain stable diagnostics.

## Close Notes
The lexer now separates each numeric body from an arbitrary attached
identifier-like tail without naming any accepted suffix. The syntax package's
`NumericLiteralSuffix::parse` is the sole owner of empty, valid, unknown, and
integer-on-floating tail classification, while
`NumericLiteralSuffix::canonical_text` owns canonical spelling. Parser
construction and all three syntax printers consume the resulting shared model.
Negative F32 and F64 patterns use the same literal representation as
expressions.

Black-box suffix-owner, parser, formatter, and compiler tests cover fixed
suffixes, complete attached tails such as `42i32foo`, negative floating
patterns, and the existing invalid/noncanonical suffix diagnostics. Verified by
`moon test --target native` on 2026-08-05: 1564/1564 tests passed.
