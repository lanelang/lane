## Description
Storing a callable as a generic value currently canonicalizes its internal
calling convention, rather than merely storing its handle. `erase_value` calls
`canonical_callable_type` and `make_callable_adapter` before `EraseI64`;
`unerase_value` performs the reverse adaptation. In `type_adaptation.mbt`,
`canonical_callable_value_type` turns concrete non-Unit callable parameters and
results into erased values, except for already-bound erased parameters.

In the ISS-434 Basic baseline, Core through Runtime ANF stores the original 18
test callables in a List. Physical emission inserts wrappers. Reading the List
and executing a test produces this actual path (IDs are baseline observations,
not stable contracts):

```text
execute_tests -> adapter f240 -> adapter f317 -> original test

f240: erase_i32(context); erase_i64(continuation); call canonical callable
f317: unerase_i32(context); unerase_i64(continuation); call original callable
```

The List legitimately selects among different source functions. The two
opposite ABI adaptations are introduced by representation, not source-level
dispatch. The entry alone materializes 18 environments and 18 closures; their
construction and erasure expand to 378 of its 833 Wasm instructions. Shared
adapter function bodies do not eliminate these allocations or call layers.

Canonicalization is not itself an architectural defect. A shared generic
consumer of `List[() -> A]` must invoke functions under a known calling
convention even when A is unknown. The same list can also reach a concrete
consumer of `List[() -> I32]`. A layout witness describes representation and
cleanup; it does not by itself implement arbitrary Wasm call signatures.
Opposite adapters in the baseline establish a cost to investigate, not a proof
that canonicalization can be deleted for all storage or all consumers.

### Reference implementation

Koka at `429f578512ba7229ec86a2389d4d2481100d17bc` uses the same general strategy:
[`Backend.C.Box.bcoerceX`](https://github.com/koka-lang/koka/blob/429f578512ba7229ec86a2389d4d2481100d17bc/src/Backend/C/Box.hs)
adapts functions to boxed argument/result conventions before boxing and adapts
back after unboxing. Its `boxDef` simplifies the resulting Core expressions;
the C pipeline performs boxing before reference-count insertion.
[`box3.kk`](https://github.com/koka-lang/koka/blob/429f578512ba7229ec86a2389d4d2481100d17bc/test/cgen/box3.kk)
and `box3a.kk` exercise the same list through generic and concrete consumers,
including nested higher-order argument representations. This is source-level
evidence for why adaptations are needed, not measured evidence that Koka
eliminates Lane's observed round trips.

## Design
Retain the correct canonical generic calling convention. Make necessary
adaptations composable and eliminate proven redundancy without replacing the
generic runtime or globally removing callable canonicalization. Preserve the
actual pipeline:

```text
Runtime ANF -> specialization plan -> VM CFG emission (including closures)
  -> callable-flow / adapter elimination / cleanup -> ARC -> slots -> Wasm
```

1. Lock the correctness baseline with a shared container consumed by both
   generic and concrete callers, then reproduce the Basic round trip.
2. Keep complete callable contracts as the owner of adapter generation, not a
   proof that two callable values have identical runtime representations.
   Behaviorally equivalent closures can have different code/environment pairs.
   Compose actual adapter bodies: preserve parameter/result conversions,
   witness operands, and returned closure construction. Only exact SSA value
   identities justify removing representation operations afterward.
3. Extend the existing `AdaptedCallable`, `DeferredCallableAdapter`, and
   `lower_adapted_call` mechanisms. Audit forced materialization in erasure,
   type application, and forwarding; keep conversions structured until their
   use requires a closure. Immediately invoked adaptations should execute
   their conversions without allocating an adapter environment.
4. Across aggregate storage, optimize emitted VM CFG after callable-flow and
   before ARC. Physical Lowering supplies the identities of generated adapters;
   VM CFG does not classify adapters by opcode patterns or presentation text.
   Compose known adapter-to-adapter calls using the existing body instantiation
   mechanism. Visit original call sites once and copy original bodies; do not
   recursively unfold copied calls or spread adapters into ordinary callers.
   This is a finite composition over existing edges, not a general-purpose
   inlining policy. Simplify changed bodies before recomputing flow. Local rules
   eliminate actual erase/unerase pairs and projections from the same SSA
   construction, without assuming equal capture values from allocation sites.
   Never feed late demand back into the completed specialization plan.
   Storage-only generic code cannot independently change a shared container's
   representation if other consumers invoke its elements generically. Any
   specialized storage/consumer contract must be planned consistently at both
   ends, not discovered by the emitter.
5. Where a target or value identity cannot be proved, retain the generic path.
   Reuse one worker per canonical specialization key, preserve finite recursive
   demand and generic fallback, and do not add a parallel flow analysis or
   emission-time specialization policy. Separately prove call cancellation and
   allocation removal: an adapter still used by another generic consumer must
   remain. Let existing use-def/cleanup remove dead environments and functions
   only after their uses disappear. Static-capture materialization belongs to
   ISS-438, not another implementation-sharing mechanism here.

Preserve higher-kinded/effect companion evidence, source effects, and cleanup
semantics throughout. Further changes to the runtime ABI or lifetime policy
require user discussion before implementation. No new public IR or runtime
dispatch protocol is prescribed by this plan.

## Implementation checkpoint: actual bodies, not endpoint cancellation

The rejected, uncommitted contract-cancellation experiment passed Basic but
broke `examples/valid/32_state_effect.lane` in both JIT and interpreter. It
replaced behaviorally equivalent higher-order results with differently
represented closures; a later target-specific environment projection then
became invalid. The source-to-Wasm State regression locks `[42, 42]`. This was
a compiler rewrite defect, not a Wasmoon defect. Its provisional size wins are
not accepted results.

The user approved replacing that experiment with actual-body composition.
The inverse-contract certificates and their cancellation API were deleted;
no speculative whole-program candidate-validation/rollback framework was
added. Cross-function capture facts and the general checked
`BorrowClosureEnvironment` remain useful: they refer to the current callable
instance, preserve its borrow root, and never equate dynamic instances.

The current implementation retains generic representation specialization,
uses the existing SSA/flow owners, and simplifies actual generated code before
ARC. A broader adapter-inlining experiment increased Basic instruction counts
and was removed; it is not the scope of this representation cleanup. Tests
cover numeric round trips, different closure targets,
recursive implementation retention, forward-definition rejection, shared
generic/concrete containers, distinct captures, and the State regression.
Correctness alone is insufficient for closure; the motivating composition must
also be eliminated without offsetting representation costs.

Further work needs a call-site-local evaluation of the actual adapter body,
using the current invocation's environment/arguments while retaining shared
implementations. This requires separating the existing callable-flow owner's
body transfer from its whole-program fixed point, not adding a second flow
producer or forcibly narrowing a shared summary. Local invocation facts must
not overwrite facts for closures allocated by other invocations of the same
function. Reusing a function index as though it identified a dynamic frame
would repeat the representation/context mistake.

Discuss that analysis boundary with the user before extending the optimizer.
Do not replace it with universal adapter inlining, a magic unfolding budget,
or deletion of required generic wrappers. No production commit or issue
closure is justified by this checkpoint alone.
