## Description
Module Frontend stores successful modules, recovered headers, source syntax,
and diagnostics in parallel arrays. Import-reachable compilation then computes
source reachability, recovered-header reachability, graph validation, and graph
construction through separate traversals; the compile facade rebuilds the graph
again. The semantic workspace consumes the same parallel arrays by positional
convention.

Module dependency failures are also classified and rendered twice. Module
Frontend and Module Compile independently own missing-import and import-cycle
kinds, E4000/E4002/E4003 codes, labels, notes, helps, and candidate facts.

## Design
Represent each parsed source as one record containing its source identity,
text, concrete syntax, identifier index, diagnostics, and either a valid module
or a recovered header. Build strict and tolerant dependency results from that
single source collection.

Make Module Graph the sole producer of import reachability, missing dependency
facts, cycle facts, and topological order. Strict compilation should consume a
completed graph directly instead of receiving a `ModuleInputSet` and rebuilding
it. Tolerant workspace analysis consumes the same parsed-source and graph facts
with an explicit unavailable-source policy.

Define one structured Module Dependency Failure and one diagnostic adapter in
Module Frontend. Source graphs and interface-artifact closure analysis provide
only provenance and candidate inputs; Module Compile must not reclassify or
rerender the same dependency failure.

## Acceptance Criteria
- [ ] One parsed-source value owns syntax, recovered header, diagnostics, and
      valid/invalid module state without parallel positional arrays.
- [ ] Strict import-reachable parsing returns the one validated Module Graph
      consumed by compilation; no caller rebuilds it or recomputes reachability.
- [ ] Tolerant semantic-workspace topology uses the same graph implementation
      and explicitly records unavailable parsed modules.
- [ ] Missing import, import cycle, duplicate input, and missing-root dependency
      failures have one structured classification and diagnostic adapter.
- [ ] Source and interface-artifact dependency failures preserve their distinct
      provenance while sharing codes, messages, facts, and suggestions.
- [ ] Black-box compile and Semantic Workspace tests cover reachable invalid
      sources, unrelated invalid sources, missing imports, cycles, and duplicate
      modules without testing parallel-array layout.
- [ ] The old reachability traversals and duplicate dependency diagnostic
      variants are deleted.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
