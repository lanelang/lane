## Description
Expose module aliases consistently through semantic analysis and validate the
feature across the complete native compiler workflow.

## Design
Index the alias token as a local Module Binding definition and qualifier
occurrences as references to it. Member references continue to target original
exported declarations. Completion exposes only the local alias as the module
candidate and completes the canonical interface after `Alias.`. Semantic type
presentation remains canonical.

## Acceptance Criteria
- [x] Definition on an alias qualifier targets the alias token; definition on a member targets the original declaration.
- [x] Completion exposes the local alias, hides the replaced complete path, and completes module members after the alias.
- [x] Alias hover identifies both local name and canonical module target.
- [x] Unused-import diagnostics follow the accepted authored-binding and canonical-sugar rules.
- [x] Valid and invalid integration examples cover alias use across values, types, nominal members, and effects.
- [x] `moon info`, `moon fmt`, `MOONBIT_NEW_NATIVE=0 moon test --target native`, and `git diff --check` pass.
