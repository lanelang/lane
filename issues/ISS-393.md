# ISS-393: Preserve generic nominal contracts in representation workers

## Description
Closed runtime-representation workers are safe only when specializing the
callable boundary does not silently change a value contract owned by uniform
generic nominal storage.

Extending worker discovery from top-level `Let` definitions to the effect-
lowered `LetRec` group selected a worker for `increment_mixed` in the existing
effect-polymorphic callback regression. The worker specialized its result to
concrete `I64`, but a callable projected from the declaration-owned effect
context data still implemented the Canonical Generic ABI. The worker invoked
that stored callable through the specialized contract. The Physical Program
verifier accepted the image, then the direct interpreter, Wasm interpreter and
Wasm JIT all trapped at the same callable ABI guard after six of ten expected
observations.

The current `Let`-only candidate boundary avoids this program but is not the
semantic proof. Representation specialization must preserve generic nominal
storage contracts independently of the top-level scheduling syntax.

## Design
Keep the closed worker key and generic fallback from ADR-0138. Replace blind
whole-body runtime-type substitution with a representation-aware Runtime ANF
rewrite:

- specialize the worker's callable boundary and ordinary local values;
- continue to consume each constructor, field and existential payload through
  its declaration-owned Generic Nominal Data Schema;
- insert structural adaptation where a specialized local value enters or
  leaves that uniform storage contract;
- never infer that a callable stored under erased evidence was co-specialized
  merely because the enclosing worker has closed evidence;
- reject a worker candidate before emission when the rewrite cannot produce a
  complete source and target Physical Value Contract.

The worker key contains the complete structural callable contract and the
closed Runtime ANF arguments consumed by the body rewrite. The latter are
required even when uniform nominal storage hides them from the outer callable
ABI: two `Connector[A, B]` values can have the same aggregate ABI while nested
callable adaptations require different nominal runtime categories. These are
runtime-projected arguments, not source type equality.

The rewrite remains private to Physical Lowering and rewrites the actual ANF
body. Do not restore a representation plan, specialized nominal family,
parallel physical IR, or `Let`/`LetRec` name-based eligibility rule. The
Canonical Generic ABI remains independently executable when specialization is
disabled.

## Acceptance Criteria
- [x] A minimal closed worker crossing a generic nominal callable field executes
      identically with specialization enabled and disabled.
- [x] `direct and forwarded elaboration agree across effect representations`
      passes on the direct interpreter, Wasm interpreter and Wasm JIT when its
      eligible effect-lowered definitions occur in `LetRec`.
- [x] Constructor insertion and match/projection consume the one
      declaration-owned generic storage contract and expose explicit adapters
      for unequal local contracts.
- [x] Equal complete contracts introduce no adapter or erase/unerase bridge.
- [x] Worker discovery may cover `LetRec` without using scheduling syntax as a
      safety condition.
- [x] The generic fallback remains executable and no specialized nominal data
      family or consumer-visible representation plan is introduced.
- [x] Explore shows the worker and every required generic-ABI crossing without
      an execution trap or unexplained adapter.
- [x] `moon info`, `moon fmt`, strict native check, native tests, and valid
      examples pass.

## Notes
- 2026-08-27: Discovered while broadening ISS-368's closed-worker coverage to
  top-level recursive groups. Disabling representation specialization restores
  all three backends, proving this is an optional rewrite defect rather than a
  backend runtime bug.
- 2026-08-27: Implementation started from a red regression at the generic
  nominal callable-field boundary. The fix must make storage contracts explicit
  during worker rewriting before `LetRec` discovery is restored.
- 2026-08-27: Full examples exposed a second collision: two closed `compose`
  instances shared the same outer aggregate ABI but required different nested
  nominal callable contracts. The shape guard correctly rejected the reused
  worker. The final key therefore owns both its structural callable contract
  and its closed runtime rewrite arguments.

## Close Notes

Closed after restoring `LetRec` worker discovery, removing ambient substitution
from slot allocation, enforcing result-boundary adaptation for every lowered
function, and making worker identity cover complete callable structure plus the
closed Runtime ANF arguments used by the body rewrite. Generic nominal schemas
remain declaration-owned and unequal crossings continue to use explicit
structural callable adapters.

Regression coverage includes specialization-on/off nominal-field execution, a
three-backend black-box case with two nested nominal contracts sharing one outer
aggregate ABI, the existing direct/forwarded effect matrix, and Explore worker
provenance. Verified with `moon info`, `moon fmt`,
`moon check --target native --warn-list +73`, `moon test --target native`
(1724/1724), the valid-examples gate, and direct JIT/Interpreter execution of
examples 55, 94, and 95.
