## Description
ISS-385 established the necessary semantic distinction between Runtime ANF
types and selected physical representations, but commit `affb6df3` implemented
that distinction as a large sidecar plan. `physical_representation.mbt` alone
contains 4,461 lines and 126 functions, while `callable_instance_plan.mbt` now
contains 5,024 lines and 155 functions. The commit added 13,739 lines, deleted
4,128, and increased the repository by 9,611 lines.

The size is a symptom rather than the primary defect. Runtime ANF is currently
interpreted separately by semantic callable-flow analysis, physical sidecar
planning, and VM CFG emission. The physical planner reconstructs expression
result types and atom shapes, stores site-keyed plans for calls, constructions,
matches, captures, and allocations, then requires the emitter to query and
revalidate those tables while it traverses the original ANF again. Runtime
type classification and local-value shape reconstruction also remain in the
emitter. A new ANF construct can therefore require synchronized switches in
three implementations.

The current code is a valuable correctness baseline: it removed ambient data
family selection, freezes generic invocation contracts, and makes unequal
representation flow name an explicit bridge. This issue preserves those
properties while replacing the shallow sidecar interface with a necessary IR
whose structure directly carries the physical facts VM CFG emission consumes.

## Design
Replace the current pipeline with one explicit elaboration:

```text
Runtime ANF + semantic callable flow
  -> Representation Constraint Graph
  -> Representation Solution
  -> Physical ANF
  -> VM CFG
```

The Callable Instance Plan retains only semantic callable identity, exact
call/capture/allocation flow, lexical generic application, and finite SCC
facts. One traversal of each reachable Runtime ANF body builds a Representation
Constraint Graph over stable value ports. One solver is the sole producer of
non-local data-family, callable-target, representation-worker, and bridge
choices. The Physical ANF constructor combines that solution with canonical
runtime-type classification and is the sole producer of final value, callable,
capture, and function-boundary contracts.

The solution is materialized as a nominal `PhysicalAnfProgram`, not as side
tables paired with the original tree. Physical call, construction, match,
capture, allocation, parameter, result, and join nodes directly carry their
selected shapes and any required bridge. Its verifier proves shape equality on
identity flow, complete data-family storage contracts, exact callable ABIs,
bridge legality, and one worker per canonical contract before emission.

VM CFG lowering consumes only verified Physical ANF and is mechanical. It does
not query `planned_*` tables, rediscover expression result types, select a
family or worker, reconstruct a callable ABI, or compare an emitted local value
against a second shape calculation. Primitive instruction selection may still
consume already-classified scalar kinds; it must not become another physical
representation producer.

The canonical generic elaboration remains the total correctness baseline.
Closed specialization is accepted only from the finite solved graph; open,
existential, joined, or recursively expanding components remain generic as a
whole. This issue introduces no size, frequency, call-count, or profitability
heuristic. ISS-368 resumes only after this representation seam is complete.

Implementation must replace old machinery in the same migration. Do not add
Physical ANF beside `PhysicalRepresentationPlan`, retain compatibility
fallbacks, or move the same switches into another package. Preserve the
behavioral tests from ISS-363 through ISS-386, then delete obsolete sidecar
plans, demand projections, query helpers, and emission-time consistency
plumbing.

## Acceptance Criteria
- [x] The owning glossary and ADR define the independent invariant of verified
      Physical ANF and distinguish it from semantic Runtime ANF and VM CFG.
- [x] Callable Instance Plan contains only semantic callable and allocation
      flow; it no longer produces physical shapes, family assignments, worker
      demands, adapter recipes, or bridge decisions.
- [x] One Representation Constraint Graph owner and solver own all non-local
      data-family, callable-target, worker, and bridge choices; the Physical ANF
      constructor solely owns final port, callable, capture, and function
      contracts.
- [x] `PhysicalAnfProgram` structurally represents calls, constructions,
      matches, captures, allocations, joins, and function boundaries with their
      selected physical contracts; no site-keyed sidecar is required to
      interpret the original Runtime ANF tree.
- [x] The Physical ANF verifier rejects missing or illegal bridges, incomplete
      data families, inconsistent callable ABIs, duplicate workers, and
      unresolved physical ports before VM CFG emission.
- [x] VM CFG emission is a mechanical consumer of verified Physical ANF and
      contains no `planned_*` lookup family, runtime-type-driven representation
      selection, worker discovery, adapter discovery, or duplicate local-shape
      reconstruction.
- [x] Delete `PhysicalRepresentationPlan` as a sidecar, the physical-demand
      responsibilities currently embedded in `CallableInstancePlan`, and all
      superseded compatibility/query paths in the same change.
- [x] Every retained representation abstraction owns a necessary invariant or
      hides a repeated decision behind the Physical ANF interface. Delete
      superseded sidecars, duplicate traversals, compatibility paths, and
      defensive recomputation rather than preserving them to reduce migration
      risk.
- [x] Generic fallback, finite recursive SCCs, nominal data-family separation,
      higher-kinded evidence forwarding, and exact source/target adapter ABIs
      preserve all ISS-363 through ISS-386 black-box and backend-conformance
      behavior.
- [x] Fresh Explore output records the same or fewer functions, adapters,
      bridges, closures, environments, instructions, and indirect calls as the
      sound ISS-385 Scheduler baseline; ISS-387 itself does not trade runtime
      scale for compiler-source reduction.
- [x] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`, and
      the complete valid examples corpus passes.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

  IDs: refined callable result families currently alias their generic source.
- 2026-08-25: Implementation resumed. Production LOC is explicitly not an
  acceptance criterion: a numeric target could reward compression or removal of
  necessary invariants. Simplicity is enforced structurally by replacement,
  single ownership, and deletion of machinery with no independent invariant.
- 2026-08-25: The first replacement slice now materializes calls,
  constructions, matches, binding flows, callable allocations, and evidence
  applications into structural Physical ANF. VM CFG expression emission
  consumes that tree, the emitted function contract no longer retains the
  site-keyed planner arrays, and the old `planned_*` lookup family has been
  removed. The Physical ANF verifier now walks the structural program before
  emission. Constraint-graph ownership and remaining emission-time defensive
  reconstruction are still in scope, so the issue remains in progress.
- 2026-08-25: Physical constraint collection and assignment now have explicit
  `RepresentationConstraintGraph` and `RepresentationSolution` owners. The
  semantic `CallableInstancePlan` contains only semantic instances, call sites,
  and rejected recursive groups. Owning glossary, ADR-0134, ADR-0136, and the
  representation-elaboration RFC now describe the structural Physical ANF
  boundary instead of the deleted represented-program sidecar. Temporary
  elaboration tables and refined-target-wide result/capture identities remain
  migration work; the issue is intentionally not closed.
- 2026-08-25: Physical elaboration now returns `(shape, PhysicalAnfExpr)` from
  the same recursive walk. It no longer fills call, construction, match, and
  binding-flow sidecars and then traverses the original Runtime ANF again to
  recover those facts by site. The obsolete materialization traversal,
  `required_*` lookup family, and construction/match/binding-flow tables were
  deleted. The remaining planner tables are lexical elaboration environments
  or canonical allocation interning, not inputs paired with the emitted tree.
- 2026-08-25: Callable atoms now distinguish lexical allocation from an
  existing callable reference. Only the former may construct a selected
  worker with in-scope captures; the latter preserves its producer invocation
  and uses an explicit callable bridge when a consumer requires another ABI.
  Callable interface projection is consequently keyed by the frozen producer
  invocation instead of being reconstructed from a semantic target. The full
  native suite passes 1787 tests and the complete examples gate passes. Refined
  target identities in the constraint graph remain open work.
