# ISS-420: Remove the abandoned generic Array feature

## Metadata

## Description
Remove the experimental compiler-built-in pure generic `Array[T]` feature and
deprecate its RFC. The implementation fixed one collection policy into every
semantic and runtime boundary while providing no indispensable language
capability or current consumer.

## Design
Remove the feature as one vertical slice: semantic identity and intrinsic
contracts, artifact support, Runtime ANF, VM CFG and Physical operations, Wasm
runtime support, Basic bindings, tests, examples, and generated interfaces.
Do not leave compatibility aliases, fallback recognition, reserved identities,
or dead runtime helpers. Preserve the RFC as a historical rejected design with
an explicit deprecation rationale.

## Acceptance Criteria
- [x] No Lane compiler IR or ABI contains an Array-specific identity,
      instruction, layout recipe, contract, or verifier rule.
- [x] The Wasm target emits no Array runtime or helper function.
- [x] Basic exposes no compiler-backed generic Array API.
- [x] Array-specific examples and fixtures are removed.
- [x] The RFC and ISS-296/415-419 record that the proposal was withdrawn.
- [x] Generated interfaces and parser artifacts are regenerated and contain no
      stale Array feature entries.
- [x] Native tests, the examples gate, and pinned Basic tests pass.
