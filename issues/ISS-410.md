## Description
Core optimization recognizes a top-level static constructor only when the
definition is syntactically `Construct`. Closed pure initializers behind aliases
and `Let` spines lose their known value, and consumers inspect syntax
independently.

## Design
Extend `CoreAnalysis` with one conservative static-head domain for facts that
are safe to duplicate or project: unknown, literal, and constructor with closed
pure payloads. Compute summaries through closed, effect-free alias and `Let`
spines with cycle-aware memoized evaluation.

Match reduction consumes this analysis. Callable identity remains owned by the
existing interprocedural callable analysis; adding an unused callable summary or
an expression-wide type-beta evaluator here would create a second producer. The
summary does not execute effects, reorder strict initializers, invent a value
for an open or recursive cycle, or become a second IR.

## Acceptance Criteria
- [x] `CoreAnalysis` is the sole producer of static top-level value summaries.
- [x] Closed pure aliases and binding spines expose constructor and literal
      summaries; effectful, open and cyclic values remain unknown.
- [x] Existing constructor-match reduction consumes summaries rather than
      inspecting top-level definition syntax.
- [x] Public pipeline regressions cover observable reduction; focused white-box
      tests cover otherwise invisible fixed-point and cycle invariants.
- [x] Native tests, examples and Basic preserve behavior.
