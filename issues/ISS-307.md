# ISS-307: Enforce binder freshness or make type substitution capture-avoiding

## Description
`Type::normalize` documents "capture-avoiding substitution" (buslane.mbt:1227),
but `substitute_with_bound` (buslane.mbt:1323) only blocks substitution of
shadowed parameters; it never renames a binder whose id occurs free in a
replacement. The safety of every substitution therefore rests on a
binder-freshness convention that no verifier checks — an invariant enforced by
comment.

The verifier itself is a victim: `synthesize_type_apply` (verify.mbt:598)
computes instantiated types with `body.substitute(...)`. When an in-scope
parameter id is also used as a nested binder inside the callee's type — legal
today, both ids come from ordinary `define_type_parameter` calls — the computed
type captures, and every downstream check runs against the wrong type. Measured:

```moonbit
// g : Forall([x], Forall([y], (x) -> Unit))
// expr = Λy. g[y]
let facts = query.synthesize(TypeLambda([y], TypeApply(Ref(g), [TypeArgument(Parameter(y))]))).unwrap()
assert_eq(facts.type_(), Forall([y], Forall([y], Function([Parameter(y)], Primitive(Unit), Empty))))
// The outer y was captured by g's inner binder.
```

Because of ISS-306's first-match lookup, alpha then reads the captured type as
the intended one — two defects composing to hide each other. Fixing either in
isolation will surface the other; land them together or in sequence with tests
covering the composition.

## Design
Decide where the law lives, then enforce it in exactly one place:
- Either the verifier enforces global binder freshness (each TypeParameterId
  bound at most once per program, never rebinding an id already in scope), and
  substitution may stay cheap; note that beta reduction can duplicate binders,
  so normalization output must be exempt from the uniqueness law or must
  refresh binders as it duplicates.
- Or substitution becomes genuinely capture-avoiding (rename binders on
  collision) and shadowing stays legal.
The doc comment must state whichever contract is real.

## Acceptance Criteria
- [ ] The reproduction above either fails verification (freshness law) or synthesizes the non-captured type (capture-avoiding substitution).
- [ ] `Type::normalize`'s documentation matches the implementation.
- [ ] A regression test pins the chosen behavior for TypeApply, Construct, Perform, and handler-alternative substitution sites.
