# ISS-398: Make Runtime ANF a fully verified boundary

## Description
`AnfProgram` is documented and exposed as the closed, backend-lowerable Runtime
ANF boundary, but its construction currently runs only the callable-disposition
check. Missing runtime metadata, unbound values or temporaries, and malformed
recursive groups can therefore cross the boundary and are first detected by
Physical Lowering as `MissingValueMetadata`, `UnsupportedExpression`, or
join-group errors.

## Design
Make the opaque `AnfProgram` the verifier-proven Runtime ANF type. Its sole
construction path must run one complete Runtime-ANF-owned verifier after all
simplification and callable classification. The verifier owns metadata
integrity, lexical value/evidence/temporary scope, unique identities, ANF
binding and recursive-group structure, and callable disposition. Physical
Lowering consumes this established contract and must not retain a second input
validation policy for these facts.

Do not add a shallow `VerifiedAnfProgram` wrapper: private `AnfProgram` fields
already prevent external construction. Keep failures structured and test the
private invalid states directly with white-box tests; valid source programs
remain covered through public compilation tests.

## Acceptance Criteria
- [x] Runtime ANF rejects incomplete metadata and invalid referenced metadata.
- [x] Runtime ANF rejects unbound or duplicate value, temporary, evidence, and
      callable identities with lexical provenance.
- [x] Runtime ANF rejects empty, non-callable, or mixed-disposition recursive
      groups and invalid top-level callable dispositions.
- [x] Callable-disposition validation is part of the complete Runtime ANF
      verifier rather than the only boundary check.
- [x] Physical Lowering no longer owns Runtime ANF metadata, scope, or
      recursive-group input diagnostics.
- [x] Focused white-box invalid-IR tests and the normal black-box lowering path
      pass.
- [x] `moon info`, `moon fmt`, strict native check, and native tests pass.

## Notes

  callable-disposition sub-invariant, not the complete Runtime ANF boundary.
- 2026-08-28: Full-corpus validation corrected two initially over-strong
  assumptions: local metadata types may refer to lexically bound evidence, and
  optimized function clones may reuse a `ValueId` in disjoint lexical scopes.
  The verifier now checks both facts at their actual lexical sites.

  evidence arity, not the instantiated result type, while constructor
  validation ignores instantiated owner arguments and payload types.

## Close Notes
- 2026-08-28: `AnfProgram` construction was believed to close through a complete verifier
  for runtime metadata, type expressions, evidence arity, lexical scopes,
  runtime expression contracts, recursive groups, matches, identities, and
  callable disposition. Invalid-IR white-box regressions cover missing
  metadata/type expressions, unbound values/temporaries, empty recursion, and
  disposition disagreement.
- 2026-08-28: Physical Lowering consumes total verified metadata accessors and
  no longer owns missing-metadata, unsupported-expression, top-level recursion,
  payload-arity, or join-disposition input errors. Remaining structural
  failures are explicitly representation-elaboration invariants.
