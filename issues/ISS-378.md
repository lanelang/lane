## Description
Callable conversion has had two identity producers: source-type adaptation
planning and late VM CFG body equivalence. The attempted repair introduced a
persistent Callable Adapter Recipe with its own evidence, layout, nested
adapter, provenance, and occurrence models. That removed late rediscovery but
turned one structural conversion into another shallow compiler subsystem.

## Design
Representation Elaboration owns one operation:

```text
adapt(source_callable_contract, target_callable_contract, value)
```

The operation recursively aligns parameters, evidence, and result contracts.
Identity emits nothing. Direct invocation may fuse conversion into the call.
First-class escape materializes one worker for the complete structural source
and target contracts; each occurrence supplies its own captured values.

The memo table that prevents duplicate workers is private implementation state.
It is not emitted as a recipe catalog or occurrence sidecar. Recursive callable
identities come from the Physical Callable Contract Graph owned by Physical
Lowering. Its invocation projection is the ABI identity; there is no second
ABI-only graph and no adapter-specific graph canonicalization.

VM CFG function-table cleanup owns reachability and general exact duplicate
removal only. It does not recognize adapters or reconstruct their identity.

## Acceptance Criteria
- [x] One structural adaptation operation owns callable parameter, evidence,
      and result conversion.
- [x] Identity and directly fused conversions allocate no worker, environment,
      closure, or function-table entry.
- [x] First-class escape materializes at most one worker for a complete
      structural source/target contract while preserving site-specific captures.
- [x] The implementation exposes no adapter recipe catalog, nested-recipe
      graph, transition-occurrence sidecar, or source-type identity key.
- [x] VM CFG canonicalization contains no adapter-specific equivalence logic.
- [x] Recursive callable ABI interning contains only physical call
      compatibility, not source binders or specialization demand.
- [x] Full lowering observations cover direct fusion and multiple escaping
      materializations sharing workers; focused white-box tests are limited to
      otherwise unobservable recursive ABI, capture, and one-worker invariants.
- [x] Explore records adapter and bridge deltas and demonstrates no aggregate
      Physical Program or Wasm size regression. Individual bridge counters are
      not required to be monotonic when direct fusion replaces a shared worker
      call with local structural conversion.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      `moon test --target native`, and the valid examples gate pass.

## Close Notes

- Replaced the persistent recipe, nested-recipe, and recipe-execution subsystem
  with one structural callable adaptation operation owned by Physical Lowering.
  Direct calls consume it in place; escaping values use a private memo keyed by
  complete physical source and target contracts.
- Physical callable contracts now form one finite recursive graph whose
  invocation projection owns call compatibility. Adapter keys reference this
  graph without retaining source binder identity or specialization demand.
- Capture discovery now observes substitution- and beta-reduced physical value
  shapes. This removed an unused witness that previously made structurally
  identical workers disagree about their environment member count in valid
  examples 79--81.
- On example 37, initial VM CFG changed from 61 to 60 functions, 51 to 50
  environments, and 307 to 304 instructions. The Physical Program changed from
  61 to 60 functions, 438 to 413 slots, and 347 to 342 instructions. Wasm
  changed from 116 to 110 functions, 10,795 to 10,365 instructions, 794 to 757
  locals, and 88 to 82 table entries. Direct fusion places one additional erase
  and one additional unerase at the fused site while retaining the shared
  escaping worker; this is an explicit local-conversion tradeoff, not a global
  profitability heuristic.
- `moon test --target native` passed 1,710 tests. The valid examples gate passed
  against Basic fixture `03c3fb19c0a8`; `moon info`, `moon fmt`, and native
  warning-enabled checking also completed successfully.
- 2026-08-29: Removed the later ABI-only graph projection. Recursive contract
  construction now reserves an identity before constructing child contracts,
  and all equality is coinductive over the one Physical Callable Contract
  Graph.
