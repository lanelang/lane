## Description
Selective CPS uses "residual" for three different things, two of which mean
opposite halves of an effect row.

| name | means |
| --- | --- |
| `residual_effect_part`, the `%residual` type parameter | `Io` and External Effects — the part CPS does not eliminate |
| `ResidualComputationSchema` | the computation still monadic after an installation — the part CPS *does* eliminate |
| the `%residual` value binder in `lower_cps_residual_bind` | a `Bind`'s value binder |

`ResidualComputationSchema` holds both senses at once, as `effect` for the
monadic part and `residual_effect` for the other. The two `%residual` names
collide in Buslane dumps, distinguishable only by which table they sit in.

## Design
Keep "residual" for the Non-Monadic Residual Effect, which is what
`CONTEXT.md` already defines, and rename the other two. The installation's
still-monadic computation is what `CONTEXT.md` calls the handled expression's
unhandled part; the value binder is just a bind result.
