## Description
The Coroutine Scheduler reached initial VM CFG with 19 direct calls and 47
indirect calls. The old callable-flow analysis only propagated local aliases
and recursively embedded aggregate member facts. It therefore missed direct
targets across calls, results and storage, and it did not terminate when a
recursive program made the aggregate fact tree grow on every fixed-point pass.

Some continuations genuinely escape through `Step` and `Queue`. Every remaining
indirect call needs a factual function origin, target-set result and flow path;
presentation must not infer these facts from names, text or array positions.
Distinguishing source-written anonymous functions from CPS-introduced functions
requires an earlier provenance owner and is tracked separately by ISS-391.

## Design
Runtime ANF owns callable identities and source-binding provenance. VM CFG owns
a private, finite allocation-site graph for final physical target and
environment flow. Values reference immutable aggregate construction sites;
aggregate fields reference value cells, so recursive data forms graph cycles
rather than recursively copied facts.

The analysis propagates facts through aliases, block and function parameters,
function results, globals and immutable aggregate projections. For a closed
zero-input execution image, an opaque callable is resolved against the complete
set of materialized, ABI-compatible callable targets. Open roots remain open.
Only a singleton capture-free target or a singleton target with a still-local
environment owner becomes a direct call. A statically known target whose
environment remains packed stays indirect; the analysis must not reuse an SSA
owner after closure construction or storage.

Explore consumes this classification; it must not derive it from labels,
function names, spans, storage positions, or rendered IR. Devirtualize only
singleton target sets with an exact environment and callable ABI. Do not add a
fallback opcode, persistent callable-instance plan, first-seen target rule, or
call-count heuristic.

## Acceptance Criteria
- [x] Every initial VM CFG and final Physical Program indirect call has a structured classification
      and typed provenance produced by the owning analysis.
- [x] Source-bound, anonymous, callable-adapter, representation-worker,
      initialization and runtime-support origins are reported as factual
      categories; ISS-391 owns finer source-written versus CPS-introduced origin.
- [x] Singleton target sets with exact environment and callable ABI lower to
      direct calls, including flows through aliases, parameters, results, and
      immutable aggregate fields.
- [x] Multi-target, open-root, packed-environment, and genuinely escaping callables
      remain indirect without speculative guards or fallback dispatch.
- [x] The Coroutine Scheduler contains 44 indirect calls: nine have one exact
      packed-environment target and 35 have multiple compatible targets. It has
      no unclassified target set or flow path.
- [x] JIT and `--no-jit` execution both produce `1112211322`.
- [x] Recursive aggregate programs terminate without analysis fuel; the real
      Flip Effect and Integer Set ADT examples and a focused site-graph
      regression cover the former non-termination.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
