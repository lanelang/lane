# ISS-354: Preserve escaping VM CFG block parameters during simplification

## Description
VM CFG simplification decides whether to remove a block parameter from only the
uses in that block. A parameter may instead define an SSA value that remains
live in a dominated successor. Removing the parameter and its incoming edge
argument leaves the later use without a definition.

The former post-bytecode slot allocator accidentally hid this defect when it
coalesced the undefined logical value with an initialized physical slot. Moving
physical-slot planning to its documented VM CFG boundary exposed the invalid
program as a bytecode verifier failure in example 67.

## Design
Make `UseDefAnalysis` the sole owner of indexed VM CFG use facts: value use
sites and whole-CFG counts, per-block counts, and instruction/terminator use
lists. Simplification must consume these facts when retaining block parameters
and threading empty jumps. ARC insertion, liveness, projection selection,
devirtualization, and physical-slot planning must consume the same analysis
rather than rescan blocks. Raw instruction and terminator operand projection is
syntax knowledge used to construct or safely prevalidate the analysis, not an
independent CFG fact index.

Thread an empty jump block only when each parameter has no use outside that
block, because only local outgoing-edge occurrences can be substituted by the
threading operation. Keep physical-slot planning strict: every active VM CFG
value must have a definition; allocation must never repair an invalid CFG
through incidental coalescing.

## Acceptance Criteria
- [x] A block parameter used only in a dominated successor remains defined after simplification.
- [x] Empty-jump threading does not bypass an escaping block-parameter definition.
- [x] Physical-slot planning reports a structured compiler defect for an active value without a definition.
- [x] The real nested-tuple-pattern example compiles and runs through the integration gate.
- [x] `UseDefAnalysis` owns whole-CFG, per-block, and instruction/terminator use facts.
- [x] Simplification, ARC/liveness, projection selection, devirtualization, and slot allocation consume the shared analysis.
- [x] Consumer-owned whole-body and per-block use-count traversals are deleted.
- [x] Checked use-definition construction rejects duplicate SSA definitions and
      reports both definition sites.
- [x] ARC-final VM CFG carries the validated use-definition index consumed by
      physical-slot planning.
- [x] Native tests and formatting/checking gates pass.

## Close Notes

`UseDefAnalysis` now owns the indexed whole-CFG, per-block, and
instruction/terminator use facts consumed by simplification, ARC and liveness,
projection selection, devirtualization, and physical-slot planning. The former
consumer-owned whole-body and block count traversals are deleted. Empty-jump
threading still requires all parameter uses to be local to the threaded block,
and the slot plan still rejects active values without definitions. Structured
analysis coverage fixes the global and per-block counts for a diamond CFG; the
original simplifier regression preserves a parameter used only by a dominated
return. Checked index construction now rejects duplicate instruction, input,
and block-parameter definitions with both sites preserved. Ownership threading
creates fresh SSA block parameters, and `ArcFinalBody` carries the validated
index into physical-slot planning without reanalysis.
