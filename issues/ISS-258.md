# ISS-258: Rename existing numeric primitives across Lane

## Description
Replace the existing source and internal primitive vocabulary `Int`, `S32`, and `Double` with `I64`, `I32`, and `F64` throughout the Lane compiler and runtime without retaining compatibility aliases.

## Design
Rename semantic variants and operations at their owning layers instead of translating names at presentation boundaries. Preserve existing bit-level behavior while updating source lookup, literal elaboration, diagnostics, Buslane, VM CFG, bytecode, backends, artifacts, host ABI descriptions, analysis displays, and compiler-owned tests.

## Acceptance Criteria
- [x] Primitive lookup accepts I64, I32, and F64 and rejects Int, S32, and Double as primitive names.
- [x] Integer literals default to I64 and elaborate to I32 under an I32 expectation; floating literals use F64 until F32 is introduced by ISS-259.
- [x] Internal semantic variants and instructions no longer use the removed source vocabulary where they represent these primitives.
- [x] Compiler diagnostics, semantic tooling, text formats, artifacts, runtime import kinds, and tests use the new names.
- [x] `moon info && moon fmt` and `moon test --target native` pass for the completed rename stage.
