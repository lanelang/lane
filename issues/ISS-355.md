## Description
Commit `4f816b1d` combined the ISS-337 Wasm-local allocation work with an
unowned dependency baseline change. It upgraded `jsonrpc2` 0.0.33 to 0.0.34,
`async` 0.20.3 to 0.20.4, `x` 0.4.48 to 0.4.49, `milkir` 0.5.1 to 0.6.0,
`wasm_core` 0.4.0 to 0.5.0, `wasmoon` 0.11.2 to 0.12.0, and `wasmoon_jit`
0.6.2 to 0.7.0. None of ISS-337, ISS-350, or ISS-351 owns that release and
compatibility decision.

## Design
Treat the four module manifests as one explicit dependency baseline. Retain the
upgraded versions only if their actual consumers pass independent compatibility
evidence: compiler and browser packages for `x`; the public framed LSP and CLI
for `jsonrpc2` and `async`; and LoisVM interpreter, Wasm compiler, default JIT,
and `--no-jit` execution for the Wasm dependency family.

The repository integration gate must exercise shipped examples, CLI behavior,
and LSP lifecycle against one freshly built executable. Do not add local
dependency overrides, dual-version fallbacks, compatibility shims, or feature
issue acceptance criteria to justify this baseline. Future aggregate upgrades
must have their own issue and commit.

## Acceptance Criteria
- [x] The exact previous and current versions and their consumer boundaries are recorded.
- [x] `moon info`, `moon fmt`, and `moon test --target native` pass with the upgraded baseline.
- [x] The integration gate passes examples, CLI JIT and `--no-jit` behavior, and the public LSP session checks with one freshly built executable.
- [x] Generated interfaces contain no unexplained public API change caused by the dependency refresh.
- [x] ISS-337, ISS-350, and ISS-351 treat this baseline as related maintenance rather than part of their feature or bug contract.
