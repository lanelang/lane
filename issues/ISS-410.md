## Description
Core optimization recognizes a top-level static constructor only when the
definition is syntactically `Construct`. Closed pure initializers behind alias,
`Let`, type abstraction/application, or other administrative spines lose their
known value, and consumers inspect syntax independently.

## Design
Extend `CoreAnalysis` with one conservative static-value domain for facts that
are safe to duplicate or project: unknown, literal, constructor with summarized
payloads, and known callable when the existing callable analysis can supply its
closed substitution. Compute summaries through closed, effect-free binding
spines with cycle-aware fixed-point evaluation.

Match reduction, projection reduction, known-call discovery and reachability
consume this one analysis. The summary does not execute effects, reorder strict
initializers, invent a value for an open or recursive cycle, or become a second
IR.

## Acceptance Criteria
- [ ] `CoreAnalysis` is the sole producer of static top-level value summaries.
- [ ] Closed pure aliases and binding spines expose constructor and literal
      summaries; effectful, open and cyclic values remain unknown.
- [ ] Existing constructor-match reduction consumes summaries rather than
      inspecting top-level definition syntax.
- [ ] Public pipeline regressions cover observable reduction; focused white-box
      tests cover otherwise invisible fixed-point and cycle invariants.
- [ ] Native tests, examples and Basic preserve behavior.
