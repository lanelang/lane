## Description
The Wasm compiler owns the true order of imports, bytecode bodies, runtime
adapters, runtime functions, helpers, shape destructors, and the entry wrapper,
but currently returns only a Module. Explore would otherwise need to duplicate
offset formulas to connect Wasm indices with bytecode functions.

## Design
Add a compile observation product that records each Wasm function at the point
where the compiler emits or imports it. Bytecode-backed functions reference the
actual FunctionId; compiler-generated functions carry a closed synthetic role.
The ordinary compile API consumes the same implementation and discards only the
observation, ensuring generated Wasm remains identical.

## Acceptance Criteria
- [x] Every Wasm function index has exactly one typed provenance record.
- [x] Bytecode bodies and runtime-import adapters reference their FunctionId.
- [x] Imports, runtime helpers, shape helpers, and entry wrapper have explicit
      synthetic roles.
- [x] Provenance uses actual emission order rather than reconstructed offsets.
- [x] Observed and ordinary compilation produce equal Wasm modules.

## Close Notes
- `compile_observed` returns the unchanged Wasm module plus complete emission
  provenance; `compile` delegates to it and discards only the observation.
- A black-box regression covers every emission category, a shape destructor,
  actual index order, and ordinary/observed module equivalence.
- Verified with `moon test --target native` (1634 tests).
