## Description
LoisVM Bytecode is persisted and decoded across a trust boundary, but decoding
only validates selected function-body metadata. Instructions, slot identities,
runtime representations, initialization/dataflow, ownership, and call shapes
remain trusted. The new float-to-string instructions extend that unverified
surface.

## Design
Define a package-owned bytecode verifier that validates the complete decoded
`BytecodeImage` before it is returned to consumers. It must check referential
integrity and instruction contracts using the image's layout, function, block,
slot, constant, and import metadata. Decoder structure checks remain decoder
responsibility; semantic bytecode validity has exactly one verifier owner.
An object projection may consume only exact shape provenance already established
by construction, static metadata, ownership transfer, checked unerasure, or a
tag-switch case. A projection never refines its source from the shape it expects
and has no backend shape guard. When erased flow carries no exact provenance,
`UneraseI32` validates the exact object shape uniquely determined by its
destination semantic kind before the verifier treats that shape as proven.
Otherwise unknown exact shape at a projection is rejected.

## Acceptance Criteria
- [x] Every persisted Bytecode instruction has a verifier rule for identities and runtime representations.
- [x] Function/block/slot/control-flow references and statically known callable signatures are checked.
- [x] Invalid decoded and directly constructed images return structured errors rather than reaching interpreter or Wasm lowering.
- [x] Black-box tests cover representation, dataflow, ownership, direct-call, CFG, global, and decoder boundaries; private codec symmetry covers every instruction constructor.
- [x] Valid compiler-produced images still round-trip and pass interpreter/JIT gates.
- [x] LoisVM context documentation defines verified bytecode and the dynamic indirect-target boundary.
- [x] Semantic value-kind documentation matches the current bytecode model and
      no longer describes the removed abstract-reference category as crossing
      the persistent boundary.
- [x] Tag loading validates Data-family membership, and its `SwitchTag` case
      establishes exact constructor shape. Field, capture, and witness
      projections require exact shape proof established before the projection.
- [x] Exact shape proof survives ownership and erasure transfers, while CFG
      joins with different shapes return to unknown provenance.
- [x] Unknown exact shape is rejected at projection sites; neither the verifier,
      interpreter, nor Wasm lowering invents an implicit shape refinement.
- [x] Decoder semantic actions only decode framing and tagged fields; directly constructed and decoded images use the same verifier-owned Char, UTF-8, runtime-symbol, and metadata rules.
- [x] Direct and indirect callable ABI checks reject incompatible concrete value
      shapes consistently without admitting cross-category casts.
- [x] Erase/Unerase transfers a compatible proven source `ObjectShapeId`.
      Without source proof, only checked `UneraseI32` may establish the exact
      shape uniquely determined by destination metadata; a non-unique
      destination remains unknown.
- [x] A `LayoutOperand::Witness` used to construct an object is proven to
      describe that instruction's `ObjectShapeId`; a mismatched dynamic layout
      is rejected before either production backend can allocate the object.
- [x] Closure evidence agrees with the current ABI and schema owners instead of
      restating removed abstract-reference compatibility or an obsolete schema
      version as current behavior.

## Notes
- 2026-08-05: Created after float formatting instructions exposed the pre-existing persistent-IR verification gap.
- 2026-08-05: Static verification checks direct target signatures. An indirect
  call's physical call-site shape is static, but compatibility with its
  dynamically selected target and target-dependent global reads remain runtime
  checks.
- 2026-08-05: Reopened after review demonstrated that `I32 + Trivial` still
  passed every reference operand check and that direct image construction
  bypassed Char and runtime-import symbol invariants.
- 2026-08-08: Reopened after review demonstrated two remaining directly
  constructible invalid images: Unerase can replace source shape provenance
  with destination metadata, and object construction accepts any `LayoutValue`
  witness without tying it to the declared object shape. The context glossary
  also still names the removed abstract-reference boundary category.
- 2026-08-08: Closed after verifier dataflow began tracking layout-recipe and
  erased object-shape provenance. Exact projections now have matching
  interpreter and Wasm runtime shape guards when erased flow cannot prove a
  constructor statically, and every compiler-owned object shape interns its
  canonical layout at the same boundary.
- 2026-08-09: Reopened after root-cause review found that
  `establish_exact_object_shape` turns unknown provenance into `Some(expected)`
  after checking only family compatibility and canonical-layout availability.
  The actual shape check is then reconstructed independently by the interpreter
  and Wasm backend. This does not satisfy the verifier-owned proof criterion and
  lets three sites share responsibility for one refinement fact. The previous
  close notes also describe removed abstract-reference compatibility and schema
  11 as current even though the linked-program schema is 12.
- 2026-08-10: The implementation direction was narrowed after design review.
  Ordinary enum dispatch already obtains exact constructor proof from
  `LoadTag` plus `SwitchTag`; no production requirement for a separate trapping
  shape-cast operation has been established. Projections will therefore reject
  unknown exact shape instead of adding a new opcode or artifact schema.
- 2026-08-10: Strict projection verification exposed a legitimate higher-kinded
  boundary where a callable returns an erased object without exact provenance.
  The existing `UneraseI32` operation now owns the required dynamic validation:
  it checks a uniquely known destination shape before establishing proof.
  Projection guards were removed from both production backends.

## Close Notes
Closed after exact object-shape provenance became a verifier-owned dataflow
fact. Unknown projections are rejected, tag-switch cases refine Data values,
different CFG shapes join to unknown, and checked unerasure is the only dynamic
operation that can recover a uniquely determined exact shape from an erased
reference. Direct interpreter, Wasm interpreter, and Wasm JIT tests cover the
unerasure trap, and the full native and integration gates pass.
