# ISS-318: Match higher-kinded templates against what a bound parameter denotes

## Description
Generic argument inference matches templates against actual types structurally
without reducing either, and it decomposes an application whose head is a
parameter it is still solving for. Both fail when a higher-kinded parameter is
instantiated with a type alias, because an alias expands to a type lambda.

Given `Wrapper[F : [Type] -> Type] { held : F[I64] }` and
`type MyBox[A] = Box[A]`, checking `Wrapper::{ held: Box::{ value: 5 } }`
against `Wrapper[MyBox]` collects two bindings for `F`:

- from the expected type, `F := type [A] => Box[A]`;
- from the field, by reading `F[I64] = Box[I64]` as `F = Box`.

Reading an application headed by an unknown as a solution for that unknown is
higher-order matching, which has several solutions and which this language
does not do. The two bindings then conflict, reported at the field expression.

## Reproduction
Measured end to end through `lane run`:

```lane
pub struct Box[A] { value : A }
pub struct Wrapper[F : [Type] -> Type] { held : F[I64] }
pub type MyBox[A] = Box[A]
pub let wrapped : Wrapper[MyBox] = Wrapper::{ held: Box::{ value: 5 } }
```

```text
error[E3006]: type mismatch
   |            expected `type [A : Type] => Box[A]`, found `Box`
```

The same shape through an enum variant fails identically, and the reordering
alias `type Swap[A, B] = Pair[B, A]` — which is not an eta-redex — fails too,
which is the case that tells the two candidate explanations apart.

## Design
Two rules, both in the inference engine:

- An application headed by a parameter already bound to a type lambda is
  matched against what it denotes: substitute the binding, reduce, and match
  that. The parameter is never re-derived from the application's shape. Only a
  type-lambda binding qualifies; any other leaves the head a parameter after
  substitution, so reducing would not make progress and would not terminate.
- Both sides are reduced before the structural match, once at the entry to
  collection rather than per level, and only at the head. The match recurses
  and each level reduces its own head, so full normalization would renormalize
  every subtree, and substitution can duplicate them.

Eta is not part of this. The language's equational theory is beta only, and
that stays.

## Close Notes
`GenericArgumentInference::collect` reduces both sides at its entry and
delegates to `collect_normalized`, which every recursive step uses, so a type
is head-reduced once per level rather than fully normalized per level.
`Type::try_head_normalize` in `modules/lanec/types/core.mbt` performs that
head reduction. `collect_normalized` matches an application headed by a
parameter bound to a type lambda against the reduced template instead of
decomposing it.

Three wrong turns, all caught by measurement rather than review:

- The first diagnosis was that instantiation sites fail to normalize after
  substituting. The refactor that gave substitute-and-normalize one owner did
  not fix the reproduction, because `Type::equals` normalizes both sides
  already, so a residual redex is not observable through it. Reverted.
- The second was eta: `type MyBox[A] = Box[A]` is the eta-expansion of `Box`,
  and adding eta to the normal form did fix that reproduction and the whole
  suite. It was shipped and then reverted, because the language is beta-only
  by design and extending its equational theory is not a bug fix. The
  discriminating experiment is `type Swap[A, B] = Pair[B, A]`, which is not an
  eta-redex and fails for the same reason — so eta was never the cause, only a
  rule that happened to cover the aliases whose bodies are eta-expansions.
- Reducing on every collect level, and reducing whenever the head parameter
  had any binding, each made `examples/valid/54_recursion_schemes.lane` run
  past 240s where it takes about a second. The first renormalizes every
  subtree; the second does not terminate, because a parameter may be bound to
  itself and substitution then leaves the template unchanged.

Effect aliases need nothing: effects have no lambda form, so a parameterized
effect alias applies its parameter as a row member rather than as a
constructor application. `type MyAsk = { Ask }` and
`type Row[E : Effect] = { Ask, E }` both check.

Regressions: `modules/lanec/compile/higher_kinded_alias_test.mbt` locks the
struct, enum, reordering-alias, and already-working explicit-application
cases, with red/green measured before the fix (struct false, enum false,
explicit true); `examples/valid/91_higher_kinded_alias_instantiation.lane`
covers the struct and enum through `lane run`.

Verified: `moon check --target native --warn-list +73` clean; `moon test
--target native` 1463/1463; examples gate exit 0 in 1m49s against the pinned
fixture, with example 54 back to its normal runtime.
