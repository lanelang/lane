## Description
Implement the globally available pure generic `Array[T]` value described by
`modules/lanec/docs/array-rfc.md`.

The RFC defines the source type constructor, closed polymorphic compiler
intrinsics, representation erasure, runtime object layout, ownership, pure
copy-on-write updates, Basic wrappers, and source-to-Wasm validation contract.

## Design
Treat the accepted RFC as the authoritative design contract. Its 2026-08-28
review aligns the implementation with the Wasm-only pipeline: source and
Buslane own the compiler-built-in type constructor, Runtime ANF owns the closed
runtime Array/evidence projection, the verified Physical Program owns operation
and ownership contracts, and Wasm is the sole runtime implementation.

When resumed, split the work into dependency-ordered child issues following
the RFC implementation sequence. Preserve its central invariants: one
compiler-owned Array type-constructor identity, one authoritative runtime
element-layout source per operation, ordinary first-class generic builtin
behavior, no source-type-based layout guessing, no runtime reflection, and no
Array extension to the host ABI.

## Acceptance Criteria
- [x] The Array RFC is re-reviewed and accepted before implementation begins.
- [x] Dependency-ordered child issues cover the semantic type, intrinsic and
      artifact pipeline, Runtime ANF, Physical Program, Wasm implementation,
      Basic interface, tooling, and examples.
- [ ] `Array[T]` satisfies the RFC's ownership, bounds, pure alias, malformed
      bytecode, and interpreter/Wasm parity requirements.
- [ ] The complete RFC acceptance criteria and `moon test --target native`
      pass before this epic is closed.

## Notes
- 2026-08-02: Created as a deferred pointer to the reviewed Array RFC. No
  implementation is currently planned; move this issue to `open` only after an
  explicit reprioritization and RFC re-review.
- 2026-08-28: Re-reviewed and activated. The design remains representation-
  erased and non-reflective, but now names Runtime ANF, Verified Physical
  Program, raw Wasm, and Wasmoon interpreter/JIT as the actual owning seams.
  Split into ISS-415 through ISS-419.
- 2026-08-29: The implementation was reviewed as a whole and withdrawn. The
  compiler-wide invariant and runtime surface was disproportionate to an
  optional collection policy with no indispensable current consumer. ISS-420
  removes the implementation and deprecates the RFC.
