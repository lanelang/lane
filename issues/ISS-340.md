## Description
`Basic.Io` needs an intentionally fatal operation. Fatal panic is distinct from
a recoverable `Result`, a handled Lane effect, and an accidental host failure.
It must remain observable in statement position, terminate identically on both
production backends, and not require every embedding to register a magic host
symbol.

The earlier implementation used Basic's nominal empty `Void` as the source
result and derived an execution `Never` ABI from empty enums. That conflated
data inhabitation with control behavior and rejected ordinary legal functions
such as `identity(value : Void) -> Void { value }`.

## Design
Expose one closed compiler intrinsic with the canonical source type:

```lane
pub let panic : (String) -> Unit ! Panic = builtin("%panic")
```

`Unit` is the ordinary source and callable result. The compiler-provided,
non-algebraic `Panic` effect owns source-level observability without claiming
that fatal control performs I/O. The compiler-owned wrapper's `Fatal(message)`
terminator owns the lack of a normal successor and produces
`ExecutionError::Fatal(message)`.

Do not introduce bottom typing, a source or execution `Never`, empty-enum
control inference, no-return call opcodes, contextual panic elaboration, or a
public Runtime Import. `Panic` has no operations, handler, or dictionary and is
not a generic replacement for `Io`. User-defined empty enums remain ordinary
nominal data. Recoverable failure remains ordinary `Result` or
algebraic-effect design and is out of scope.

## Acceptance Criteria
- [x] The fatal-control RFC defines `panic : (String) -> Unit ! Panic` as a compiler intrinsic.
- [x] `Panic` is a compiler-provided non-algebraic effect distinct from `Io`, with no operation, handler, or dictionary.
- [x] Source type, effect observability, and execution termination have distinct owners.
- [x] Direct and first-class panic calls use the ordinary Unit callable ABI.
- [x] The compiler-owned wrapper ends in verified `Fatal(message)` and creates no Runtime Import.
- [x] No source or execution `Never`, no-return call form, or empty-enum control inference remains.
- [x] Interpreter and Wasm executions terminate with the same structured fatal outcome and do not continue after panic.
- [x] Fatal unwinding and owned-value cleanup are covered at both production backend boundaries.
- [x] Wrong builtin annotations use the ordinary canonical-signature diagnostic.
- [x] Panic in discarded statement position remains observable.
- [x] Recoverable host failures remain outside this issue and no second implicit failure channel is introduced.
- [x] The pinned Basic revision exports `panic : (String) -> Unit ! Panic = builtin("%panic")`.
- [x] A black-box Lane command regression invokes shipped `Basic.Io.panic` and proves that execution does not continue.
- [x] `moon info`, `moon fmt`, `moon test --target native`, and the integration gate pass.
