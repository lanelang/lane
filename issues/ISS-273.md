## Description
The repository contains substantial native tests and a project-specific example
smoke script but has no checked-in CI configuration. Warning, formatting,
testing, example, artifact, and coverage regressions therefore depend on
developers running the complete local gate set manually.

## Design
Add a minimal GitHub Actions workflow for the repository's supported native
compiler path. Run strict warning checks, formatting, the full native suite,
the repository integration gate, and a coverage report. The integration gate
is the public repository-level command: it builds `lane.exe` once and passes
that exact executable to the examples and LSP CLI checkers. Record a checked-in
coverage baseline for lanec and critical boundary packages and fail on
unexplained regression rather than chasing a global 100% target.

For pull requests, whitespace validation must inspect the base-to-head range;
bare `git diff --check` on a clean CI checkout is not a meaningful gate.

## Acceptance Criteria
- [ ] Pull requests and main-branch pushes run `moon check --target native --warn-list +73`.
- [ ] CI runs `moon fmt --check`, `moon test --target native`, and `tools/check-lane-integration.sh`.
- [ ] Pull-request whitespace validation checks the merge-base/base-to-head range.
- [ ] CI generates package-level coverage for lanec, compile, artifact, module compile, module link, typecheck, and analysis.
- [ ] A documented baseline prevents silent coverage regression while allowing intentional reviewed updates.
- [ ] Toolchain and dependency setup is reproducible from a clean checkout.
- [ ] Workflow documentation explains which local commands reproduce every CI job.
