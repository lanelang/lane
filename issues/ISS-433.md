# ISS-433: Make contextual constructor inference linear in payload depth

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: typecheck, inference, performance, list, agent
- Assignee: unassigned
- Created: 2026-09-02
- Updated: 2026-09-02
- External ref: modules/lanec/typecheck/generic_arguments.mbt

## Description
A List literal resolves to right-nested `List::cons` variant applications.
Generic argument inference previously synthesized every payload before
collecting result evidence, then ordinary variant checking checked every
payload again. At each `cons`, synthesizing the tail repeated the same work for
the complete remaining list.

The resulting typechecking cost was approximately exponential in literal
length. A release `lane explore` took about 0.06 seconds for eight items, 0.41
seconds for sixteen, 5.8 seconds for twenty, and did not finish a 24-item case
within thirty seconds. Sampling showed the repeated stack in
`infer_variant_owner_generic_arguments` and
`try_synthesize_checked_expr_type_silently`, before Core optimization or Wasm
lowering began.

## Design
For construction sites whose generic inference is explicitly
`collect_result_first`, collect contextual result evidence before payload
evidence. Once every generic parameter has an exact binding, stop asking later
payloads to reproduce owner-type evidence. The ordinary checking judgment then
checks every payload exactly once against the instantiated payload type.

Keep ordinary generic callable inference unchanged: it continues collecting
all argument evidence so diagnostics such as `choose(1, true)` retain the fact
that two call arguments inferred conflicting types. Do not special-case List,
memoize mutable checker state, impose a nesting limit, or add a work budget.

## Acceptance Criteria
- [x] A 128-item List literal passed through an ordinary generic function
      typechecks through the public compile facade.
- [x] The same test rejects a heterogeneous later element after the List owner
      type has already been fixed.
- [x] Existing callable generic-conflict diagnostics remain unchanged.
- [x] Typechecking work for nested contextual variants grows linearly rather
      than by recursively re-synthesizing every tail.
- [x] The original 20-, 64-, and 128-item Explore reproductions complete and
      the 128-item program executes its final element.

## Notes
- 2026-09-02: Initial suspicion focused on recursive Core inlining, but native
  process sampling placed all active time in source typechecking. Core was not

## Close Notes

- 2026-09-02: Constructor-owner inference now gathers payload evidence lazily
  and stops after result-first inference has exact bindings. Remaining payloads
  are still checked normally. Release Explore measurements are approximately
  0.07 seconds for 20 items, 0.07 seconds for 64, and 0.13 seconds for 128.
- Added public compile-facade regressions for a 128-item generic List and a
  heterogeneous tail. All 250 typecheck tests and 268 compile tests pass.
