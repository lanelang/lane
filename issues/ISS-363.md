## Description
The canonical generic ABI correctly carries CPS callables through erased answer
and higher-kinded companion boundaries, but closed paths may retain avoidable
callable wrappers and erase/unerase operations. Optimizing those paths requires
following callable identity and closed ABI facts through parameters, results,
captures, aggregates, recursion, and immutable globals.

The previous implementation made a persistent Callable Instance Plan and
whole-program representation solution prerequisites for lowering. That design
is superseded by ADR-0138 and must not be restored.

## Design
This issue is an optional program optimization after ISS-390 establishes
independently correct generic lowering.

Use exact callable-flow facts to discover closed calls. For each closed
`(generic definition, canonical runtime ABI)` key, create at most one concrete
worker and rewrite actual definitions and calls. The work queue, substitutions,
and SCC analysis remain private to the specialization pass.

Open, indirect, incompatible, unsupported, or recursively expanding uses stay
generic. Recursive calls may reuse a stable existing key; no global proof is
required to lower the generic program. Higher-kinded companions keep explicit
layout-constructor evidence unless a complete closed worker removes the
corresponding generic boundary.

Do not specialize nominal storage families. Values crossing generic nominal
storage keep its declaration-owned erased schema. Closed non-escaping
aggregates may be scalar-replaced by a separate local rewrite.

VM CFG callable-flow retains its physical responsibility: devirtualize closed
callable values and remove environments when the final whole-image fact proves
the ABI rewrite coherent. It does not discover representation workers.

## Acceptance Criteria
- [ ] With specialization disabled, every regression in this issue still
      compiles and observes the same result through the Canonical Generic ABI.
- [ ] A minimal closed-answer CPS callback removes its avoidable callable
      adaptation and erase/unerase operations when specialization is enabled.
- [ ] Callable flow crosses aliases, parameters/results, captures, constructor
      fields, and recursive continuation paths.
- [ ] One closed canonical ABI key produces at most one worker; open and
      incompatible uses retain the generic implementation.
- [ ] Stable recursive keys may reuse a worker; expanding key sequences remain
      generic without blocking lowering.
- [ ] The pass rewrites program definitions and calls and exposes no
      callable-instance plan or representation-demand model to lowering.
- [ ] Generic nominal storage remains declaration-owned and uniform.
- [ ] The Coroutine Scheduler prints `1112211322` under JIT and `--no-jit`.
- [ ] Explore records worker, adapter, bridge, indirect-call, function, and
      instruction changes without using a profitability metric as semantics.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      `moon test --target native`, and the valid examples gate pass.

## Notes
- 2026-08-12: Opened after exact adapter equivalence reduced example 37 but
  left CPS answer erased/concrete boundaries.
- 2026-08-18: Several planner-based experiments demonstrated that allocation
  identity cannot justify changing generic nominal storage and that partial
  producer/consumer specialization is unsound.
- 2026-08-25: The issue was closed after a whole-program callable-instance and
  physical-contract architecture passed local gates. That closure is revoked:
  the implementation made specialization necessary for correctness and created
  parallel program models.
- 2026-08-26: Reopened under ADR-0138. The earlier measurements remain useful
  baselines, but no planner or catalog from that implementation is normative.
