## Description
ISS-363 briefly used one exact Runtime ANF allocation site and closed runtime
arguments to specialize generic data storage. The resulting object shape was
still interned under the declaration's `DataFamilyId`. Multiple instantiations
could therefore emit different shapes for the same family and constructor tag,
causing duplicate-tag verifier failures, callable ABI mismatches, and runtime
traps. Allocation identity proves value flow; it does not create a nominal
representation identity.

The unsafe optimization has been removed. Generic constructors and matches once
again use their declaration-owned uniform erased ABI, leaving some CPS callable
adapters and erase/unerase bridges in otherwise closed paths.

## Design
If generic data storage is specialized, introduce an explicit lowerer-owned
representation family before object-shape interning. A family must cover the
complete constructor set and every construction, match, destruction, and
callable boundary that can carry its values. Its canonical key must preserve
the semantic runtime type expressions and evidence needed by nested payloads;
an outer `Reference` layout is insufficient.

The callable-instance plan remains the sole demand producer, but may only select
a specialized family whose complete closed use graph is proven. Open,
existential, or incompatible uses retain the declaration family, and the generic
implementation remains available. Do not reuse a declaration `DataFamilyId`,
guess identity from object shape, or choose storage while emitting bodies.

This is not required to complete ISS-363. Closed generated aggregates should be
scalar-replaced without changing their nominal storage ABI. Resume this issue
only when a concrete workload requires retained, escaping values to use multiple
physical representations.

## Acceptance Criteria
- [ ] Specialized and declaration-owned data families have distinct explicit identities before VM CFG emission.
- [ ] One family identity owns exactly one complete constructor-tag and object-shape contract.
- [ ] Constructor, match, destruction, callable adaptation, and bytecode verification consume the same family identity.
- [ ] Nested runtime type expressions and higher-kinded evidence remain available when payload operations require them.
- [ ] Open, existential, recursive-expanding, and multi-ABI uses retain the uniform declaration family.
- [ ] Black-box regressions cover generic fallback plus specialized use, phantom higher-kinded constructors, and structural derivation over nested generic data.
- [ ] Explore demonstrates the intended adapter and bridge reduction without duplicate shapes, runtime traps, or code-size regression.
- [ ] All valid examples pass under JIT and `--no-jit`.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and `moon test --target native` pass.
