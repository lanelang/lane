## Description
Introduce the single compiler-owned source identity for `Array : [Type] ->
Type` and make the intrinsic ABI capable of expressing closed polymorphic type
schemes.

## Design
Add a built-in type-constructor identity distinct from scalar primitives and
nominal declarations. Preserve it through source types, Buslane, interfaces,
module objects, fingerprints, normalization, substitution, kind checking, and
presentation. Extend the closed intrinsic contract with bound Type parameters
and constructor application; existing monomorphic intrinsics are the zero-
parameter subset. Typechecking materializes ordinary `Forall` types and uses
the existing directional compatibility relation.

Do not recognize a Basic declaration by name, encode Array as a fake nominal
symbol, or add Array-specific expected-type inference.

## Acceptance Criteria
- [x] `Array` resolves without imports and has kind `[Type] -> Type`.
- [x] Partial and ill-kinded applications use ordinary kind diagnostics.
- [x] Source types, Buslane, interfaces, module objects, fingerprints, codecs,
      pretty output, normalization, and substitution preserve `Array[T]`.
- [x] The five Array intrinsics synthesize the RFC's canonical `Forall` schemes.
- [x] Alpha-renamed compatible annotations succeed and incompatible schemes
      produce the existing builtin-signature diagnostic.
- [x] Existing monomorphic intrinsic behavior and native tests remain green.
