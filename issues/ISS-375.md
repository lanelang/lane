## Description
Batch module compilation and Semantic Workspace independently implement Source
Elaboration. Both invoke resolution, type checking, diagnostic conversion,
linting, Module Interface construction, and exported-symbol projection. The
workspace additionally reuses declaration identities and retains partial state,
while batch compilation orders successful declarations and computes persistent
fingerprints. Those policy differences do not justify two producers for the
shared semantic result.

## Design
Create one deep Source Elaboration Module accepting a parsed module, import
environments, symbol registry, and optional previous declaration identities.
Return a structured outcome whose variants make partial states explicit:
resolution failure, typecheck failure, success, or structured compiler defect.

A successful Source Elaboration owns the resolved source, source-order checked
source, certified Module Interface, exported symbol metadata, and warnings.
The batch adapter requires success, computes initialization order and persistent
fingerprints, then lowers the module. The workspace adapter caches partial
results, builds the Semantic Index, and retains the last successful interface.
Neither adapter may invoke resolve/typecheck or reproduce their diagnostic
policy independently.

## Acceptance Criteria
- [x] Batch compilation and Semantic Workspace call the same Source Elaboration
      operation for resolve, typecheck, lint, interface, and exported symbols.
- [x] The result type cannot represent a checked source without its matching
      resolved source and certified Module Interface.
- [x] Stable declaration-identity reuse is an explicit input to the shared
      operation rather than a separate workspace elaborator.
- [x] Batch-only initialization ordering/fingerprinting and workspace-only
      caching/indexing remain adapters over the shared result.
- [x] Typecheck invalid-input failures preserve a structured compiler-defect
      cause and are rendered by one source-elaboration diagnostic owner.
- [x] Black-box compile and Semantic Workspace parity tests cover success,
      resolve errors, type errors, warnings, imported interfaces, and identity
      reuse.
- [x] The duplicate resolve/typecheck/lint implementations are deleted.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
