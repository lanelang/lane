# ISS-430: Make the WebAssembly host contract truthful

## Description
The target RFC says WASI Preview 1 is the operating-system host seam and rejects
a second Lane host ABI. Generated modules nevertheless import deterministic
float formatting and fatal control from `lane.runtime.internal.v1`. They also
export named runtime-control globals that the Lane runtime resolves and mutates.

An import or export consumed by another component is an artifact ABI regardless
of whether documentation calls it compiler-private. The current architecture
therefore simultaneously claims a standard WASI command module and requires a
Lane-Wasmoon execution contract.

## Design
Make one explicit compatibility decision and apply it across compiler, runtime,
tests, and documentation:

1. For a genuinely WASI-only host seam, move deterministic float formatting and
   fatal control into guest Wasm/runtime helpers, and replace named control
   exports with standard engine resource controls or ordinary guest semantics.
2. If Wasmoon-specific runtime cooperation is intentional, define and version a
   first-class Lane Wasm Runtime ABI and stop describing the artifact as needing
   only a compatible WASI Preview 1 host.

The implemented WASI target RFC currently selects the first option, so that is
the default unless an explicit superseding decision is recorded. Do not retain
both interpretations or add host fallback discovery.

## Acceptance Criteria
- [x] One document owns the complete required import/export contract of a Lane
      executable Wasm artifact.
- [x] Compiler emission, runtime loading, and compatibility tests consume that
      exact contract without separately naming hidden runtime services.
- [x] If WASI-only remains the decision, generated programs that format floats
      or panic have no `lane.runtime.*` imports and preserve deterministic Lane
      behavior.
- [x] Every runtime-consumed named export is either removed or explicitly
      documented and versioned as public artifact ABI.
- [x] Black-box tests inspect the complete import/export set and execute the
      representative artifacts with only the chosen host contract.
- [x] Target RFC, runtime glossary, and release qualification agree with the
      implemented contract.

## Close Notes
- 2026-08-31: Removed the private `lane.runtime.internal.v1` function imports,
  runtime-control globals, runtime ABI package, and host-side float/fatal
  adapters. `%f32_to_string` and `%f64_to_string` now select statically linked,
  reachable Ryū-derived guest Wasm functions. Panic writes its message through
  canonical WASI `fd_write` and terminates through `proc_exit(1)`.
- 2026-08-31: Replaced the runtime's fatal error channel with
  `ExecutionOutcome::Returned | ProcessExit(code)`. The Lane command is the
  sole owner of mapping a process exit status to the host process status.
  Interpreter and JIT tests distinguish normal return, `proc_exit(0)`, and
  nonzero process exit.
- 2026-08-31: Verified `moon check` for native, wasm, wasm-gc, and js; 1739/1739
  native tests; the release Lane build; all 12 pinned Basic checks; and the
  complete valid/invalid examples gate.
