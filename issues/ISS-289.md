# ISS-289: Report an unusable core-optimizer input instead of aborting

## Description
`expression_has_empty_effect` aborts the process when the facts query cannot
synthesize an expression:

```moonbit
Err(_) => abort("core optimizer requires a verified Buslane expression")
```

The user sees a crash with no file, no expression, and no reason. The reason is
discarded before the message is built, so even a developer has to patch the
compiler to learn what failed — which is what this issue was found by doing.

The path is reachable. Effect lowering is not yet verified on its output
(ISS-284), so the optimizer can be handed a program that does not typecheck, and
this is where it notices.

## Design
Return a `CoreOptimizeError` carrying the underlying failure and let the driver
render it, the way `CoreOptimizationError` already reaches the user. The
optimizer has an error type and a `Result` boundary already; this case is the
only one that bypasses them.

## Acceptance Criteria
- [ ] An unsynthesizable expression produces a compiler diagnostic naming the
      underlying failure, not an abort.
- [ ] A test covers it.
- [ ] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.
