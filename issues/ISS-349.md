# ISS-349: Remove the hard-coded host-object release import index

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: area/loisvm, area/wasm, callable-abi, host-objects, compiler-defect, tests, agent
- Assignee: codex
- Created: 2026-08-08
- Updated: 2026-08-10
- External ref: modules/loisvm/wasm/compiler/compile.mbt, modules/loisvm/wasm/compiler/runtime_imports.mbt

## Description
The Wasm host-object destructor called internal import index zero regardless of
which internal imports preceded `host_object.release`. A program using float
formatting and an Opaque runtime import therefore generated a destructor that
passed an I64 token to `f32_to_string:(f32)->i32`; Wasm validation rejected the
compiler-produced module.

## Design
Make internal runtime import planning assign and retain the index of every
selected helper. Helper generation consumes the planned host-object release
index directly. Absence is represented explicitly when host objects are not in
the image; there is no positional default or fallback index.
Represent the plan as ordered entries carrying internal-function identity and
assigned index. Import emission, count and offset calculation, instruction
lowering, and helper generation all consume those entries; no second branch
order may reconstruct physical import positions from presence flags.

## Acceptance Criteria
- [x] `host_object.release` has an explicit planned import index.
- [x] Host-object destruction consumes that index rather than a constant.
- [x] Import emission iterates the ordered plan entries and does not reconstruct
      physical import order from a separate sequence of optional fields.
- [x] Float formatting and Opaque runtime imports compile together in one image.
- [x] The compiler-produced module passes complete Wasm validation.
- [x] `moon info`, `moon fmt`, `moon test --target native`, and `git diff --check` pass.

## Notes
- 2026-08-08: The ISS-347 complete internal-import regression exposed the
  invalid call while combining both float formatters with an Opaque import.
- 2026-08-09: Reopened because index assignment and import emission still have
  separate hard-coded orders. `internal_runtime_imports` assigns indices through
  one sequence of branches, while `append_internal_runtime_imports` reads only
  presence and emits through another sequence. The constant-zero symptom is
  gone, but adding or reordering a helper can recreate the same index drift.
  One ordered import plan must own selection, order, indices, and emission.
- 2026-08-10: Refactoring resumed. The compiler plan will retain ordered
  `(function, index)` entries filtered from the package-owned internal ABI table;
  all physical-index consumers and import emission will read that plan.

## Close Notes

`InternalRuntimeImportPlan.entries` is now the only selected-helper order. The
planner filters `@internal_abi.functions()` and records each selected function
with its assigned physical index. Import emission iterates those entries;
instruction lowering and host-object destruction look up indices by function
identity; internal import count and public runtime-import offsets derive from
the same entry array. The former optional position fields, stored count, and
second emission branch order were deleted.

One black-box regression compiles all eight combinations of F32 formatting, F64
formatting, and host-object support. It observes the complete ordered internal
import names and signatures through the public Wasm module, including empty,
host-only, skipped-middle, and complete plans. Public compilation performs full
Wasm validation. `moon info`, `moon fmt`, all 1601 native tests, the integration
gate, and `git diff --check` pass.
