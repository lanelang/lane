## Description
The Ubuntu native quality gate fails `run executes schema 2 top-level
initialization`: `lane_run` returns a non-success outcome for a program with an
eager `String` binding that is read by the selected entry. The same test passes
on the current macOS development host.

The failure predates the deterministic-NaN change. Ubuntu runs 31158793383 and
31358677214 both report it, while the latter proves the independent F32 NaN
snapshot defect is fixed. The current assertion discards the actual
`LaneCommandOutcome`, so CI does not identify whether compilation, executable
lowering, Wasm compilation, or execution failed.

## Design
First preserve the complete command outcome in the regression failure. Reproduce
the source through the built executable on Linux in both default and `--no-jit`
modes to locate the failing execution tier. Then trace the first owner boundary
that violates its contract and fix that owner; do not skip the test on Linux,
special-case `String`, or treat the Wasmoon backend as the root cause without
evidence.

Keep the schema-2 invariant at the public execution boundary: an eager top-level
initializer runs once before the entry, and its initialized value is readable
through both execution tiers.

## Acceptance Criteria
- [ ] The regression reports the complete non-success outcome instead of reducing it to a boolean assertion.
- [ ] A Linux reproduction distinguishes default Wasm execution from `--no-jit` interpretation.
- [ ] The root cause is assigned to and fixed at its owning compiler, bytecode, runtime, or backend boundary.
- [ ] The schema-2 eager `String` initializer succeeds through both execution tiers on Ubuntu.
- [ ] No platform skip, source-type special case, or fallback execution path is introduced.
- [ ] `moon info`, `moon fmt`, `moon test --target native`, and the integration gate pass on Ubuntu.
