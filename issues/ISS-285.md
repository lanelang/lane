# ISS-285: Stop nested function bindings from claiming closed metadata types

## Metadata
- Type: bug
- Status: closed

- Assignee: unassigned
- Created: 2026-07-31
- Updated: 2026-07-31

## Description
A function literal written inside a generic function produces a linked program
that does not verify. Every free type parameter of the enclosing generic is
reported as `UnknownTypeParameter`.

`examples/valid/63_nominal_tuple_sugar.lane` reproduces it with no effects
involved at all: 12 diagnostics, all naming the tuple type parameters `A`, `B`,
and `T`, all in metadata and none in scope.

`BuslaneLowerer::lower_function_literal_value` binds the literal with

```moonbit
let id = self.define_fresh_value("function_literal", Function, self.lower_type(type_))
```

`ValueKind::Function` is one of the kinds for which
`ValueKind::has_closed_metadata_type` returns true, so `verify_metadata` checks
the type in an empty type scope. The binding is a nested `LetRec`, not a
top-level function, and its type legitimately mentions the enclosing generic's
parameters.

`lower_function_effect_widen` binds `effect_adapter` the same way and has the
same defect.

Across `examples/valid` these two sites account for **401 of the 401**
`UnknownTypeParameter` diagnostics reported on the effect-lowering input.

## Design
Bind both as `Local`. They are nested `LetRec` bindings, and `Local` is the kind
for a binder whose type is scoped by its context rather than closed.

Nothing is lost in checking: `synthesize_letrec` already passes
`FunctionBinding` for every nested recursive binding regardless of value kind,
so the function-implementation check still applies. Only `verify_top_let` and
`verify_top_letrec` consult the kind, and neither reaches these bindings.

## Acceptance Criteria
- [x] `function_literal` and `effect_adapter` are bound as `Local`.
- [x] A program with a function literal inside a generic function verifies.
- [x] A regression test covers it at the lowering level.
- [x] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.

## Close Notes
Both bindings are `Local`. The kind is only consulted by `verify_top_let` and
`verify_top_letrec`, neither of which reaches a nested binding, so the
function-implementation check `synthesize_letrec` already applies is unchanged.

Measured over `examples/valid` with a temporary verification probe: on the
effect-lowering input, `UnknownTypeParameter` drops from 401 across 27 programs
to 0, and after monadic-lift from 420 to 19. The 19 that remain belong to
ISS-286.
