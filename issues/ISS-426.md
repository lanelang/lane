## Description
The fixed `ByteBuffer` guest-memory model replaces sealed `Bytes` frames,
relocations, standalone pointer materialization, and explicit lifetime markers.
The semantic and execution regressions pass, but the new boundary also adds a
layout and several Wasm runtime functions. Reachability and scale must be
measured after the migration so pure programs do not pay for guest memory and
I/O programs emit only the operations they actually use.

## Design
Use the existing Physical Program verifier, Wasm function catalog, and Explore
metrics as the only fact owners. Add structural regressions at those public or
verified boundaries: pure programs must not require `ByteBuffer` support;
guest-address calls must retain their structured buffer-and-offset operand;
and Wasm catalog construction must include only reachable buffer runtime
functions. Record representative pure, `println`, and mutable-buffer programs.

Do not add function-size, call-count, or score-based pruning. If support is
over-emitted, repair the deterministic dependency graph owned by Wasm function
requirements and catalog construction.

## Acceptance Criteria
- [x] A pure executable emits no `ByteBuffer` layout, runtime function, helper,
      or guest-address adapter.
- [x] `println` and an explicit buffer read/write program emit exactly the
      reachable guest-memory support and no unused buffer runtime functions.
- [x] Physical observations contain structured `GuestAddress(buffer, offset)`
      calls and no pointer temporary, relocation, or lifetime-marker operation.
- [x] Explore records stable Physical and Wasm scale for all representative
      programs, with unchanged interpreter and JIT behavior.
- [x] `moon info`, formatting, strict native check, native tests, Basic tests,
      examples, and CI pass.
