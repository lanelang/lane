## Description
`WasmFunctionCatalog` owns identities and ordering but still declares the full
runtime/helper role lists and every shape destructor before emission. This
forces JIT compilation of support that the final Physical Program may not
reference.

## Design
Make the catalog own a typed dependency graph among physical operations,
runtime roles, helper roles, shape support, lifecycle and exports. Starting
from entry, exports, reachable physical bodies/imports, callable-table entries,
global lifecycle, layouts and object shapes, compute the transitive closure
before allocating function indices or table slots. Emit the catalog once.

Do not emit all support and run semantic DCE afterward. Do not introduce a
second reachability/index map outside the catalog.

## Acceptance Criteria
- [ ] Runtime/helper/shape dependencies are typed and owned by the catalog.
- [ ] Function indices and table slots are allocated only after closure.
- [ ] Every emitted support role is transitively reachable from a declared root.
- [ ] Omitting any required dependency is rejected before Wasm body emission.
- [ ] Explore reports zero unreachable emitted support roles.
- [ ] Small scalar programs exclude byte-sequence, host-object and unrelated
      destructor support while exported runtime contracts remain intact.
- [ ] Native tests, Wasm validation, JIT/`--no-jit`, valid examples and Basic
      tests pass.
