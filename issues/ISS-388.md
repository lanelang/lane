# ISS-388: Give refined callables independent representation identities

## Description
`CallableRepresentationTarget::Refined` reuses its source
`CallableInstance.id`. Data-family, result, capture, port, and allocation facts
are indexed by that semantic instance ID, so a closed refined callable cannot
own representation facts distinct from its generic source instance.

A minimal generic handler constructs a `Monoid[I64]` whose callable field
returns a closed `WriteResult[Unit, I64]`. Callable flow correctly identifies a
refined target, but its worker result is planned from the source instance's
generic data family. Construction then tries to store that callable under the
refined field contract and lowering rejects the valid program with
`RepresentationSpecializationInvariant`: the source result uses one
`DataValue` family and the target result uses another.

Changing whether `Semantic` or `Refined` wins a local target-selection tie is
not a repair. It changes provenance while both targets still query the same
instance-indexed representation facts.

## Design
Make the representation solver key callable nodes by a stable, canonical
callable-target identity rather than by the source semantic instance integer.
A semantic instance and each distinct refined target may share one Runtime ANF
definition, but they must own separate substitution, port, result, capture,
allocation, data-family, and worker-demand facts.

Implement this in the Physical ANF representation graph introduced by
ISS-387. The graph should use canonical structural `Semantic` and `Refined`
target keys, attach the source definition as provenance only, and solve every
closed target's complete physical contract from its own flow component. Do not
allocate negative synthetic instance IDs, fall back to source-instance facts, choose a
family while emitting VM CFG, or add an adapter between unequal nominal data
families.

## Acceptance Criteria
- [x] A refined callable has a stable representation identity distinct from
      its source semantic instance while retaining explicit source-definition
      provenance.
- [x] Port, result, capture, allocation, data-family, and worker facts are
      indexed by the refined target identity and never retrieved through the
      source instance ID.
- [x] The minimized `run_write` program using `WriteResult[Unit, I64]` compiles
      and observes `42` under the interpreter, Wasm, and JIT backends.
- [x] A generic source callable and two closed refined targets can coexist with
      three independently verified physical contracts and one generic
      fallback.
- [x] No representation adapter is used to cross two distinct nominal
      `DataValue` family identities.
- [x] Existing higher-kinded storage, recursive companion forwarding, and
      complete examples regressions continue to pass.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      and `moon test --target native` pass.

## Notes
- 2026-08-24: Discovered while minimizing the representation regressions that
  escaped the Lane test corpus. Existing examples exercise the larger generic
  test framework, but not this closed refined callable result boundary.
- 2026-08-25: Physical callable allocations are now keyed by the structural
  `CallableRepresentationTarget`, not by the source function ID. A black-box
  backend-conformance regression runs the minimized `run_write` shape and
  observes `42` under the direct interpreter, Wasm interpreter, and Wasm JIT.
  The broader constraint-graph identity audit remains coupled to ISS-387.
- 2026-08-25: The new graph/solution seam keeps canonical callable targets as
  physical constraint identities instead of hiding them behind the semantic
  plan. Result, capture, and port projections that still accept semantic
  instance integers are the remaining reason this issue stays in progress.
- 2026-08-25: Physical ANF no longer treats source-function provenance as
  permission to reconstruct an existing callable reference with a selected
  worker. This fixes parser-combinator and structural-derivation regressions
  by preserving producer ABI and captures, but does not replace the remaining
  source-instance-indexed graph facts; the issue remains in progress.

## Close Notes
- 2026-08-25: Physical representation facts are keyed by
  `CallableRepresentationOwner::Callable(CallableRepresentationTarget)`.
  `Semantic` and canonical `Refined` targets retain source-definition
  provenance without sharing port, result, capture, allocation, data-family,
  scalar, or worker facts through the source instance integer.
- 2026-08-25: Backend-conformance tests observe the minimized closed
  `run_write` result and a generic callable with two independently refined
  `I64` and `Bool` contracts under the interpreter, Wasm interpreter, and Wasm
  JIT. Generic fallback and nominal family separation remain intact, and all
  repository gates pass.
