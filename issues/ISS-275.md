## Description
ADR-0115 defines Explore Protocol version 1 with compiler identity, root
identity, artifact-selected entry, overall status, stage domain, text format,
per-stage diagnostics, a fixed ordered set of eighteen stages, and explicit
unavailable status after failure. The current model has only
`id/title/text` stages and a report-level optional failure string. Failed
reports omit later stages.

Exploration also parses all supplied library sources and fails on diagnostics
from unused libraries, while normal compilation uses import-reachable source
semantics. The documented guarantee that exploration shares production
orchestration and failure semantics is therefore not met.

## Design
Implement a closed, versioned protocol model. Represent each fixed stage as
completed with a snapshot, failed with diagnostics, or unavailable. Snapshots
own stable identity, display label, compiler/backend domain, text format,
human-readable text, and diagnostics. Reports own compiler identity, root
identity, selected entry, overall status, diagnostics, and all eighteen stages.

Create one production compilation orchestration path with an optional read-only
observer. Normal compilation installs no observer; exploration renders observed
stage values. Use the same import-reachable input and failure semantics in both
workflows. Do not grow the current `failure : String?` record with ad-hoc fields.

## Acceptance Criteria
- [x] The protocol type contains compiler identity, root identity, selected entry, typed overall status, and exactly eighteen ordered stage states.
- [x] Completed snapshots contain domain, text format, text, and diagnostics.
- [x] Failed reports preserve completed stages, identify the failed stage, and mark every later stage unavailable.
- [x] Native and Wasm adapters serialize or render the same compiler-owned report semantics.
- [x] Normal compilation and exploration share import-reachable source selection and stage-owning orchestration.
- [x] An unused malformed library produces the same observable success/failure decision in compile and explore.
- [x] Black-box tests cover success plus parse, graph, resolve, typecheck, link, entry-selection, executable, LoisVM, and Wasm failure reports where constructible.
- [x] ADR-0115, context documentation, generated interfaces, native HTML, and Wasm JSON agree exactly.
- [x] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.

## Close Notes

- Closed on 2026-07-31 after replacing the ad-hoc stage array and optional failure string with a compiler-owned Explore Protocol v1 model containing typed report identity, status, and exactly eighteen ordered stage states.
- Production compilation now exposes read-only syntax, resolved, checked, and module-lowered observations from the same import-reachable orchestration used without an observer by ordinary compilation. Executable and LoisVM observations continue through their stage-owning production entrypoints.
- Native HTML and Wasm JSON consume the same `ExploreReport`; failed stages retain prior snapshots, carry diagnostics, and leave all later stages unavailable. Entry-selection failure is owned by the `buslane.linked` boundary.
- Black-box coverage includes all eighteen successful snapshots, parse, graph, resolver, typecheck, and entry-selection failures, unreachable malformed libraries, exact native HTML, and complete Wasm JSON. Later internal lowering failures have no stable malformed-source construction path and use the same typed first-unavailable failure boundary when raised.
