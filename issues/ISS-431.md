## Description
Optional representation specialization is currently decided while ordinary
calls and closures are being lowered. `ImageLowerer` owns candidate discovery,
worker contracts, mutable worker emission, active specialization ancestry, and
the final physical emitter. Ordinary call lowering can create a worker on
demand, while closure plans copy ambient ancestry to control recursive fallback.

This interleaves optimization planning, termination policy, worker identity, and
correctness lowering. Although generic fallback exists, the optional
optimization is not an independently removable planned transformation.

## Design
Keep one public Physical Lowering interface, but split its private execution
into deterministic stages:

1. derive canonical runtime representation and callable contracts;
2. build an immutable specialization demand graph keyed by semantic definition
   and complete canonical runtime ABI;
3. solve recursive SCCs, reusing finite keys and routing expanding edges to the
   canonical generic implementation;
4. materialize each planned worker once; and
5. emit generic and specialized physical code by lookup only.

The emitter must not discover candidates, create workers, mutate specialization
ancestry, or make fallback decisions. Removing the specialization plan and its
workers must leave the canonical generic compiler correct and observationally
equivalent. Do not use call counts, function sizes, scores, or fixed expansion
limits to decide semantic specialization.

## Acceptance Criteria
- [x] One immutable plan owns all representation-specialization demand, worker
      identity, recursive reuse, and generic fallback decisions.
- [x] Ordinary call, closure, and function emission only query the completed
      plan and cannot create new specialization work.
- [x] `active_specialization_ancestry` and the specialization enable flag are
      removed from `ImageLowerer` and closure plans.
- [x] Every canonical key materializes at most one worker; alpha-equivalent
      runtime arguments share the same key.
- [x] Recursive stable SCCs specialize finitely, while expanding recursive
      edges use the generic implementation without heuristic limits.
- [x] Black-box generic and higher-kinded examples have unchanged behavior with
      specialization present; focused white-box tests lock plan finiteness and
      worker uniqueness.
- [x] Explore records worker, adapter, erase/unerase, Physical, and Wasm scale
      before and after the refactor.

## Close Notes

- 2026-09-01: Physical Lowering now collects candidate applications and call
  edges, solves a finite immutable demand plan before body emission, reserves
  every canonical representation worker once, and makes call/closure lowering
  lookup-only. Recursive SCC edges that change their closed runtime argument
  vector use the generic implementation; no fuel or size heuristic is used.
- Removed mutable emission-time specialization ancestry, candidate catalogs,
  and closure-carried specialization state. Added focused regressions for
  partial applications, aliases, stable and expanding recursion, alpha
  equivalence, disabled specialization, and worker uniqueness.
