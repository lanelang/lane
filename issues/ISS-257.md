## Description
Rename the source-language numeric primitives `Int`, `S32`, and `Double` to `I64`, `I32`, and `F64`, add a complete `F32` primitive, and migrate the compiler, Basic library, VS Code grammar, examples, tests, artifacts, runtimes, and documentation as one coordinated breaking change.

## Design
The old source names are removed rather than retained as aliases. Internal semantic names, diagnostics, text formats, and public APIs must use the new vocabulary consistently. Machine representations remain explicit and distinct: I64 uses signed 64-bit integer semantics, I32 uses signed 32-bit integer semantics, F64 uses IEEE 754 binary64, and F32 uses IEEE 754 binary32.

## Acceptance Criteria
- [ ] Lane recognizes exactly `I64`, `I32`, `F64`, and `F32` as the numeric primitive type names.
- [ ] Compiler and runtime support covers parsing, typing, lowering, artifacts, bytecode, interpreter, Wasm, analysis, diagnostics, formatting, and testing.
- [ ] Basic exposes coherent modules, offers, constants, conversions, and builtin declarations for all four numeric primitives.
- [ ] lane_vscode highlights all four primitive type names and no longer classifies the removed names as built-in numeric types.
- [ ] Every valid, invalid, warning, and fixture example uses the new names and the complete example gate passes.
- [ ] Native tests pass in every modified repository and a final repository-wide stale-name audit is clean.
