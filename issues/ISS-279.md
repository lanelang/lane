# ISS-279: Require only the interface closure a public surface reaches

## Description
Compiling against interface artifacts demanded every module the imports were
themselves compiled against, not the ones their public surfaces reached.

Given `Z`, a `Y` that imports `Z` purely as an implementation detail, and a
`Main` that imports only `Y`, compiling `Main` required both `y.lanei` and
`z.lanei`. `Y`'s interface listed `types: (none)` and a single value
`pub fn total() : () -> I64` — nothing about `Z` was observable — yet
`E4002: missing imported module Z` was reported without it.

Two mechanisms caused this:

- `reachable_interface_artifacts` recursed along `imported_interface_fingerprints`,
  which records direct source imports.
- `interface_type_references` and `interface_effect_references` accumulated the
  reference tables of every imported interface unconditionally, so the tables
  described modules the interface did not depend on.

The effect was that interface artifacts had no encapsulating power: a module's
private choice of dependency became a required input for everyone downstream.

## Design
Require the **Reachable Interface Closure**: the modules that own the symbols an
interface's own content mentions, transitively.

The language makes this computable. A module cannot re-export an imported type,
so anything naming `Z.TypeZ` in a public signature must import `Z` directly.
A surface therefore names every module it depends on.

`ModuleInterface::dependency_symbols` walks types, effects, type aliases, and
values; `dependency_module_paths` maps those symbols to owners through the
interface's reference tables. Both live in `Milky2018/lanec/module` and replace
the private copy in `elaborate/buslane_lowering`. Interface construction records
references only for surface symbols, so the tables and the closure agree.

`optimization_hints` fall under the rule even though they carry no symbols yet,
so a hint that later embeds a body cannot escape it.

Non-goals: no CLI discovery flag, no module-path-to-filename convention, and no
change to linking, which still requires the full **Implementation Closure**.

## Notes
- 2026-07-31: Rejected alternatives, in the order they were considered: a
  `--interface-dir` search path; GHC's module-path-to-filename convention, which
  `CONTEXT.md` forbids since filesystem paths do not define **Module Paths**;
  and waiting for a Lane-authored build system, which the **NoBuild Model**
  favours but which this change makes smaller rather than replaces.
- 2026-07-31: Narrowing the reference tables initially aborted freshening with
  "missing interface type dependency", because `remap_type_symbol` insists on
  remapping every recorded reference. Recording only surface symbols removed the
  unresolvable entries rather than making freshening tolerant of them.
- 2026-07-31: The first implementation walked each interface three times, which
  cost about 3.5% on `examples/valid/78_structural_derivation.lane` and pushed
  that fixture past its 60s timeout. Computing the walk once and reading owners
  straight from the reference tables brought it to 56.5s against a 57.0s
  baseline.

## Close Notes
Added `modules/lanec/module/interface_dependencies.mbt` with
`ModuleInterface::dependency_symbols`, `ModuleInterfaceType::dependency_symbols`,
and `ModuleInterface::dependency_module_paths`. Deleted the equivalent private
walkers from `elaborate/buslane_lowering/import_dependencies.mbt`, which now
calls the shared ones.

`visit_interface_artifact` recurses along `dependency_module_paths` and looks up
each dependency's expected fingerprint with the new
`ModuleInterfaceArtifact::imported_interface_fingerprint`, so narrowing which
modules are required did not narrow how strictly the required ones are checked.
`ModuleImportEnvironments::from_pool` follows the same edge, keeping the
in-memory environment and the input requirement identical.

`SemanticChecker::module_interface` now builds the surface first and resolves
references from it, so the tables describe only what the interface depends on.

Vocabulary: sharpened **Reachable Interface Closure** and added
**Implementation Closure** in `CONTEXT.md`, with relationships stating that
compiling requires the former and linking the latter. Recorded as
`modules/lanec/docs/adr/0126-interface-closure-follows-interface-content.md`.

Verification:
- `moon check --warn-list +73` and `moon check modules/lanec --target all
  --deny-warn` clean.
- `moon test --target native`: 1338 tests, all passed.
- `tools/check-lane-run-examples.sh` passes.
- New tests: `modules/lanec/compile/interface_closure_test.mbt`, covering the
  hidden dependency, the exposed dependency, and the fingerprint check.
- Manual, with `lane compile`: `Main` builds from `y.lanei` alone when `Z` is
  hidden; still reports `E4002` when `Z` reaches `Y`'s signature; reports
  `E4103` when a required `Z` is stale; and `lane link` still reports `E4203`
  for a missing object.

Interface reference tables shrank, so interface fingerprints changed and
existing artifacts must be regenerated.
