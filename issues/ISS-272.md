## Description
The repository requires black-box tests by default, reserving white-box tests
for private invariants that cannot reasonably be observed through public APIs.
The current test layout does not meet that rule. The 2026-08-03 audit found 222
explicit black-box test declarations and 1166 white-box declarations across 38
and 128 files respectively. At least 318 white-box declarations exercise public
behavior and can move to black-box coverage directly or after a small split.

The highest-risk suites bypass the actual product boundary: LSP tests call the
private message handler instead of `run_server`, CLI tests call command helpers
instead of the executable, and compiler diagnostic tests use private request
and result adapters instead of the public compilation outcome.

## Design
Move public behavior tests to `_test.mbt` files and keep `_wbtest.mbt` only for
explicit private invariants. Split mixed files instead of broadening production
APIs for test convenience. Test compiler diagnostics through `CompilationOutcome`,
analysis through `SemanticWorkspace`, LSP protocol behavior through `run_server`,
and CLI behavior through the built executable. Move backend conformance tests
out of the executable package into a dedicated integration-test package that
imports stable public compiler, lowering, and runtime APIs.

Preserve focused white-box coverage for typechecker elaboration shapes,
specialization planning, CPS ABI ownership, VM CFG transforms, runtime ARC and
heap invariants, and other state that has no stable public observation.

- [x] Formatter and parser behavior tests run as black-box tests while their private layout invariants remain white-box tests.

- [x] Language acceptance and diagnostics use compiler-facade black-box tests; checked-IR and solver invariants remain in typecheck white-box tests.

- [x] `run_server` exposes graceful exit, premature exit, and transport closure as distinct public results.
- [x] The CLI alone maps LSP termination results to process status, with premature `exit` returning nonzero.
- [x] Public IO and built-executable regressions cover normal `shutdown -> exit` and premature `exit`.
- [x] CLI command regressions exercise the built executable, including output and exit status.
- [x] Backend conformance tests live outside the executable package and import only stable public seams.
- [x] Every retained white-box suite has a concrete private invariant that justifies its test mode.
- [x] `moon info && moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.

## Close Notes

Rebalanced the repository around public test boundaries without widening production
APIs. Public Buslane, codec/text, diagnostics, lexer, types, formatter/parser,
analysis, artifact, compiler-facade, and LSP behavior now runs from black-box test
packages. The LSP boundary test executes a complete framed editing and shutdown
session through `run_server`; mixed suites retain only private layout, cache, and
normalization invariants as white-box coverage.

Moved 38 Direct Interpreter/Wasmtime/JIT consistency tests out of the `lane`
executable package into `modules/lane/backend_conformance`; the package composes
only public compilation, elaboration, LoisVM lowering, and runtime APIs. Existing
CLI fixtures continue to run the built executable and now cover all valid/invalid
examples without stale single-test calls.

Verified `moon info && moon fmt`, focused package suites, `moon test --target
native` (1400/1400), `tools/check-lane-run-examples.sh`, and `git diff --check`.

The final lifecycle closure exposes `GracefulExit`, `PrematureExit`, and
`TransportClosed` from `run_server`. The CLI maps premature `exit` to status 1
without writing non-protocol output; graceful exit and transport closure retain
status 0. Verified with 49 focused LSP tests, `moon test --target native`
(1484/1484), direct release-binary status checks, `moon info && moon fmt`, and
`git diff --check`.
