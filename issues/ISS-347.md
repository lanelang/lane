## Description
The compiler and loader independently spell the
`lane.runtime.internal.v1` namespace, float-format helper names, and Wasm
signatures. The context document calls the ABI jointly owned, so adding or
changing an internal helper requires synchronized edits across two authorities
and can produce a module that its matching loader cannot satisfy.

## Design
Introduce one package-owned internal ABI description that contains namespace,
symbol, and physical signature facts. Both compiler import emission and loader
host-function installation consume that description. Place the owner where it
does not create a compiler/loader dependency cycle, and keep the ABI private to
LoisVM rather than exposing it through the embedding runtime registry.

## Acceptance Criteria
- [x] Namespace, helper names, and physical signatures have one executable owner.
- [x] Compiler lowering and loader registration consume the same internal ABI
      declarations without repeating string or signature literals.
- [x] A regression proves every emitted internal import has exactly one matching
      loader implementation with the same Wasm type.
- [x] The LoisVM glossary names the single owner and retains the private/public
      ABI distinction.
- [x] `moon info`, `moon fmt`, `moon test --target native`, interpreter/JIT
      conformance, and `git diff --check` pass.

## Close Notes

`loisvm/wasm/internal_abi` now owns the complete V1 internal runtime function
table: namespace, symbol names, and physical Wasm signatures. Compiler import
emission and loader host-function installation both consume it, while the
loader retains only the backend-specific implementation dispatch.

The mixed float-formatting/host-object regression inspects the complete emitted
internal import set against the shared table. The loader's exhaustive dispatch
over the same closed function enum ensures each declared function has one typed
implementation, and the existing execution tests continue to cover both float
formatting and host-object release behavior.
