# ISS-322: Verify callable dependencies used by top-level initializers

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: area/buslane, verifier, correctness, agent
- Assignee: -
- Created: 2026-08-04
- Updated: 2026-08-04
- External ref: modules/buslane/verify.mbt, modules/buslane/interpreter/evaluate.mbt

## Description
The Buslane verifier promotes every later top-level binding into scope while
checking a function body. An earlier value initializer can call that function
before those bindings exist, so a verified program may still fail in the
reference interpreter with `UnboundValue`.

## Design
Keep deferred bindings legal in stored function bodies, but verify the lexical
dependencies of every callable reached by an eager top-level `Let` initializer,
regardless of the binding's `ValueKind`. Only a direct function or type-function
implementation is closure construction rather than eager body execution.
The check must follow callable references transitively and conservatively treat
a mentioned callable as potentially invoked, matching Lane's initialization
ordering rule. It validates term order; it does not reorder Buslane programs.

## Acceptance Criteria
- [x] A verified program cannot call an earlier function that reads a later top-level binding during initialization.
- [x] Transitive callable dependencies are checked.
- [x] Stored function bodies may still refer to bindings established before they are called.
- [x] A black-box test pins verifier/interpreter agreement for the regression.
- [x] A Function-kind `Let` whose non-closure initializer calls a factory is checked as eager.
- [x] Direct function and type-function implementations may still capture later bindings.

## Close Notes
`Program::unbound_callable_dependencies` validates the lexical dependencies of
callables mentioned by each non-closure top-level `Let` initializer. It follows
top-level callables transitively, handles inline and nested callable bodies,
and reports a deferred dependency before the ordinary verifier accepts the
program. `ValueKind` classifies declarations but no longer decides evaluation
time; direct references remain owned by the existing sequential scope rule.

Black-box interpreter regressions cover both an ordinary eager value and a
Function-kind eager `factory()` initializer, and check that `verify_program`
and `evaluate_buslane_program` reject them as the same invalid program. The
existing direct-function capture regression remains accepted.
