## Description
The Ubuntu native quality gate failed `run executes schema 2 top-level
initialization`: `lane_run` returned a non-success outcome for a program with an
eager `String` binding that is read by the selected entry. The same test passed
on the macOS development host.

The complete Linux outcome identifies the failure as
`UserErrors([LaneHomeNotConfigured])`. The self-contained regression source did
not use Basic, but its call to `lane_run` retained the command default
`no_basic=false`. The test therefore depended on the developer machine's
`LANE_HOME` even though that installation input was unrelated to the invariant
under test. The old boolean assertion discarded this distinction and made the
configuration error look like a cross-platform runtime failure.

## Design
Preserve the complete command outcome in the regression failure. Make the test
own its source-input contract by passing `no_basic=true`; do not inject a fake
`LANE_HOME` into the test environment or weaken the command's correct default
library behavior. Execute the same source through both default and `--no-jit`
modes and inspect the pair of complete outcomes.

Keep the schema-2 invariant at the public execution boundary: an eager top-level
initializer runs once before the entry, and its initialized value is readable
through both execution tiers.

## Acceptance Criteria
- [x] The regression reports complete command outcomes instead of reducing them to boolean assertions.
- [x] A Linux reproduction distinguishes command-input failure from default Wasm and `--no-jit` execution.
- [x] The self-contained test explicitly disables the implicit Basic library input.
- [x] The schema-2 eager `String` initializer succeeds through both execution tiers on Linux.
- [x] No environment injection, platform skip, source-type special case, or fallback execution path is introduced.
- [x] `moon info`, `moon fmt`, the full macOS native suite, and the integration gate pass; the affected regression and integration gate also pass on native Linux.
