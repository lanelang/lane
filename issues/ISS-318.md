# ISS-318: Include eta in the type-level normal form

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: area/lanec, area/types, correctness, agent
- Assignee: -
- Created: 2026-08-03
- Updated: 2026-08-03
- External ref: modules/lanec/types/core.mbt

## Description
`Type::normalize_with_fuel` reduces beta but never eta, so `Box` and
`type [A] => Box[A]` are two distinct normal forms. A parameterized type alias
is written as exactly that eta-expansion — `type MyBox[A] = Box[A]` is how the
language spells an alias for `Box` — so using an alias where a higher-kinded
parameter expects a constructor is rejected.

## Reproduction
Measured end to end through `lane run`:

```lane
pub struct Box[A] { value : A }
pub struct Wrapper[F : [Type] -> Type] { held : F[I64] }
pub type MyBox[A] = Box[A]
pub let wrapped : Wrapper[MyBox] = Wrapper::{ held: Box::{ value: 5 } }
```

```text
error[E3006]: type mismatch
   | pub let wrapped : Wrapper[MyBox] = Wrapper::{ held: Box::{ value: 5 } }
   |                                                     ^^^^^^^^^^^^^^^^^
   |            expected `type [A : Type] => Box[A]`, found `Box`
```

The message names the two eta-equivalent forms directly. The same shape
through an enum variant fails identically:

```lane
pub enum Holder[F : [Type] -> Type] { hold(F[I64]) }
pub let held : Holder[MyBox] = Holder::hold(Box::{ value: 5 })
```

Controls that isolate the cause:
- `Wrapper[Box]` (no alias) runs and prints `5`.
- `pub type MyBox = Box` — the same alias written without the eta-expansion —
  runs and prints `5`, which is the measurement that identifies eta rather
  than anything about aliases or inference.
- `take[MyBox](Box::{ value: 5 })` for an explicit generic application runs,
  because there the alias is beta-applied to `I64` and never compared as a
  constructor.
- `examples/valid/18_type_alias_header_higher_kind_parameter.lane` passes for
  the same reason, which is why the corpus did not cover this.

## Design
Eta belongs in the normal form, not in a comparison: `Type::equals` is already
alpha-equality after normalization, so extending normalization is the one
change that reaches every consumer. Reduce
`type [A..] => f[A..]` to `f` when the arguments are exactly the binders in
order and `f` does not mention them.

## Close Notes
`eta_reduce` in `modules/lanec/types/core.mbt` reduces
`type [A..] => f[A..]` to `f` when the arguments are exactly the binders in
order and the callee does not mention them, applied where
`normalize_with_fuel` builds a `TypeLambda`. Since `Type::equals` is alpha
after normalization, every comparison in the checker sees eta without any
comparison site changing. A local `mentions_parameter` predicate carries the
side condition; the existing one lives in `typecheck` and is not visible to
`types`.

The filed root cause was wrong and measurement overturned it. The issue first
claimed that instantiation sites fail to normalize after substituting, since
only `check_explicit_generic_application` pairs `substitute` with
`normalize_type_or_error`. That refactor was implemented and did not fix the
reproduction, because `Type::equals` normalizes both sides already — a
residual redex is never observable through it. Rewriting `type MyBox[A] =
Box[A]` as `type MyBox = Box`, which passes, is what named eta as the real
cause. The substitute-and-normalize pairing is a mild redundancy rather than
a defect and was reverted rather than shipped inside this fix.

Effect aliases need nothing: effects have no lambda form, so a parameterized
effect alias applies its parameter as a row member rather than as a
constructor application and is never eta-shaped. Both `type MyAsk = { Ask }`
and `type Row[E : Effect] = { Ask, E }` check today.

Regressions: `modules/lanec/compile/higher_kinded_alias_test.mbt` locks the
struct and enum cases and the explicit application that already worked, with
red/green measured before the fix (struct false, enum false, explicit true);
`examples/valid/91_higher_kinded_alias_instantiation.lane` covers both through
`lane run`.

Verified: `moon check --target native --warn-list +73` clean; `moon test
--target native` 1463/1463; examples gate exit 0 against the pinned fixture.
