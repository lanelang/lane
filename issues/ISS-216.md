## Description
Retire the advanced semantic host-ABI backlog after the Wasm-only migration
removed the boundary it proposed extending.

## Design
This epic described extensions to the deleted semantic Runtime Registry and
Opaque Host Object ABI. The implemented WASI Preview 1 WebAssembly Target RFC
supersedes that boundary: core Wasm imports are the executable contract,
Preview 1 resources use explicit scalar descriptors and guest-memory protocols,
and Wasmoon executes the same raw Wasm module in interpreter and JIT modes.

Do not revive generic External Types, Host Object transfer, or implicit
aggregate marshaling. Recoverable failures and structured values can be
expressed by an explicit Lane wrapper over a scalar/guest-memory protocol. A
future standardized typed-resource boundary belongs to a separately approved
Component Model RFC rather than this removed ABI.

## Acceptance Criteria
- [x] The semantic Runtime Registry and Opaque Host Object assumptions are
      explicitly superseded by the implemented Wasm-only RFC.
- [x] Current Preview 1 resource and structured-value boundaries are explicit.
- [x] Future typed resources require a new standards-based RFC rather than an
      extension of the deleted host ABI.
- [x] No implementation work remains under this obsolete epic.

## Close Notes

Closed as superseded on 2026-08-28. ISS-400 through ISS-406 removed the
semantic runtime manifest, independent bytecode interpreter, Runtime Registry,
Runtime Context, Opaque value kind, Host Object Store, and private token
transport assumed by this epic. The raw WebAssembly import section and the
canonical WASI Preview 1 catalog now own the host boundary. Explicit scalar and
guest-memory protocols remain available without compiler support for implicit
host objects or aggregate marshaling; a future Component Model resource design
must start from a new RFC.
