## Description
Carry `Array[T]` and polymorphic intrinsic evidence through the closed Runtime
ANF boundary without retaining source type syntax or inventing an Array-only
generic call model.

## Design
Project an applied Array type to one explicit runtime Array representation with
its element `RuntimeArgument`. Project intrinsic `Forall` and evidence
application through the same Runtime ANF forms used by ordinary generic
callables. Extend Runtime ANF verification, equality, substitution, pretty
printing, traversal, and simplification around that one representation fact.

## Acceptance Criteria
- [x] Runtime ANF represents Array values with one element runtime argument and
      natural reference layout.
- [x] Generic intrinsic evidence applications survive direct and first-class
      source uses through verified Runtime ANF.
- [x] Runtime ANF verifier rejects missing, ill-kinded, or free evidence.
- [x] No Buslane source type, nominal placeholder, or Array-only call syntax
      crosses the Runtime ANF boundary.
- [x] Focused public compiler tests cover exported/imported and indirect Array
      intrinsic values.

## Close Notes

- 2026-08-28: Runtime ANF now projects `Array[T]` to exactly
  `Array(RuntimeArgument)` and classifies the outer value as an owned reference.
  The element argument uses the existing interned type-expression and evidence
  catalogs; no Buslane type or Array-specific invocation node survives.
- 2026-08-28: Direct calls and first-class specialization both lower through
  the ordinary `EvidenceLambda` and `ApplyEvidence` forms. The Runtime ANF
  verifier checks the element argument at arity zero and rejects missing,
  unbound, and higher-kinded evidence.
- 2026-08-28: Black-box compiler coverage verifies an exported generic Array
  intrinsic imported and specialized as a first-class value. Structured Runtime
  ANF regressions cover direct and indirect calls. `moon info`, `moon fmt`, and
  all 1,728 native tests pass.
