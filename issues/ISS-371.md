## Description
Wasm emission remains the largest structural size amplifier for the Coroutine
Scheduler. The current bytecode has 61 functions and 350 instructions, while
the emitted module has 115 defined functions, 10,551 rendered instructions,
764 locals, 516 structured `if` nodes, 180 `unreachable` nodes, and 87 table
entries. The instruction ratio is approximately 30.15 to one.

The largest generated bodies expand 20 to 27 bytecode operations into 476 to
518 Wasm instructions, and one callable adapter expands to 301 instructions.
Different IRs count instructions at different granularity, so the ratio is not
itself a correctness defect, but it identifies repeated control-flow, runtime
guard, ARC, and indirect-call machinery as the dominant code-size owner.

## Design
Give the Wasm emission owner structured expansion accounting by bytecode
function, opcode family, runtime guard, ARC action, control-flow scaffold,
helper, and entry/runtime lifecycle. Use it to identify repeated emitted
structures and remove duplication at the deepest owner that possesses the
required proof.

Verifier-established bytecode invariants may justify deleting redundant
runtime guards; repeated implementation sequences may move behind canonical
helpers when that reduces total code without changing ownership or trap
behavior. Keep dynamic checks whose facts are not statically proven. Do not
change source semantics, weaken verifier contracts, add per-example branches,
or use arbitrary function-size and call-count thresholds.

## Close Notes
Explore now requires every emitted defined function to account exactly for all
of its instructions and locals using structured categories owned by the Wasm
emitter. The dominant remaining owners on example 37 are ARC/unwind (2,415
instructions), object operations (2,027), callable operations (1,009), runtime
support (780), and runtime guards (684).

Three structural changes remove duplication without heuristics:

- all indirect calls use one canonical callable-ABI guard helper instead of
  inlining the target-range and compatibility-matrix policy;
- frames with no owned values propagate fatal exceptions without a vacuous
  cleanup handler;
- owned references and packed callables use their invalid zero representation
  as the empty-owner state, while erased values retain the separate liveness
  bit required by their valid zero payload and layout witness.

Bytecode-normalized comparison on the same example 37 input:

- Physical Program: 60 functions and 342 instructions before and after;
- Wasm: 10,365 to 8,864 instructions (-1,501, -14.5%);
- locals: 757 to 495 (-262, -34.6%);
- structured `if`: 511 to 419 (-92, -18.0%);
- `unreachable`: 175 to 82 (-93, -53.1%);
- table entries: 82 to 82;
- defined functions: 110 to 111 because the repeated ABI policy became one
  non-table helper.

End to end, the Coroutine Scheduler still has 60 physical functions and 413
physical slots, emits 111 Wasm functions, and prints `1112211322` under both
JIT and `--no-jit`. Callable ABI mismatch, fatal cleanup, byte-sequence
ownership, and interpreter/JIT regression tests pass.
