# ISS-386: Canonicalize the cleaned pre-ARC function table

## Description
LoisVM lowering computes whole-image function reachability before VM CFG local
simplification. Dead `ConstFunction` instructions therefore retain functions
that have no consumer in the cleaned program. Exact duplicate generic and
representation-worker bodies also remain distinct even when their complete VM
CFG bodies and callable ABIs are identical. The CPS callback regression
contains both failures: an unused generic `apply_call` remains reachable, and
an anonymous generic body is instruction-for-instruction identical to its
worker.

This makes the persisted bytecode function table depend on pre-cleanup facts
and prevents ISS-385 from measuring the actual physical implementation closure.

## Design
Make VM CFG own a nominal cleaned pre-ARC image boundary. Local
devirtualization, consuming-projection selection, simplification, borrow
preparation, and metadata validation run before function-table policy.
Function-table canonicalization then computes reachability, exact body
equivalence, runtime-import deduplication, deterministic ordering, and the old
to-new identity relation from that cleaned image in one operation.

LoisVM lowering maps its provenance through the returned identity relation but
does not rediscover reachability or body equivalence. The canonical pre-ARC
image is compiler-private: the public API completes ARC insertion, physical
slot allocation, bytecode emission, and bytecode verification in one call,
then exposes the pre-ARC image only as observation data on the completed
finalization. Equality is the complete VM CFG body contract, not a source role,
function-size threshold, hash guess, or profitability heuristic.

## Acceptance Criteria
- [x] Local VM CFG cleanup precedes the sole whole-image reachability pass.
- [x] The function-table owner merges exact equal bodies and preserves all
      contributing provenance.
- [x] Bytecode finalization consumes a private nominal canonical pre-ARC image
      and does not expose a caller-mutable prepare/finalize protocol.
- [x] A dead function reference removed by local cleanup cannot retain its
      target in VM CFG or bytecode.
- [x] Equal generic and representation-worker bodies produce one function with
      both origins.
- [x] Callback and normalization regressions reduce retained functions;
      Scheduler Explore, JIT, and `--no-jit` preserve behavior.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Notes
- 2026-08-21: A concrete Explore dump showed an unused `ConstFunction` keeping
  generic `apply_call` alive and two distinct FunctionIds containing exactly
  the same VM CFG body.
- 2026-08-21: Boundary review removed the public two-step `prepare` /
  `finalize_prepared` protocol. Its `Image` accessor exposed mutable arrays and
  allowed mutation after proof but before finalization. `finalize_observed` now
  returns observation data only after the bytecode image has passed its
  verifier.

## Close Notes
- 2026-08-21: VM CFG now privately constructs one canonical cleaned pre-ARC
  image after local devirtualization, projection selection, simplification,
  borrow preparation, and verification. Whole-image reachability and exact
  function-body canonicalization run only at this boundary.
- 2026-08-21: Finalization exposes the canonical pre-ARC image and identity
  relation only as completed observation data. Callers cannot mutate a proved
  image between preparation, ARC insertion, slot planning, bytecode emission,
  and final bytecode verification.
- 2026-08-21: Exact duplicate bodies merge all origins, while dead references
  removed by cleanup no longer retain their targets. All 53 VM CFG tests, the
  complete 1760-test native suite, and Scheduler JIT / `--no-jit` execution
  pass.
