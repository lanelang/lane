## Description
Callable adapter identity is currently produced twice. Type adaptation caches
plans by source type, target type, parameter mapping, and substitution. After
VM CFG emission, function-table canonicalization computes structural
equivalence classes for callable-adapter bodies and merges plans that the first
identity failed to recognize as the same runtime operation.

The second producer proves that source type syntax is not the canonical adapter
identity. It also makes FunctionId, provenance, reachability, and adapter count
depend on a late fixed-point structural comparison.

## Design
After parameter/result alignment and runtime-type classification, construct one
`CallableAdapterRecipe` containing only facts that affect emitted behavior:
canonical source/target runtime ABI, parameter alignment, result adaptation,
ordered captured evidence ABI, environment shape, and erase/unerase/layout
operations. Intern recipes before allocating adapter FunctionIds.

Every recipe produces at most one worker. Adapter closure creation supplies
site-specific captured values but does not allocate another body. Remove the
VM CFG callable-adapter structural equivalence analysis. Function-table
canonicalization may retain general reachability, stable ordering, remapping,
and Runtime Import deduplication, but it must not own adapter identity.

## Acceptance Criteria
- [x] One canonical `CallableAdapterRecipe` is the sole key for adapter body and
      FunctionId allocation.
- [x] Definitionally different source types that emit the same runtime recipe
      share one worker before VM CFG construction.
- [x] Different runtime ABI, alignment, adaptation operation, or capture ABI
      produces distinct recipes.
- [x] Adapter provenance is attached when the recipe is interned and survives
      ordinary function-table remapping without structural rediscovery.
- [x] VM CFG canonicalization contains no callable-adapter-specific structural
      class or fixed point.
- [x] Focused white-box tests cover recipe equality/inequality; black-box
      lowering tests cover shared bodies with distinct captured witnesses.
- [x] Explore reports no regression in adapter, erase/unerase, closure,
      environment, function, or Wasm instruction counts.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Close Notes

`CallableAdapterContract` now makes the semantic identity/no-op/adapter
decision once. Materialized conversions project that contract into a canonical
`CallableAdapterRecipe` containing runtime callable ABIs, physical parameter
flow, evidence origins, concrete layouts, nested adapter recipes, capture ABIs,
and result behavior. The recipe is interned before its one worker FunctionId;
each escape site supplies its own witness and callable captures.

Runtime evidence selection now produces one `RuntimeEvidencePlan` consumed by
both ordinary lowering and recipe projection. The VM CFG function-table pass no
longer computes adapter structural equivalence or runs an adapter fixed point;
it retains reachability, Runtime Import deduplication, stable remapping, and
provenance remapping only. The obsolete structural-equivalence test was deleted.

Focused tests distinguish layout-sensitive recipes and prove alpha-distinct
captured parameters share a worker. A public lowering regression over the real
Coroutine Scheduler observes 17 adapter workers serving 23 closure
materializations. Before/after Explore metrics are identical: initial VM CFG
has 61 functions, 396 instructions, 46 closures/environments, 16 erases, 10
unerases, and 49 indirect calls; Bytecode has 61 functions and 350
instructions; Wasm has 115 functions and 10,551 rendered instructions. JIT and
`--no-jit` both print `1112211322`.

Verified with `moon info`, `moon fmt`,
`moon check --target native --warn-list +73`, and
`moon test --target native` (1749/1749).
