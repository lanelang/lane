## Description
`inline_is_profitable` accepts strict structural shrinkage or a straight-line
candidate. `is_straight_line_value` rejects every Match, including a certified
single-constructor field projection with no runtime branch.

In the ISS-434 baseline, the TestReport.counts getter survives both Core
optimization stages and becomes a Physical function:

```text
fn(report) { match report { TestReport(counts, failures) => counts } }
```

For this multiply-used getter, a call with an atomic argument has structural
size 3 and the substituted projection also has size 3. Strict shrinkage fails;
the syntactic Match exclusion also fails. `execute_tests` consequently retains
report, calls counts, and calls passed, then repeats the counts call before
calling failed. The unnecessary call boundaries also obstruct local ARC work.

## Design
Make profitability distinguish a verified irrefutable projection from a real
case split using existing constructor/type facts. Keep legality and effect-aware
argument evaluation under their current owners. Do not classify all one-arm
matches as irrefutable, special-case Basic getters, increase arbitrary inlining
budgets, or introduce a parallel metadata analysis.

## Acceptance Criteria
- [ ] A multiply-used single-constructor getter is reduced to a local projection
      even when the current syntactic node count does not decrease.
- [ ] Real case splits, impossible matches, and nontrivial branch bodies are
      not incorrectly classified as straight-line projections.
- [ ] Non-atomic and effectful arguments preserve evaluation multiplicity and
      effects; owned projected fields remain valid.
- [ ] Public execution and structural optimization regressions cover the
      distinction without locking incidental IDs or function order.
- [ ] Re-run Basic and record getter calls and related ARC work before/after.
