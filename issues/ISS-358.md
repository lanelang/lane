## Description
ANF functions have no identity and LoisVM lowering allocates FunctionId values
through several direct `plans.push` paths. A later observer therefore cannot
distinguish preserved functions from closures, adapters, initializers, and
other generated functions without reconstructing lowering behavior.

## Design
ANF lowering assigns deterministic report-local function identities. Replace
the bare planned-entry array with one atomic function-plan abstraction carrying
the entry and its typed origin. Every FunctionId allocation goes through one
owner. Generated functions use explicit roles rather than fabricated source
parents.

## Acceptance Criteria
- [ ] Every ANF function has a deterministic identity preserved by simplification.
- [ ] Bound functions retain their final Buslane value anchor when one exists.
- [ ] Every planned FunctionId is created together with exactly one typed origin.
- [ ] Nested, recursive, initializer, adapter, intrinsic, layout, and import
      planning paths cannot bypass the provenance owner.
- [ ] Focused tests cover source and synthetic origins.
