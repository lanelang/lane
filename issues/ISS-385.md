## Description
ISS-384 introduced explicit identities for specialized nominal data families,
but the lowering model still passes an ambient
`Array[DataRepresentationFamilyPlan]` through functions, calls, captures,
matches, adapters, and slots. That array is simultaneously treated as a
catalog of available families and as the selected representation of each
value. These are different facts.

The deep-handler regression demonstrates the contradiction. One function
context contains specialized `Data1[Unit]` and `Data1[Callable]` families, so a
single `Data1[Unit]` parameter is incorrectly attributed the complete ambient
array. A nested capture independently retains the declaration family. Strict
family-context equality then misses an existing worker, while subset matching
or lowering-time filtering can select the wrong worker and increase emitted
code. More propagation cannot repair a representation fact that has no unique
value-level owner.

Runtime ANF semantic types also cannot be the final owner. The same semantic
`Data(owner, arguments)` may validly use the declaration family in one open
component and a specialized family in a different closed component. Physical
representation must therefore be assigned to value ports and flow edges by a
separate immutable plan before VM CFG emission.

## Design
Introduce one deep Physical Representation Planner between Runtime ANF
callable-flow analysis and VM CFG emission. It consumes semantic callable
instances, stable ANF sites, allocation flow, and representation evidence and
produces a nominal `RepresentedRuntimeAnfProgram` containing the original
Runtime ANF plus a total immutable `PhysicalRepresentationPlan`. It does not
copy the ANF tree.

Every runtime value port has exactly one interned `ValueShapeId`. Ports include
function parameters and results, bindings, call arguments and results,
captures, constructor results and payloads, match scrutinees and payloads, and
control-flow joins. A value shape directly identifies Unit, scalar,
byte-sequence, opaque-reference, erased-evidence, callable-ABI, or data-family
representation. A data value is `Data(DataFamilyId)`; no consumer receives a
family array from which it can choose again.

The planner owns three related contracts:

- a Callable Invocation Contract containing exact witness, parameter, and
  result shapes;
- a Function Representation Variant containing one semantic callable instance,
  its invocation contract, capture shapes, and body-site assignments; and
- a Data Representation Family Contract containing the nominal owner and the
  complete constructor member-shape and stored-evidence schemas.

A specialized family identity is determined by its complete physical storage
contract, not only by its source owner and closed generic arguments. Recursive
members refer to the current data-family SCC identity rather than recursively
expanding the contract. Callable-valued members name one exact invocation
contract; capture layout belongs to the producing function variant, not to the
callable value ABI.

Planning is finite constraint solving over value ports. Identity-preserving
flow requires equal shapes. Construction, matching, callable invocation, and
capture edges contribute their structural constraints. Open, existential,
indirectly incompatible, or joined flow forces the canonical generic
representation. The only unequal edges are explicit planned bridges for
erase, unerase, or callable adaptation. There is no implicit conversion
between declaration and specialized data families.

The canonical generic elaboration is the always-correct baseline. A candidate
specialization is accepted only when its entire connected component receives a
consistent closed assignment. Worker discovery uses a finite worklist keyed by
semantic callable instance plus complete physical function contract. Recursive
SCCs must prove a finite set of canonical contracts; otherwise the complete SCC
retains the generic representation. Rejection occurs in planning and never
becomes an emission-time fallback.

VM CFG emission consumes only `RepresentedRuntimeAnfProgram`. It projects
planned shapes to VM CFG metadata and emits the selected worker, family,
environment, or bridge. It may not inspect `RuntimeType` to choose a family,
filter an ambient family set, discover a worker, or create an adapter absent
from the plan.

## Acceptance Criteria
- [x] Runtime ANF and the Callable Instance Plan remain the sole owners of
      semantic types, callable identity, and semantic flow; neither stores a
      selected physical family context.
- [x] A nominal `RepresentedRuntimeAnfProgram` proves that every runtime value
      port and every identity-preserving flow edge has exactly one compatible
      `ValueShapeId` before VM CFG emission.
- [x] Callable invocation contracts name exact witness, parameter, and result
      shapes; function variants additionally name exact capture and body-site
      shapes.
- [x] Each data-family identity owns one complete constructor member-shape and
      evidence contract, including callable-valued and recursively nested
      members.
- [x] Specialized family identity includes the complete physical storage
      contract; equal source owner and arguments do not conflate different
      nested representations.
- [x] Open, existential, recursively expanding, joined, or incompatible
      components retain the canonical generic representation as a whole.
- [x] The planner is the only producer of representation workers and explicit
      erase, unerase, and callable-adapter bridges; every canonical contract
      produces at most one worker.
- [x] VM CFG lowering accepts only the represented phase value and contains no
      ambient family array, family filtering, representation inference, worker
      discovery, or emission-time fallback.
- [x] Delete `FunctionLowerer.data_families`, callable-instance family context,
      `*_with_data_families`, and all equivalent parallel family-selection
      paths.
- [x] Yield, Flip, State, Coroutine, structural derivation, deep nested
      handlers, and higher-kinded callable storage pass under JIT and
      `--no-jit` without `DataValue` or callable ABI mismatch.
- [x] Explore records the complete post-plan implementation closure and its
      representation costs without using scale as a semantic acceptance rule;
      further adapter and bridge reduction is owned by ISS-368.
- [x] The representation RFC, ADR-0134, ADR-0136, and the owning glossary state
      the per-value-port model and no longer claim that a semantic type or
      ambient family context uniquely determines specialized representation.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.

## Notes
- 2026-08-18: Discovered while validating specialized families against the
  complete examples corpus. Treating a callable field as an ordinary reference
  produced partial family specialization and bytecode semantic-kind failures.
- 2026-08-19: The first implementation attempted to make callable contracts
  carry complete family arrays. Focused paths improved, but nested handler and
  capture paths exposed contradictory family ownership.
- 2026-08-20: Root-cause review rejected ambient family propagation. A source
  slot was attributed two unrelated specialized families solely because both
  were visible in its worker. Strict matching failed; permissive matching made
  Scheduler metrics worse. The issue is rewritten around total per-value
  physical-shape assignment rather than further lowering patches.
- 2026-08-21: Capture-flow validation exposed a downstream function-table
  ordering defect: reachability runs before local VM CFG cleanup and exact
  duplicate bodies are not merged. ISS-386 owns the cleaned pre-ARC
  canonicalization boundary required before ISS-385 scale acceptance.
- 2026-08-21: Generic callable invocation contracts are frozen before workers
  and bodies. Higher-order contracts consume already-frozen callable ABIs;
  runtime type syntax is no longer a second invocation-contract producer.
- 2026-08-21: Callable provenance may justify an adapter boundary only when it
  definitionally owns one complete endpoint. ABI equality can then identify
  the peer representation, but cannot establish provenance by itself.

## Close Notes
- 2026-08-21: Completed the nominal `RepresentedRuntimeAnfProgram` boundary and
  total `PhysicalRepresentationPlan`. Every emitted function consumes frozen
  invocation, value-shape, data-family, worker, and adapter facts; emission no
  longer filters ambient family arrays or reconstructs generic call ABIs from
  type syntax.
- 2026-08-21: Correct evidence adaptation materializes the source witness list
  independently from target evidence inputs. Concrete, captured, and forwarded
  higher-kinded witnesses therefore retain one exact physical contract.
- 2026-08-21: The sound Scheduler plan contains 22 adapter workers, 30 adapter
  materializations, and 22 finalized adapters. The earlier 19/26/19 result was
  rejected because it failed five backend-conformance cases. Fresh Explore
  records 64 initial VM CFG functions, 331 instructions, 22 adapters, 15 erase,
  and 11 unerase operations; ISS-368 owns any subsequent safe reduction.
- 2026-08-21: `moon info`, `moon fmt`, strict native check, all 1760 native
  tests, and Scheduler execution under JIT and `--no-jit` pass.
