## Description
Two small blemishes against the no-special-cases rule:

- `is_exhaustive` (verify.mbt:1167) has an explicit `Primitive(F64) => false`
  arm that duplicates the wildcard default two lines below. A branch that does
  what the default does is noise; if the intent is "floats are deliberately
  never exhaustive", that belongs in a comment on the default, not a dead arm.
- `verify_generic_argument_kind` (verify.mbt:1224) hardcodes `actual = Type`
  when a TypeArgument appears where Effect is expected, discarding the
  synthesized kind it just computed. The rejection is right; the diagnostic
  lies when the argument's kind is a Function kind.

## Acceptance Criteria
- [x] The F64 arm is gone (or replaced by a comment on the default) with no behavior change.
- [x] The kind-mismatch diagnostic reports the argument's synthesized kind.

## Close Notes
The `Primitive(F64)` arm is gone; the wildcard default now carries a comment
saying every other scrutinee has more values than a match can enumerate, so
only a default alternative makes it exhaustive.

The second item was fixed against its own acceptance criterion rather than
literally. Reporting the argument's synthesized kind would produce
`KindMismatch(expected=Effect, actual=Effect)` whenever the offending type
argument is an effect-kinded parameter — a diagnostic that reads as a
contradiction. The defect is that a *category* error (a type argument where an
effect row belongs) was being reported as a *kind* error, so
`verify_generic_argument_kind` now reports the new
`ExpectedEffectArgument(Type)` / `ExpectedTypeArgument(Effect)` kinds, named
after the `TypeSubstitutionError` pair that already states the same distinction
one layer down. No synthesized kind is invented, and the rejection is unchanged.

Verified with ISS-311 in one change: `moon test --target native` 1458/1458,
`moon check --target native --warn-list +73` clean.
