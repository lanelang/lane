## Description
Basic asks why `summon_via[Debug, Option, Char]()` cannot be written as
`summon_via()` even when the binding has expected type
`Debug[Option[Char]]`. The current compiler reports E3010 for `Evid`, `T1`, and
`T2`.

The expected type is available, but `Debug[T]` is a transparent alias for
`Into[T, String]`, which is itself `(T) -> String`. After head reduction, the
expected type is `(Option[Char]) -> String`; it no longer has a `Debug` head.
Inferring `Evid` from that shape would require synthesizing a higher-kinded
lambda such as `type[X] => (X) -> String`. Lane's local structural inference
intentionally does not perform that non-unique higher-order unification.

Nominal `Equal[Option[Char]]` does infer in the adjacent test because its
outer `Equal` constructor remains structurally visible. The contrast is an
important consequence of transparent capability aliases, not evidence that
expected-result inference is absent.

## Design
Keep the beta-only, local structural inference boundary established by
ISS-318. Retain explicit generic arguments at transparent `Debug` lifting
sites and replace the speculative TODO with an explanation at the narrowest
durable documentation seam, preferably `summon_via` or the transparent
capability documentation rather than repeated comments in tests.

Do not add eta equality, global constraints, higher-order type-lambda search,
or a nominal runtime wrapper for `Debug`. A partial-explicit-generic syntax or
specialized lifting helper may be considered separately only if multiple real
call sites demonstrate an ergonomics problem.
