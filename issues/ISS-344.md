# ISS-344: Give finalized callable ABIs one owner

## Metadata

- Status: closed

## Description
VM CFG finalization interns callee callable ABIs before `finalize_body` performs
ownership and slot transformations. Indirect call sites then reconstruct a
separate ABI from the transformed local metadata. The two producers can observe
different cleanup shapes, as previously happened when valid examples exposed
`Trivial` versus `OwnedRef` argument mismatches.

## Design
Derive callee and call-site ABIs from one canonical finalized-slot model owned by
the finalizer. Do not snapshot callee metadata before transformations or repair
individual mismatches in the verifier. Runtime-import ABIs must enter the same
interning plan without becoming dependent on VM CFG internals.
The bytecode layer owns the single operation that projects finalized slot views
into `CallableAbi`; VM CFG supplies finalized views and consumes the resulting
ABI rather than maintaining a second projection implementation.

## Acceptance Criteria
- [x] No callable ABI is interned from pre-finalization ownership metadata.
- [x] Callee definitions, direct and indirect call verification, indirect call
      emission, tail calls, and runtime imports consume one bytecode-owned ABI
      projection and assembly chain.
- [x] Borrowed source values that become trivial bytecode slots produce the same
      cleanup shape at definitions and every call site.
- [x] Focused regressions cover owned, borrowed, erased, and higher-kinded
      callable arguments and results.
- [x] All valid examples, interpreter/JIT conformance, `moon test --target
      native`, and `git diff --check` pass.

## Notes
- 2026-08-08: The earlier nine-example ABI failure is fixed, but the structural
  split remains at `finalize_or_raise`, `vmcfg_callable_abi`, and
  `callsite_callable_abi`.
- 2026-08-09: Reopened because the timing defect is fixed but ABI construction
  still has two owners. Definitions and runtime imports use
  `FunctionEntry::callable_abi`, while indirect calls and tail calls use VM
  CFG's separate `finalized_callable_abi`. Reading the same finalized metadata
  does not prevent the two projection rules from drifting; all paths must
  consume one bytecode-owned construction operation.
- 2026-08-10: Implementation resumed with the bytecode package as the sole
  interpreter of finalized slot metadata. VM CFG will retain only value-to-slot
  lowering and ABI identity interning; its duplicate ABI projection is removed.
- 2026-08-10: Review found that bytecode verification still rebuilt comparison
  ABIs by copying slot fields and that the regression fixed interner order. The
  issue remained open until verification consumed the canonical projection and
  the test asserted identities through the public lookup API.

## Close Notes

Closed after deleting VM CFG's `finalized_callable_abi` implementation and the
verifier's independent comparison-ABI projection. The bytecode package now owns
the only finalized `SlotMetadata` to `ValueAbi` projection and the only
`CallableAbi` assembly operation. Function definitions, indirect-call emission,
and verification delegate to that chain; runtime imports translate their
distinct source declaration into `ValueAbi` before using the same assembler.
VM CFG only selects ABI-final operands and assigns `CallableAbiId` identity.
Physical-slot allocation may subsequently remap or coalesce only identical
`SlotMetadata`, so it cannot alter the interned ABI.

An order-independent black-box complete-image regression proves that a
definition, ordinary indirect call, indirect tail call, and runtime import
resolve through the expected shared ABI identities. Existing owned, borrowed,
erased, higher-kinded, and backend conformance regressions remain green. `moon
info`, `moon fmt`, all native tests, the full integration gate, and `git
diff --check` pass.
