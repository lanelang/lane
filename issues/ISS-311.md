## Description
`VerifyDiagnostic` (verify.mbt:2) is a bare kind: no top-term anchor, no path to
the offending expression, no originating declaration. The review standard
requires failures to carry what diagnosis needs; the ISS-284/ISS-292 sessions
are the measured counterexample — regressions surfaced as "401
UnknownTypeParameter" and locating them required hand instrumentation of the
pipeline, because the reports could not say which declaration produced them.

## Design
Give every diagnostic an anchor: at minimum the enclosing top term (index or
ValueId) and the metadata identity under check during the metadata pass. A
lightweight breadcrumb (push/pop on VerifyContext) keeps the verifier pure and
adds no cost to the clean path. Pretty-printing should render the anchor with
Buslane names, not bare indexes.

## Acceptance Criteria
- [x] Every diagnostic reports the top term or metadata entry it arose in.
- [x] Expression-level diagnostics carry enough path to locate the node (term index + child path is sufficient).
- [x] Gate failures in lanec print anchored diagnostics end to end.

## Close Notes
Provenance is produced by descent, not by reporting sites. `VerifyContext`
carries a frame stack; `within` pushes one frame around a descent and pops it,
and `report` copies the stack, so the clean path pays a push and a pop per node
and no reporting site knows provenance exists. Frames mirror the verifier's own
phases: `Metadata(MetadataAnchor)` for the metadata pass, `TopTerm(ValueId)`
per top-level binding, `Expression(ExprLabel)` per expression.

The expression path costs one call site because `synthesize_expr` is already
the sole dispatch point for every form — it pushes `expr.label()` around the
whole match, so every nested construct is covered without touching the
individual synthesizers. `Expr::label` is a total function of `Expr`, so a new
expression form is a compile error there rather than an unlabelled path step.
`verify_top_letrec` was split per binding so each recursive binding anchors to
its own term rather than to the group.

Rendering reads as the route taken, outermost first:
`unknown_value value#9999 at term value#1 / fn / let value#0 / ref value#9999`.
Gate failures in lanec now print that form too — `loisvm_lowering/lower.mbt`
rendered the result with `Repr`, a debug dump; it uses the pretty renderer now.
The measured motivation was three sessions of hand instrumentation
(ISS-284/292's "401 UnknownTypeParameter", and this review's
`InvalidBinderKind(value={index: 8})` and `UnknownValue({index: 3})`), each of
which the path answers directly.

Existing tests whose subject is which rule fired now compare
`diagnostic.kind` through a local projection, so a scope-rule test does not
re-assert a path; snapshot tests carry the full value including provenance.
Two new tests pin the fact itself — an expression path and a metadata anchor.

Verified: `moon check --target native --warn-list +73` clean; `moon test
--target native` 1458/1458; examples gate exit 0; `.mbti` drift is the three
new public types plus their Pretty impls.
