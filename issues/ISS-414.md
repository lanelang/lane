## Description
The post-ISS-411 Basic Physical Program contains 372 retains and 286 releases,
while Wasm expansion accounting attributes 20,351 instructions to ARC and
unwind support. This is the largest current Wasm expansion category. The
physical operation count and emitted support count measure different work, so
neither alone proves which instructions are removable.

## Design
Use the verified ARC-final lifetime and cleanup plans as the only semantic
owner. First refine owner-produced expansion facts enough to distinguish
mandatory ownership operations, per-frame unwind state, repeated cleanup
scaffolding, and shared runtime support. Then remove or share only structures
whose lifetime plans are structurally identical.

Prefer eliminating redundant ownership demands in VM CFG before ARC insertion.
When repeated unwind implementation remains after that point, intern a typed
cleanup plan before Wasm function identity and indices are allocated. The Wasm
emitter consumes the plan and must not rediscover liveness from slot patterns.

Fatal propagation, reverse cleanup order, partial initialization, reusable
continuations, and erased ownership remain observable constraints. Do not use
function size, call frequency, or a fixed instruction budget to decide
correctness.

## Acceptance Criteria
- [ ] Explore separates mandatory ARC operations, per-frame unwind scaffolding,
      and shared support without parsing rendered Wasm.
- [ ] ARC-final lifetime plans remain the sole producer of cleanup semantics.
- [ ] Proven redundant ownership demands are removed before emission, or
      structurally identical unwind plans share one implementation.
- [ ] Fatal and normal exits retain exact cleanup behavior, including partial
      initialization and reverse release order.
- [ ] A fixed Physical Program emits fewer ARC/unwind Wasm instructions without
      weakening its verifier contract.
- [ ] The pinned Basic comparison, JIT, `--no-jit`, native tests, and all valid
      examples pass.
