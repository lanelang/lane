# ISS-337: Bound top-level initializer lowering by peak live ownership

- Type: bug
- Status: closed

## Description
Lane currently combines every reachable eager top-level binding into one
LoisVM initializer function. The lowering then gives each historical bytecode
slot its own Wasm local and, when cleanup is required, a second `i32` live-bit
local. Final cleanup emits one conditional release for every non-trivial slot.

Consequently the generated initializer is sized by all temporaries ever
created while initializing the whole program, rather than by peak live state.
A small, valid source addition can therefore push an already large aggregate
initializer over a backend limit even when the addition is correct and does
not duplicate existing initialization work.

This was reproduced by adding one two-field derived `Debug` dictionary to
Basic. The clean Basic image compiles, while the modified image fails during
AArch64 JIT compilation with:

```text
BackendCompileFailure(
  detail="Wasmoon JIT compilation failed for `wasm_func_146`: AArch64CompilationFailed(cause=EmissionFailed(cause=BranchOutOfRange(offset=1471440, bits=19)))"
)
```

The added global accounts for 85 additional LoisVM bytecode instructions and
87 additional slots. There is no repeated copy of the old initializer. The
aggregate failing initializer nevertheless has 431 bytecode instructions and
353 slots; Wasm lowering expands those slots into 706 locals and approximately
484 cleanup `if` expressions.

This is a Lane code-generation defect independent of any execution backend:
the physical resources required by an initializer must follow peak live state,
not the number of logical values that existed earlier in the function.

## Design
Preserve the existing single logical image initializer, but implement it as a
small orchestrator over one ordinary step function per eager top-level
initializer. Steps compute and return values; only the orchestrator may execute
`InitGlobal`. Planning preserves source dependency order and the existing
exactly-once initialization contract.

Within each generated function, physical locals and cleanup state should be
allocated from liveness and ownership information:

- reuse compatible physical locals after a value's lifetime ends;
- represent cleanup work in terms of currently owned values, not every
  historical slot;
- retain enough provenance to release partially initialized values exactly
  once on exceptional paths; and
- keep representation and cleanup compatibility part of the reuse rule.

Physical slot allocation happens after ownership finalization has made
retains, releases, and consuming transfers explicit. It may reuse a slot only
when the previous lifetime has ended and the complete slot metadata is
compatible. Erased values and their companion witnesses remain conservative
until they can be allocated as one proven-compatible group.

The desired invariant is that the largest generated initializer step depends
on the largest individual source initializer, while the orchestrator's local
and cleanup state depends on peak simultaneously live ownership. General
outlining of one pathologically large expression is a separate compiler-wide
problem and is not part of this issue.

Do not special-case `derive`, `Debug`, or Basic. The derived dictionary is only
a threshold trigger. Do not make the Lane fix depend on the Wasmoon issue being
resolved first; the two changes are complementary.

## Acceptance Criteria
- [x] The real Basic aggregate compiles and its configured `test.sh` entry completes with the installed development compiler; an isolated derived dictionary alone is not sufficient coverage.
- [x] The bytecode image retains one logical initializer whose orchestrator invokes one step per eager top-level initializer in dependency order.
- [x] Only the orchestrator executes `InitGlobal`; ordinary step functions return their owned result to it.
- [x] A generated scaling test shows that increasing independent owned initializers from 4 to 16 leaves the orchestrator at one compatible owned result slot.
- [x] A structural test, limited to this otherwise unobservable resource invariant, checks complete step and orchestrator instruction sequences and verifies the resulting bytecode image.
- [x] Slot reuse runs after ownership finalization, requires complete metadata equality, and extends erased companion interference across the owner lifetime.
- [x] Multi-block functions allocate compatible physical slots from finalized CFG liveness and preserve distinct function inputs and simultaneous block parameters.
- [x] Wasm lowering allocates transfer scratch by peak per-representation edge width and cleanup liveness only for non-trivial physical slots.
- [x] Existing interpreter and Wasm initializer failure/cleanup lifecycle regressions continue to pass with physical slot reuse enabled.
- [x] `moon test --target native` passes in Lane and `basic/test.sh` completes with the installed development compiler.

## Notes
- 2026-08-06: Clean Basic produced 607 bytecode functions and the triggering change produced 641; the additional functions are expected derive closures, specializations, and adapters, not duplicated copies of a large body.
- 2026-08-06: The clean initializer had 266 slots and 346 instructions. The failing initializer had 353 slots and 431 instructions. The exact delta, 87 slots and 85 instructions, belongs to the new derived global.
- 2026-08-06: The failing generated Wasm function had 706 locals, approximately 484 `if` expressions, and approximately 7,976 rendered WAT lines. Lane creates one value local and one cleanup-live local for each of the 353 bytecode slots.
- 2026-08-07: Implementation uses semantic initializer steps rather than arbitrary count-based chunks. General oversized-function outlining remains out of scope.
- 2026-08-11: The original single-block allocator left ordinary CFG-heavy functions unallocated, while Wasm lowering still reserved one transfer and one cleanup local per physical slot. The completed allocator now colors the finalized CFG interference relation, and a single Wasm-local plan owns value, transfer, dispatcher, and cleanup indices.

## Close Notes
- 2026-08-07: Replaced the aggregate eager initializer with one ordinary step
  function per reachable binding and one image initializer orchestrator. Only
  the orchestrator performs ordered `InitGlobal` transfers.
- 2026-08-07: Moved physical slot reuse after ownership finalization. The
  single-block allocator uses one exhaustive destination/source traversal,
  requires complete slot metadata equality, and conservatively keeps erased
  companion groups distinct.
- 2026-08-07: Added public lowering regressions for complete step/orchestrator
  shape and 4-to-16 initializer scaling. Updated affected canonical bytecode
  snapshots and retained the existing erased-companion and cleanup lifecycle
  coverage.
- 2026-08-07: Verified with `moon info`, `moon fmt`,
  `moon test --target native` (4210 passed), the development installation
  script, and `basic/test.sh` (completed with its configured test entry).
- 2026-08-11: Extended physical-slot reuse to finalized multi-block CFGs and
  replaced arithmetic Wasm-local indexing with one function-local plan.
  Function inputs, simultaneous block parameters, instruction operands, exact
  slot metadata, and erased companions remain explicit interference
  constraints. The real Basic program's maximum generated Wasm local count
  fell from 759 to 145, and three installed-binary runs fell from a 10.08 s
  median to 7.11 s. Verified with 1,611 native tests and the complete
  integration gate.
