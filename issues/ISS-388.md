# ISS-388: Give refined callables independent representation identities

## Description
`CallableRepresentationTarget::Refined` reuses its source
`CallableInstance.id`. Data-family, result, capture, port, and allocation facts
are indexed by that semantic instance ID, so a closed refined callable cannot
own representation facts distinct from its generic source instance.

A minimal generic handler constructs a `Monoid[I64]` whose callable field
returns a closed `WriteResult[Unit, I64]`. Callable flow correctly identifies a
refined target, but its worker result is planned from the source instance's
generic data family. Construction then tries to store that callable under the
refined field contract and lowering rejects the valid program with
`RepresentationSpecializationInvariant`: the source result uses one
`DataValue` family and the target result uses another.

Changing whether `Semantic` or `Refined` wins a local target-selection tie is
not a repair. It changes provenance while both targets still query the same
instance-indexed representation facts.

## Design
Make the representation solver key callable nodes by a stable, canonical
callable-target identity rather than by the source semantic instance integer.
A semantic instance and each distinct refined target may share one Runtime ANF
definition, but they must own separate substitution, port, result, capture,
allocation, data-family, and worker-demand facts.

Implement this in the Physical ANF representation graph introduced by
ISS-387. The graph should intern `Semantic` and `Refined` target keys, attach
the source definition as provenance only, and solve every closed target's
complete physical contract from its own flow component. Do not allocate
negative synthetic instance IDs, fall back to source-instance facts, choose a
family while emitting VM CFG, or add an adapter between unequal nominal data
families.

## Acceptance Criteria
- [ ] A refined callable has a stable representation identity distinct from
      its source semantic instance while retaining explicit source-definition
      provenance.
- [ ] Port, result, capture, allocation, data-family, and worker facts are
      indexed by the refined target identity and never retrieved through the
      source instance ID.
- [ ] The minimized `run_write` program using `WriteResult[Unit, I64]` compiles
      and observes `42` under the interpreter, Wasm, and JIT backends.
- [ ] A generic source callable and two closed refined targets can coexist with
      three independently verified physical contracts and one generic
      fallback.
- [ ] No representation adapter is used to cross two distinct nominal
      `DataValue` family identities.
- [ ] Existing higher-kinded storage, recursive companion forwarding, and
      complete examples regressions continue to pass.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      and `moon test --target native` pass.
