# ISS-351: Compose colliding inlay hints from nested calls

## Metadata
- Type: bug
- Status: closed

## Description
`textDocument/inlayHint` fails for ordinary Basic source files because Lane
treats any two hints at one source position as a compiler defect. Distinct
nested calls can legitimately share an insertion boundary. For example, in
`assert_true('你' < '😀')`, the outer ordinary call inserts its contextual
`info` argument immediately before `)`, while the inner operator call inserts
its contextual `op` argument at the end of the operand expression. Those are
the same source position even though the hints describe different calls.

The current release build reproduces this through the public stdio LSP server
against `../basic/test/data/char.lane`:

```text
internal Lane compiler bug: multiple inlay hints were produced at
.../basic/test/data/char.lane:36:25
(`, info=source_info` and `, op=char_impl_compare`)
```

The same failure repeats across numeric comparison tests and nested arithmetic
in `../basic/src/data/string.lane`. Each failed request discards the complete
inlay result, so one legal collision makes inlay hints unavailable for the
requested document range.

## Design
Make semantic analysis own a deterministic, composable inlay presentation
rather than asking the LSP serializer to reject position collisions.

Keep the originating call span and nesting relationship while collecting
implicit-argument hints. Before publishing `InlayHintEntry` values, group
fragments that share an insertion position and compose them in semantic
inner-to-outer order. This corresponds to the order in which the omitted
arguments would be inserted into the nested calls. Multiple omitted arguments
for one call remain one fragment, as they are today.

The final analysis result must preserve every logical hint exactly once. It
must not drop one side, deduplicate by label, invent neighboring columns, or
depend on incidental traversal order. The LSP layer should serialize that
final presentation directly and remove the false global one-hint-per-position
invariant. Position collisions involving other hint kinds must either be
represented by the same explicit composition contract or remain as distinct
valid protocol entries; they must not turn a successful analysis into a failed
request.

## Acceptance Criteria
- [x] A public `run_server` session requesting inlay hints for
      `../basic/test/data/char.lane` returns a successful result containing
      both `op=char_impl_compare` and `info=source_info` exactly once.
- [x] Nested arithmetic matching `../basic/src/data/string.lane` preserves the
      inner and outer operator offers in deterministic inner-to-outer order.

- [x] The LSP boundary no longer rejects legal hints solely because their
      rendered positions are equal.
- [x] Black-box regressions exercise the public stdio server; white-box tests
      are limited to the private composition invariant if it cannot be
      observed precisely through the public response.
- [x] No hint is dropped, shifted to a fabricated position, or recovered by a
      label-based fallback.
- [x] `moon info`, `moon fmt`, `moon test --target native`, and the LSP
      integration gate pass.

## Notes
- 2026-08-10: VS Code Lane Language Server logs contain repeated failures in
  Basic for `char`, `i32`, `i64`, `f64`, and `string` sources. A fresh public
  stdio session using the current release executable reproduced the `char`
  failure, ruling out a stale installed binary and duplicate workspace
  indexing as necessary causes.
- 2026-08-10: `implicit_argument_insertion_span` deliberately places an
  ordinary call hint before its closing parenthesis and an operator hint at the
  operator expression end. Nested syntax can make those correct positions
  identical; `validate_inlay_hint_positions` encodes the invalid invariant.
- 2026-08-10: Claimed for a source-backed composition design and public LSP
  regression beginning from the real Basic collision.

## Close Notes

- 2026-08-10: `InlayHintEntry` now carries its final analysis-owned insertion
  position. Private inlay facts retain the originating syntax span until the
  presentation pass has deterministically ordered colliding implicit fragments
  from the smallest nested span outward.
- 2026-08-10: The presentation pass combines only implicit-argument fragments
  at one insertion point. Other hint kinds remain distinct protocol entries;
  the LSP layer now serializes the completed analysis result without deriving
  positions or enforcing a false uniqueness invariant.
- 2026-08-10: A public framed `run_server` regression covers the original
  operator-inside-call collision and a stable result after `didChange`. A
  black-box analysis regression covers right-nested multiplication/addition,
  while the existing multiple-auto-argument regression remains green.
- 2026-08-10: The fixed release binary returned
  `, op=char_impl_compare, info=source_info` for the pinned Basic char fixture.
  The pinned Basic string fixture returned
  `, op=i64_impl_mul, op=i64_impl_add` at all three colliding arithmetic sites.
  Verified with `moon info`, `moon fmt`, all 1,609 native tests, and
  `tools/check-lane-integration.sh`.
