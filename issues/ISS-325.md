## Description
Top-term and metadata provenance anchors render only storage IDs such as
`value#1` and `datacon#0`. The verifier has the corresponding Buslane names
when it constructs each frame, but discards them, forcing readers to search the
metadata table before a diagnostic identifies its declaration.

## Design
Make anchors self-contained structured values carrying both semantic ID and
optional display name. Known metadata declarations always carry a name; an
invalid top-term ID may legitimately fall back to its bare ID. Rendering shows
the name and retains the ID for unambiguous lookup.

## Acceptance Criteria
- [x] Known top-term anchors render their Buslane name and ID.
- [x] Known metadata anchors render their Buslane name and ID.
- [x] Missing metadata remains diagnosable without inventing a name.
- [x] Structured provenance remains self-contained after verification.

## Close Notes
`ValueAnchor` retains a top-level value ID and its optional metadata name, while
every `MetadataAnchor` variant retains both the entity ID and its known name.
The verifier constructs these anchors while the metadata entry is in hand, so
diagnostics remain self-contained after verification. Pretty output renders
`"name"#unique (value#id)` and the analogous metadata form.

Black-box tests cover a named top term, a named data constructor, and an invalid
top-term ID whose missing metadata correctly falls back to the bare ID.

Verified with `moon check --target native --warn-list +73`, `moon test
modules/buslane --target native` (88/88), the full `moon test --target native`
(1478/1478), `moon info`, and `moon fmt`.
