# ISS-399: Propagate verified IR certificates through backend seams

## Description
Lane owns complete verifiers for Buslane and Physical Program, but their
successful results are discarded at several compiler seams. Downstream stages
therefore accept raw IR and repeat input validation even when the immediately
preceding owner already certified the same value. This weakens the type-level
chain of trust and makes verifier calls look like defensive policy owned by
consumers.

Each transformation that creates a new IR must still certify its output. The
problem is specifically the loss of that certificate before the next consumer:
linked Buslane, effect-specialized Buslane, optimized Buslane, CPS Core, and the
final Physical Program all currently cross at least one raw-value seam.

## Design
Buslane owns one opaque certified-program type produced by its existing
verifier. Compiler transformations consume a certified input and certify their
new output exactly once. Raw `Program` remains the public interchange syntax
for parsers, codecs, diagnostics, tests, and other untrusted producers; it does
not enter compiler transformations without certification.

Physical owns one opaque verified Physical Program containing the
verifier-produced global lifecycle plan. VM CFG finalization returns this value
directly and Wasm emission consumes it without invoking the verifier again.
Raw Physical Program remains available to focused verifier tests and any
untrusted construction seam, but is not the compiler pipeline contract.

Do not remove verification of genuinely new transformation outputs. Effect
Lowering's private transitional stages continue to use the single Buslane
semantic verifier through their existing projection; only the already-certified
input check and later consumer rechecks are removed. Do not introduce a second
set of semantic rules or a compatibility fallback accepting both raw and
certified compiler inputs.

## Acceptance Criteria
- [x] Buslane exposes one opaque certified-program value produced by its owning verifier.
- [x] Link, effect specialization, core optimization, Effect Lowering, executable elaboration, and Runtime ANF pass certified Buslane values between stages.
- [x] Every transformation certifies its newly produced Buslane output exactly once; consumers do not reverify unchanged inputs.
- [x] VM CFG finalization returns an opaque verified Physical Program with the verifier-owned lifecycle plan.
- [x] Wasm emission consumes verified Physical Program and contains no Physical verifier call or raw-input fallback.
- [x] Downstream defensive errors and checks made impossible by certified inputs are removed rather than retained as fallback paths.
- [x] The owning glossary distinguishes raw interchange IR, certified compiler IR, and newly produced outputs requiring certification.
- [x] Focused black-box tests cover rejection at raw certification seams and successful certified propagation; white-box tests remain limited to otherwise unobservable verifier invariants.
- [x] `moon info`, `moon fmt`, strict native check, native tests, relevant Wasm-target tests, and the valid examples gate pass.

## Notes
- 2026-08-28: Started after auditing approximately 7,749 lines of named verifier logic. The audit found that the verifier families mostly own distinct invariants; the actionable duplication is certificate loss at raw-value interfaces.
- 2026-08-29: Reopened after mutation-isolation review found that Buslane
  certification shallow-copies nested mutable arrays and Physical
  certification retains and exposes the original mutable image. The wrappers
  therefore do not preserve their verified facts against aliases.

## Close Notes

- Added opaque `VerifiedProgram` and `VerifiedPhysicalProgram` certificates at
  the Buslane and Physical ownership boundaries. Compiler transformations now
  consume certificates and certify only newly produced IR; VM CFG owns final
  Physical certification and Wasm consumes that result without a fallback.
- Removed downstream input-verification errors that certified inputs make
  impossible. Raw values remain available only at interchange, construction,
  interpreter, and focused verifier-test boundaries.
- Full certification exposed a pre-existing Buslane verifier defect: match
  binders were checked but not placed in alternative scope, despite the core
  language and interpreter requiring that visibility. Fixed the owning scope
  rule and added a black-box regression.
- Verified with `moon info`, `moon fmt`, strict native check, 1736 native tests,
  the 12-test Basic suite, and the valid-examples gate.
