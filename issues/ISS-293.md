## Description
`examples/valid/45_async_effect.lane` produces two `TypeMismatch` after
monadic-lift. Both compare a CPS'd callable passed as an argument against the
parameter it is passed to. The expected type is a callable whose dictionary sits
at the *enclosing* function's answer and residual:

```
Forall([%answer#404, %residual#405],
  Function([ Schedule%dictionary<%answer#414, %residual#415>, ... ],
           Parameter(%answer#404), Parameter(%residual#405)))
```

while the actual is a callable polymorphic in its own. The two are each
well formed; they disagree about which pair the dictionary belongs to.

This started as "the binders and the parameter values come from different
`rewrite_type` generations", which is what the uniques suggest. Instrumenting
the pass ruled that out. Across every `examples/valid` program:

- no CPS callable construction site — `lower_cps_function`,
  `lower_cps_effectful_result_call`, `UnhandledFrame::fresh_frame`,
  `adapt_direct_argument_to_cps` — builds a callable whose parameter values
  mention an answer or residual other than the binders it is about to bind;
- `rewrite_type`'s monadic branch never produces a type with a free `%answer`
  or `%residual`;
- no type committed through `store_cps_value_type` has one either.

So neither expression construction, type construction, nor the commit path
leaks a binder. The parameter is not free in its scope, and the uniques being
from different generations is a consequence of allocation order rather than
evidence of a capture.

What is actually in question is a rule this pass does not state anywhere: when a
CPS'd callable is *itself* a parameter, whose answer and residual does its
dictionary sit at — the enclosing callable's, or its own? Both are constructed
consistently; the two sides of this call chose differently.

## Design
Decide the rule first, then make one place own it.

A CPS'd callable parameter can only be called with a dictionary its caller
already holds, which is the enclosing callable's. Typing it polymorphically then
forces the caller to instantiate it at that same pair, which is the shape
`lower_cps_monadic_call` already produces. Whether the parameter's declared type
should quantify or should name the enclosing pair follows from that, and the
answer belongs in `CONTEXT.md` beside **Answer-Type CPS**, since it is part of
the ABI rather than an implementation detail.

Once the rule exists, giving a function occurrence one shape is what keeps both
sides on it:

```
CpsCallableShape
  source_type
  target_type
  answer_parameter
  residual_parameter
  context_parameter_types
  value_parameter_types
  result_type
```

Both consumers read the same shape: the declaration's committed type, and the
`TypeLambda` plus `Function` that implements it. A nested function is driven by
the shape its consuming position supplies; where there is no expected type, the
source type is synthesized once and one shape is created from it. Metadata and
AST are never derived separately.

`commit_cps_binding_type` goes away. The shape is the intent, and the
implementation is checked against it rather than defining it:

```
type_is_consumable_as(synthesize(lowered_rhs), committed_type)
```

Consumability rather than equality, because a lowered body's row is legitimately
narrower than the row its position declares — that is the result ISS-284
established, and asserting equality here would fire on correct output.

Checking at each binding is the point. A divergence introduced while lowering
one function is reported there, naming that function, instead of surfacing after
monadic-lift as a `TypeMismatch` between two large types with no indication of
which pass produced either.

A structural cache on `rewrite_type` is not a substitute and must not be added.
Sharing a binder identity between two quantifier positions is the defect, not
the fix.

## Acceptance Criteria
- [ ] The rule for where a CPS'd callable parameter carries its dictionary is
      stated in `CONTEXT.md`, and both sides of a call follow it.
- [ ] One `CpsCallableShape` per function occurrence feeds both the declared
      type and the implementation.
- [ ] `commit_cps_binding_type` is replaced by a consumability assertion against
      the committed type, checked as each binding is lowered.
- [ ] A CPS focused test covers a higher-order effectful parameter, a nested
      function, and a context dictionary sharing one shape, and fails on a free
      binder rather than accepting two alpha-equivalent types.
- [ ] `examples/valid/45_async_effect.lane` verifies after monadic-lift.
- [ ] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.

## Notes
- 2026-08-02: Retitled and re-scoped after instrumenting. The original premise —
  that a binder escapes its owner — is disproved by the three measurements in
  the description. `CpsCallableShape` on its own would not have fixed this
  example, because every site it would unify is already self-consistent. It is
  still worth building, as the thing that keeps both sides of a call on one
  rule, but the rule has to be decided first or the refactor has nothing to
  enforce.

  Priority dropped from 0 to 1: ISS-292 is unblocked and independently
  verifiable, this one now starts with a design question.
