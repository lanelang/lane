## Description
Implement the globally available pure generic `Array[T]` value described by
`modules/lanec/docs/array-rfc.md`.

The RFC defines the source type constructor, closed polymorphic compiler
intrinsics, representation erasure, runtime object layout, ownership, pure
copy-on-write updates, Basic wrappers, and cross-tier validation contract. This
work is intentionally deferred and is not part of the current implementation
queue.

## Design
Treat the RFC as the authoritative design contract. Before implementation
starts, re-review the Draft against the then-current compiler, artifact,
LoisVM, Wasm, and Basic interfaces and promote or revise it explicitly.

When resumed, split the work into dependency-ordered child issues following
the RFC implementation sequence. Preserve its central invariants: one
compiler-owned Array type-constructor identity, one authoritative runtime
element-layout source per operation, ordinary first-class generic builtin
behavior, no source-type-based layout guessing, no runtime reflection, and no
Array extension to the host ABI.

## Acceptance Criteria
- [ ] The Array RFC is re-reviewed and accepted before implementation begins.
- [ ] Dependency-ordered child issues cover the semantic type, intrinsic and
      artifact pipeline, generic lowering, VM CFG and bytecode, interpreter,
      Wasm tier, Basic interface, tooling, and examples.
- [ ] `Array[T]` satisfies the RFC's ownership, bounds, pure alias, malformed
      bytecode, and interpreter/Wasm parity requirements.
- [ ] The complete RFC acceptance criteria and `moon test --target native`
      pass before this epic is closed.
