## Description
The release examples check consistently fails while running the valid
`79_structural_derivation_equal.lane:answer` fixture. LoisVM reports a Wasm JIT
trap in `wasm_func_140` instead of the expected output:

```text
error[E6013]: LoisVM execution failed
  reason: EngineTrap(detail="JITTrap(\"unreachable ... wasm=140 'wasm_func_140'+0x91a0\")")
```

The failure reproduces both in the current worktree and in an isolated build of
commit `93f6ac41`, so it predates the Explore function-identity correction that
exposed it through the integration gate.

## Design
Minimize the failing derived `Equal` program, then compare the final LoisVM
bytecode, emitted Wasm, interpreter execution, and JIT execution to locate the
first incorrect fact owner. Determine whether the unreachable instruction is
valid compiler-generated control flow reached by a backend defect or invalid
control flow emitted by Lane. Fix that owner and preserve one compilation and
execution path; do not skip the fixture, disable JIT, add a runtime fallback, or
special-case structural derivation.

## Notes
- 2026-08-12: Reproduced repeatedly on macOS in the current worktree and in an
  isolated release build of `93f6ac41`; both trap at Wasm function 140.
- 2026-08-12: After replacing recursive Core partial evaluation with immutable
  inline planning, the exact fixture passed under both default JIT and
  `--no-jit` before any runtime dependency upgrade. Upgrading the complete
  Wasmoon family from `0.12.0/0.7.0` to `0.12.1/0.7.1` also passes the fixture,
  all 1,681 native tests, and the complete release examples check. The upgrade
  therefore cannot be credited as the cause; the original JIT defect requires
  a preserved old Wasm artifact or a minimized shape before it can be closed.
- 2026-08-26: Resumed against the latest published Wasmoon family. Closure now
  requires a fresh JIT/no-JIT comparison and the complete valid examples gate;
  no Lane fallback or fixture exception will be accepted.
- 2026-08-26: The first maintained boundary was the old recursive Core partial
  evaluator: replacing its repeated whole-program expansion with immutable
  inline planning removed the invalid reachable path before Wasm emission.
  This predates the dependency upgrade and is therefore the compiler-side root
  repair; the Wasmoon update is not credited for it.
- 2026-08-26: The exact structural-derivation fixture now prints
  `derive equal: box list point tree` under both JIT and `--no-jit`. All 1,713
  native tests and the complete valid examples gate pass without a skip,
  derive-specific lowering branch, or execution fallback.

## Close Notes

The structural derivation itself was valid. The obsolete recursive Core
partial evaluator could leave an invalid reachable path that only the JIT
entered; immutable inline planning removed that producer. The original
generated Wasm artifact is no longer available for further historical
minimization, so closure is based on the maintained source fixture at the
compiler and public execution boundaries, not on attributing the fix to the
Wasmoon upgrade.
