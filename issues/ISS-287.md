## Description
Four things found while reviewing the selective-CPS package after ISS-283. None
is a reported failure; each is a place where the pass either contradicts itself
or emits something it cannot justify.

**1. A match alternative's type binders are rewritten on one path and not the
other.** `lower_cps_monadic_match` maps them through `companion_parameter`,
`lower_cps_direct_expr` leaves them alone. The same opened existential binder
therefore lowers differently depending on whether its match sits in a monadic
position. One of the two is wrong; the validator does not check alternative type
binders, so neither is caught.

**2. `build_empty_context_direct_call` instantiates the residual at `Empty`
without checking the callee has one.** It hands the callee an identity
continuation, which is only well typed when the callee's own residual is empty.
A probe over the whole test suite and every example never fired, because effect
specialization monomorphises the empty instantiation first — but the path has no
guard, so a future caller reaches it silently.

**3. `lower_cps_direct_expr` returns `Bind` and `OpenContext` unchanged.**
Neither can appear in direct position in a well-formed program, since both mark
a monadic computation whose enclosing function is therefore CPS'd. Passing the
subtree through unlowered turns an upstream defect into wrong output instead of
an error.

**4. `lower_cps_effectful_result_call` lowers its arguments with no current
answer** even though it has just built one. An argument containing a type
application that needs a packed context type falls back to `Unit` and `Empty`.

## Design
1. Decide which path is right by asking what an opened effect-kind binder means
   after CPS, then make both agree and have `mon_trans_validate` check
   alternative type binders so they cannot drift again.
2. Raise rather than emit when the callee's residual is not empty.
3. Raise on `Bind` and `OpenContext` in direct position.
4. Thread the answer through.

## Acceptance Criteria
- [x] Both match paths treat alternative type binders identically.
- [x] The two unreachable-by-construction cases raise instead of emitting.
- [x] `lower_cps_effectful_result_call` threads its answer.
- [x] `moon check`, `moon test --target native`, and
      `tools/check-lane-run-examples.sh` pass.

## Close Notes
All four are closed, three by refusing to emit what could not be justified.

**1.** The two paths now agree, and the direct path was the correct one — the
opposite of what this issue assumed. `lower_cps_monadic_match` was the only
place mapping an opened binder through `companion_parameter`; an effect-kind
existential is erased outright rather than given a dictionary companion, which
`modules/lanec/loisvm_lowering/lower_wbtest.mbt` already pins by asserting a
stored witness count of zero. Mapping it was found to be wrong by making the
change and watching that test go red.

**2.** `build_empty_context_direct_call` checks that the callee accepts a pure
continuation instead of assuming it. A probe over the whole suite and every
example never reached the bad case, because effect specialization monomorphises
the empty instantiation first.

**3.** `Bind` and `OpenContext` in direct position raise.

**4.** `lower_cps_effectful_result_call` threads the answer it already had.

Having `mon_trans_validate` check alternative type binders is dropped from here
and left to ISS-288, which already carries it. Bolting one more hand-written
walk onto a validator that is not a type checker is the shape of the problem
that issue exists to remove.
