# ISS-338: Make compiler-produced IEEE special constants deterministic

## Description
LoisVM lowering currently constructs `%f32_inf`, `%f32_ninf`, `%f32_nan`,
`%f64_inf`, `%f64_ninf`, and `%f64_nan` by evaluating floating-point division
in the compiler host and then reinterpreting the result. In particular,
`0.0 / 0.0` produced different NaN sign bits on macOS and Linux, so the same
Lane source compiled to different bytecode and the Ubuntu quality gate failed.

Compiler-produced constants are artifact data and must be reproducible across
hosts. This is distinct from arithmetic performed by a compiled program: Lane
does not promise a particular NaN payload for arbitrary runtime operations.

## Design
Lower the six special-value intrinsics from explicit IEEE 754 bit patterns.
Use the positive canonical quiet NaNs `0x7fc00000` for F32 and
`0x7ff8000000000000` for F64. Encode both infinities directly as well so the
entire producer family has one deterministic implementation.

Do not globally canonicalize NaNs. Existing F32/F64 values must retain their
stored bits through persistence and representation erasure, and formatting
must continue to render every NaN sign and payload as `NaN`.

## Acceptance Criteria
- [x] F32 and F64 infinity, negative infinity, and NaN intrinsics lower from explicit IEEE bit patterns rather than host floating-point arithmetic.
- [x] `%f32_nan` lowers to `0x7fc00000` and `%f64_nan` lowers to `0x7ff8000000000000` on every compiler host.
- [x] Lowering regressions cover the exact bit patterns for both widths.
- [x] Formatting regressions cover NaNs with distinct signs and payloads without requiring canonicalized input bits.
- [x] Existing artifact and representation-erasure bit-preservation semantics remain unchanged.
- [x] The native test suite passes.
- [x] The Ubuntu quality gate no longer reports a host-dependent F32 NaN snapshot.
