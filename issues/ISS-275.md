## Description
ADR-0115 defines Explore Protocol version 1 with compiler identity, root
identity, artifact-selected entry, overall status, stage domain, text format,
per-stage diagnostics, a fixed ordered set of eighteen stages, and explicit
unavailable status after failure. The current model has only
`id/title/text` stages and a report-level optional failure string. Failed
reports omit later stages.

Exploration also parses all supplied library sources and fails on diagnostics
from unused libraries, while normal compilation uses import-reachable source
semantics. The documented guarantee that exploration shares production
orchestration and failure semantics is therefore not met.

## Design
Implement a closed, versioned protocol model. Represent each fixed stage as
completed with a snapshot, failed with diagnostics, or unavailable. Snapshots
own stable identity, display label, compiler/backend domain, text format,
human-readable text, and diagnostics. Reports own compiler identity, root
identity, selected entry, overall status, diagnostics, and all eighteen stages.

Create one production compilation orchestration path with an optional read-only
observer. Normal compilation installs no observer; exploration renders observed
stage values. Use the same import-reachable input and failure semantics in both
workflows. Do not grow the current `failure : String?` record with ad-hoc fields.

## Acceptance Criteria
- [ ] The protocol type contains compiler identity, root identity, selected entry, typed overall status, and exactly eighteen ordered stage states.
- [ ] Completed snapshots contain domain, text format, text, and diagnostics.
- [ ] Failed reports preserve completed stages, identify the failed stage, and mark every later stage unavailable.
- [ ] Native and Wasm adapters serialize or render the same compiler-owned report semantics.
- [ ] Normal compilation and exploration share import-reachable source selection and stage-owning orchestration.
- [ ] An unused malformed library produces the same observable success/failure decision in compile and explore.
- [ ] Black-box tests cover success plus parse, graph, resolve, typecheck, link, entry-selection, executable, LoisVM, and Wasm failure reports where constructible.
- [ ] ADR-0115, context documentation, generated interfaces, native HTML, and Wasm JSON agree exactly.
- [ ] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
