## Description
Complex private algorithms often contain useful invariant comments, but major
public compiler seams have little or no declaration-level contract
documentation. At review time the analysis, driver, module-compile, and
executable packages respectively had 36, 7, 31, and 9 public declarations with
no public documentation comments. Callers must infer snapshot invalidation,
failure states, ordering, determinism, and lifecycle behavior from
implementation or long-form context documents.

## Design
First shrink and stabilize the affected public surfaces through the related
architecture issues. Then document only the durable seams: compile requests and
outcomes, semantic workspace and snapshot lifecycle, artifact trust and schema
rules, link ordering and diagnostics, executable ownership, and driver protocol
semantics.

Comments should state invariants, failure conditions, ordering, determinism,
mutation/lifetime behavior, and meaningful complexity. Do not add comments that
merely restate names or narrate private implementation steps.

## Acceptance Criteria
- [x] Stable public compile, artifact, link, driver, executable, semantic-workspace, and snapshot APIs have declaration-level contract comments.
- [x] `SemanticWorkspace` documents revision changes, dirty-source invalidation, snapshot `None` cases, and diagnostic delta semantics.
- [ ] Artifact and link APIs distinguish untrusted input validation from trusted internal invariants.
- [x] Compilation outcomes document warnings versus errors and whether partial products may exist.
- [x] Driver and executable APIs document stage order, failure behavior, ownership, and determinism.
- [x] Generated documentation or IDE-visible interfaces expose these contracts.
- [x] No blanket comments are added to self-evident private helpers.
- [ ] Linked-program artifact comments agree with the actual decode boundary:
      `parse_bytecode_image_binary` already invokes the LoisVM verifier and no
      public comment instructs callers to repeat a verification step that has
      already occurred.
- [x] `moon info`, `moon fmt`, documentation checks, `moon test --target native`, examples, and `git diff --check` pass.
