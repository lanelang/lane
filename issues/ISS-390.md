## Description
Lane already has a complete generic correctness model: open values use an
erased payload with layout evidence, higher-kinded parameters pass layout
constructors, and generic nominal storage has a declaration-owned uniform
schema.

The current LoisVM lowering branch instead requires a whole-program
representation solution before it can emit VM CFG. Callable flow, per-value
demands, data-family variants, callable contracts, adapter recipes, physical
shapes, and emission support are persisted as several parallel models. Their
mutual consistency is enforced by thousands of lines of projection and
verification code. Representation specialization has therefore become a
correctness prerequisite rather than an optional optimization.

## Design
Replace the current representation-planning stack with the architecture in
ADR-0138:

```text
Runtime ANF
  -> canonical generic representation elaboration
  -> explicit structural adaptations
  -> VM CFG with authoritative physical contracts
  -> canonical VM CFG / ARC / slot / bytecode verification
```

Representation elaboration is private to LoisVM Lowering. Private normalization
caches, substitutions, evidence recipes, interning tables, and work queues may
exist inside it, but no physical-program mirror or planning sidecar crosses the
package boundary. Delete consumer-visible demand, solution, occurrence, and
family sidecars; do not preserve compatibility lookup paths.

The first executable path must use only the Canonical Generic ABI. Concrete
values retain their natural ABI. Open ordinary and higher-kinded values carry
explicit evidence. Generic nominal storage remains declaration-owned and
uniform. A structural `adapt(source, target, value)` operation inserts erase,
unerase, or callable conversion at unequal boundaries.

Only after that path is independently complete may representation
specialization return as a removable program rewrite. It clones a real generic
definition for a closed canonical ABI key and rewrites actual calls. Open,
indirect, unsupported, or recursively expanding uses retain the generic
implementation. Specialized nominal storage is outside this issue; closed
aggregate scalar replacement may optimize non-escaping values without changing
nominal family identity.

Do not retain Physical ANF unless it owns an invariant distinct from Runtime ANF
and VM CFG. The removed form did not: it copied executable structure and
planner projections that VM CFG already represents. Representation choices are
therefore made once while VM CFG is constructed and are validated by the VM CFG
finalization boundary.

## Acceptance Criteria
- [x] Every valid Runtime ANF regression lowers and executes through the
      Canonical Generic ABI with representation specialization disabled.
- [x] Generic ordinary, higher-kinded, CPS-companion, recursive, indirect, and
      nominal-storage cases do not require a closed specialization demand.
- [x] Representation Elaboration remains behind one lowering interface; no
      consumer receives a callable-instance plan, representation graph or
      solution, adapter recipe catalog, specialized data-family catalog, or
      transition-occurrence sidecar.
- [x] No Physical ANF mirror remains; VM CFG is the first IR containing closed
      physical contracts and explicit adaptations.
- [x] VM CFG finalization consumes already selected physical operations and
      does not select workers, storage families, layouts, or adapters.
- [x] Generic nominal declarations have one uniform storage schema; no closed
      argument silently creates another nominal family.
- [x] Structural callable adaptation materializes at most one worker per
      complete source/target physical contract and does not rely on VM CFG body
      equivalence.
- [x] Optional specialization is absent from the correctness path and remains
      an independent rewrite owned by ISS-363.
- [x] Delete the superseded planner, graph, catalog, remapping, and
      duplicate verification paths in the same migration.
- [x] Black-box coverage includes higher-kinded identity, refined callable
      results, structural derivation, parser combinators, data types a la carte,
      and the Coroutine Scheduler under the interpreter and JIT where
      applicable.
- [x] Explore records the canonical generic output's function, adapter,
      erase/unerase, indirect-call, and final code-size metrics without making
      those metrics semantic gates; ISS-363 owns future comparison with an
      optional rewrite.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
      `moon test --target native`, and the complete valid examples gate pass.

## Notes
- 2026-08-26: Created after comparing Lane's representation branch with Koka's
  typed Core, local boxing/coercion pass, optional specialization rewrite, and
  backend-owned ARC pipeline. The comparison identified optimization/correctness
  coupling and persistent projections of derived facts as the root errors.
- 2026-08-26: Production line count is not an acceptance condition. The design
  instead uses the deletion test: removing specialization must leave a correct
  compiler, and deleting the elaborator must cause its complexity to reappear
  at consumers rather than make it vanish.
- 2026-08-26: Implementation started from the Canonical Generic ABI path. The
  migration will replace consumer-visible planning sidecars rather than layer a
  compatibility path over them.
- 2026-08-26: The migration proved that Physical ANF had no independent
  invariant and removed it. Runtime ANF is now elaborated directly into VM CFG;
  VM CFG finalization remains the verified physical boundary.

## Close Notes

- 2026-08-26: Deleted the mandatory callable-instance plan, representation
  constraint/solution stack, specialized data-family catalog, Physical ANF,
  transition sidecars, and their duplicate verifiers. The production diff
  removes over twenty thousand lines while keeping generic nominal storage
  uniform.
- 2026-08-26: Restored the Canonical Generic ABI for direct, indirect,
  higher-kinded, recursive, CPS-companion, first-class type-application, and
  Unit-instantiated callables. Callable adaptation now has one private complete
  recipe identity; worker materialization and nested adaptation consume that
  identity, and VM CFG body equality does not rediscover it.
- 2026-08-26: Native tests pass 1775/1775 and the complete valid examples gate
  passes against the pinned Basic checkout. Optional closed representation
  specialization remains deliberately absent and is tracked by ISS-363.
