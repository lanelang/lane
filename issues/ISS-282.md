# ISS-282: Stop the example fixture timeout from misattributing regressions

## Description
Before the 2026-08-02 runtime dependency upgrade,
`examples/valid/78_structural_derivation.lane` took about 57s against the
fixture runner's 60s timeout, leaving roughly 5% of headroom. Any change that
added a few percent of compiler overhead could push it over, and the failure
read as a timeout in the example rather than as a cost added elsewhere.

This already happened. While narrowing the interface closure in ISS-279, a first
implementation that walked each interface three times cost about 3.5% and turned
that fixture red. The report gave no indication that the cause was a small
uniform overhead rather than something wrong with structural derivation, and
distinguishing the two took a baseline run with the change stashed.

The same generated module was fast under wasmtime and slow under the previous
Wasmoon dependency set, but that comparison did not isolate the triggering
module property or the responsible runtime component. Updating the external
runtime dependencies changed the real `lane run` measurement from about 58s to
7.72s, restoring enough headroom that fixture-specific timeout policy is no
longer warranted.

## Design
Keep the shared 60s timeout and update the external runtime dependency set. Do
not add fixture-specific policy after the measured case falls well below the
shared budget. ISS-280 still owns the independent structural-depth concern; the
dependency upgrade does not establish a flattened-depth causal result.

## Acceptance Criteria
