## Description
The WebAssembly-only migration and Wasmoon 0.12.6 upgrade passed local checks,
but the release contract needs one durable, current baseline. Historical test
and optimization evidence predates the removal of the semantic runtime.

## Design
Use the existing public compiler and command boundaries. Pin and record the
Basic revision and Wasmoon dependency family, run native compiler checks, the
complete examples corpus, Basic under both Wasmoon execution modes, and the
Lane WebAssembly Profile feature probes. Inspect emitted raw Wasm through its
public module contract to prove that legacy Lane runtime imports and container
metadata are absent.

Prefer strengthening the existing quality gate or public black-box tests over
adding a second integration script. Build `lane.exe` once per gate.

## Acceptance Criteria
- [ ] The exact Basic revision and Wasmoon dependency family are recorded.
- [ ] Native check, formatting, tests, release build, full examples and Basic
      suite pass at the pinned revisions.
- [ ] Wasmoon interpreter and JIT execute the same profile probes and Basic
      behavior.
- [ ] A public contract test verifies `_start`, required `memory`/WASI imports,
      and absence of the deleted `lane.runtime.v1`, `lane.entry`, and linked
      executable container.
- [ ] CI invokes the durable release gate without rebuilding Lane redundantly.
