## Description
The core module compiler depends on `lanec/analysis` to produce unused-binding,
unused-declaration, unused-generic-parameter, and unused-import warnings.
`analysis` also owns completion, semantic workspace snapshots, navigation, and
other editor-oriented behavior. This reverses the intended dependency direction
between compiler semantics and tools.

## Design
Move compile-time lint fact collection and diagnostic production to a dedicated
`lanec/lint` package that depends only on the resolved/checked compiler layers
and shared diagnostic infrastructure. Both module compilation and semantic
analysis may consume that package.

If warning collection needs reusable semantic facts, move only those facts to
the lint boundary. Do not make the core compiler depend on completion or
workspace-analysis models and do not duplicate warning algorithms.

## Acceptance Criteria
- [x] `lanec/module/compile` no longer imports `lanec/analysis`.
- [x] One package owns each compiler warning algorithm and diagnostic wording.
- [x] Analysis and compilation report identical warning identities, spans, and ordering for the same source.
- [x] The lint package has no dependency on completion, LSP, workspace snapshots, or host services.
- [x] Warning examples and focused diagnostic regressions remain unchanged.
- [x] Generated package interfaces show a one-way compiler-to-tool dependency graph.
- [x] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
