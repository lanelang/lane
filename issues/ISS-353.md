# ISS-353: Preserve Wasm runtime failures without Linux longjmp aborts

## Description
The current Linux native suite aborts while the Wasm backend propagates an
intentional runtime-import failure from an entry function. The failing public
backend regression is `Wasm entry failures clean initialized global roots`:

```text
*** longjmp causes uninitialized stack frame ***: terminated
RUNTIME ERROR: abort() called
.../wasmoon_jit/native_context_execution.mbt:226 at NativeJITContext::call_trampoline
.../wasmoon/jit/ffi_jit.mbt:346 by JITContext::call_multi_return
.../wasmoon/jit/jit_runtime.mbt:521 by JITModule::call_with_context
```

The failure reproduces on native Linux/aarch64 and Linux/x86_64 under QEMU,
while the same suite passes on macOS. It prevents the Ubuntu native gate from
validating unrelated cross-platform changes. The intended result is the typed
`RuntimeImportFailure` followed by initialized-global cleanup; the host process
must not abort while transporting that failure.

## Design
First minimize the failure at the Wasmoon JIT boundary and establish whether a
native trap crosses an invalid `setjmp`/`longjmp` lifetime or Lane invokes the
JIT through an unsupported re-entrant cleanup path. Assign the fix to the owner
of that control-transfer contract. If the defect is upstream, track the exact
Wasmoon fix and update the dependency; do not catch SIGABRT, skip Linux, or
replace the JIT execution with an interpreter fallback.

LoisVM must continue to expose one typed execution outcome in both backends.
Cleanup of initialized globals must run after a failed entry without changing
the original failure classification, leaking roots, or invoking a second
execution path.

## Acceptance Criteria
- [ ] A minimized Linux reproduction identifies the invalid control-transfer boundary.
- [ ] Wasm/JIT returns the original typed `RuntimeImportFailure` on Linux instead of aborting the host process.
- [ ] Initialized global roots are released after the failed entry.
- [ ] Interpreter and Wasm/JIT preserve the same failure classification and cleanup result.
- [ ] No Linux skip, signal catch, interpreter fallback, or test-only runtime path is introduced.
- [ ] The regression passes on native Linux/aarch64, Linux/x86_64, and macOS.
- [ ] `moon info`, `moon fmt`, `moon test --target native`, and the integration gate pass on Ubuntu.
