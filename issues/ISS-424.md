# ISS-424: Remove mandatory logical call-depth instrumentation

## Description
Every emitted Physical function currently increments, checks, and later
decrements a mutable logical call-depth global, even when the execution
configuration supplies no limit. The policy contributes almost the entire
current Wasm runtime-guard expansion and makes an optional host budget part of
the ABI and every function body.

Lane now has one WebAssembly target and one supported Wasmoon execution
runtime. Native Wasm stack exhaustion is already a terminal engine trap under
the single-shot execution-instance contract. Maintaining a second mandatory
call-stack model in generated code is therefore redundant execution policy,
not program semantics.

## Design
Remove logical call depth from the public execution configuration, runtime
control ABI, emitted globals, function prologues, return paths, tail-call paths,
and failure decoding. Ordinary artifacts rely on the Wasm engine's stack
behavior and report stack exhaustion as `EngineTrap`.

Retain the canonical live-heap-byte limit and external interruption. If a
future deterministic execution budget is required, it must be an explicit
runtime fuel or instrumented execution profile rather than unconditional code
in every Lane function.

## Acceptance Criteria
- [x] `ExecutionConfig`, runtime-control ABI, and public generated interfaces no
      longer expose logical call depth.
- [x] Emitted Wasm contains no call-depth globals, per-function depth prologue,
      return decrement, tail-call adjustment, or call-depth failure code.
- [x] Live-heap limits, interruption, Fatal, normal instance-global cleanup,
      and single-shot execution behavior remain covered.
- [x] Documentation identifies engine stack exhaustion as an engine trap and
      does not promise a portable logical call-depth limit.
- [x] Explore records the structural reduction for the coroutine scheduler and
      pinned Basic entry without changing Physical Program metrics or output.
- [x] `moon info`, `moon fmt`, strict native check, native tests, valid examples,
      dual-engine representative executions, and Basic tests pass.

## Close Notes

- Removed call depth from `ExecutionConfig`, the runtime-control ABI, exported
  globals, Wasm function emission, control transfers, and failure decoding.
  Runtime failure codes are now owned by a shared structured ABI instead of
  duplicated integer conventions in the emitter and loader.
- The scheduler Physical Program remains 58 functions / 344 instructions / 408
  slots while its Wasm size falls from 4,983 to 4,097 instructions. The Basic
  Physical Program remains 378 / 4,672 / 4,067 while Wasm falls from 44,218 to
  38,480. Runtime-guard expansion is 29 instructions for each input.
- JIT and interpreter executions preserve scheduler output `1112211322` and
  unqualified-effect output `unqualified operations=40`.
- Verified with `moon info`, `moon fmt`, strict native check, 1,730 native
  tests, all valid examples, and all 12 Basic test commands. The installed
  release binary completed `../basic/test.sh` in 1.12 seconds on this host.
