# ISS-308: Enforce effect-flavor laws in the Buslane verifier

## Description
CONTEXT.md states the law: an External-flavored Effect Row Variable "admits
only rows of External Effects". Selective CPS reads flavors to decide what must
be discharged (`callable_shape.mbt`, `context_schema.mbt`), so the law is
load-bearing. But `grep flavor modules/buslane/verify.mbt` finds nothing — no
verifier anywhere (including lanec's extended-IR verifier) enforces it. Three
measured manifestations:

1. Instantiation is flavor-blind. `insert_verified_argument` (verify.mbt:1256)
   checks kind only, so applying `Forall([R : Effect, flavor=External], ...)`
   to an algebraic singleton row verifies clean. Downstream,
   `effect_term_is_algebraic(Parameter(R))` answers false while R now stands
   for an algebraic effect: the lowering will classify an effect it must
   discharge as residual.
2. Equality is flavor-blind. `binders_compatible` (buslane.mbt:509) compares
   binder kinds but not flavors, so `Forall([E : Algebraic], T)` is
   definitionally equal to `Forall([E : External], T)` — the flavor can be
   laundered through an equality-gated position.
3. `remove_handled_effects` (verify.mbt:1563) treats every `Parameter` term as
   an open row that may contain the handled effect. An External-flavored row
   cannot, so the verifier is needlessly lenient about handlers over rows that
   provably lack the handled effect.

One root cause: flavor is recorded metadata with no typing rule consuming it
inside buslane.

## Reproduction
```moonbit
let algebraic = metadata.define_effect("Alg", [])
let residual_row = metadata.define_type_parameter("R", Effect, flavor=External)
// g : Forall([R^External], () -> Unit ! R),  h = g[{Alg}]
// verify_program(program).is_ok() == true   // must be a flavor diagnostic
```

## Design
Give flavor a typing rule, uniformly: an effect argument substituted for an
External-flavored parameter must contain only non-algebraic terms
(`effect_term_is_algebraic` false for every term). Make binder compatibility
require flavor agreement for Effect-kind binders (decide whether definitional
equality demands equal flavors and whether consumability may relate them
directionally — an External variable ranges over fewer rows). Let
`remove_handled_effects` consult the flavor before declaring a row open. Add a
dedicated diagnostic kind; do not overload KindMismatch.

## Acceptance Criteria
- [x] Instantiating an External-flavored parameter with a row containing an algebraic term is a verifier diagnostic.
- [x] Flavor participates in binder compatibility with a written rule in CONTEXT.md.
- [x] `remove_handled_effects` distinguishes flavored rows, with a test for a handler over a purely-External row.
- [x] Existing CPS companion tests (External-flavored `%residual` binders) stay green.

## Close Notes
Flavor now has three typing rules, each with one owner, all decided by the
existing predicate `effect_term_is_algebraic` — no new classification logic.

- Instantiation: `VerifyContext::verify_argument_flavor` reports the new
  `EffectFlavorMismatch(parameter~, argument~)` when an argument paired with
  an External-flavored declared parameter contains any algebraic term. It is
  called from both substitution builders (`insert_verified_argument`,
  `insert_verified_binder`) and from nominal type application in
  `synthesize_type_kind`, so declared types carrying dictionary-shaped
  applications are covered too. Higher-kinded application is deliberately out
  of scope: kinds carry no declarations, and flavor is a property of declared
  row variables, not of kinds — the boundary is written into CONTEXT.md.
- Binder compatibility: `definitional_equality_context`'s
  `binders_compatible` requires equal flavors for Effect-kind binders, in
  definitional equality and consumability alike. The directional reading (an
  External variable ranges over fewer rows) could be sound but has no
  measured need, so both relations stay strict; the decision and rationale
  are recorded in CONTEXT.md's Effect Row Variable Flavor entry.
- Open rows: `remove_handled_effects` now asks per handled effect whether an
  open row's flavor admits it — an Algebraic row variable conceals anything,
  an External one only non-algebraic effects — so a handler over a purely
  External row that never names its algebraic effect is an `EffectMismatch`.

Regressions (blackbox): the issue's reproduction (External row instantiated
with an algebraic singleton → diagnostic; Empty/Io/External/unions admitted),
flavor-distinguishing equality and both consumability directions, the
purely-External-row handler diagnostic with the Algebraic-row contrast, and
constructor-parameter flavor enforcement inside a declared value type.
Red/green measured where old API permits: the binder-compatibility test alone
fails against the pre-fix relation (cross-flavor Foralls compared equal); the
other three reference the new diagnostic and pin the fix by construction.

Verified: `moon check --target native --warn-list +73` at the pre-existing
baseline (9 warnings, none in buslane); `moon test --target native`
1443/1443 including every CPS companion test; examples gate exit 0 against
the pinned fixture; `.mbti` drift is exactly the new diagnostic case. Also
replaced the two deprecated `try?` uses this review's ISS-307 tests had
introduced.
