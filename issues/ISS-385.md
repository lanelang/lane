# ISS-385: Carry representation families through callable-valued data fields

## Description
ISS-384 gives a closed generic data instance its own complete representation
family. A remaining higher-order case stores a callable in that family while
the callable parameters or result themselves carry nominal data. The current
callable ABI key describes physical values but does not carry the selected
nested representation-family contract. Specializing such a field can therefore
make the stored callable and its representation worker disagree about the
family of a returned value.

The Yield, Flip, State, Coroutine, and structural-derivation examples exposed
this as bytecode `DataValue` mismatches. ISS-384 now rejects callable-valued
storage before creating a family, so these programs correctly retain their
declaration ABI.

## Design
Make the callable-instance plan own a family-aware callable contract. A
callable stored in a specialized data field must name the complete family map
for every nominal parameter, result, capture, and nested callable position.
The adapter key, representation worker, environment layout, indirect-call ABI,
and bytecode verifier must consume that same contract. Do not infer nested
families from `Reference` layout or add them while emitting a body.

Accept the higher-order family only when the complete callable use graph is
closed and every producer and consumer selects the same family map. Otherwise
retain the declaration family. Generic callable fallback remains available.

## Acceptance Criteria
- [ ] Canonical callable ABI keys include selected nominal representation
      families for parameters, results, captures, and nested callables.
- [ ] Callable-valued constructor fields and their workers consume one complete
      immutable family-aware ABI contract.
- [ ] Open, existential, recursively expanding, or incompatible callable uses
      retain the declaration family without partial specialization.
- [ ] Yield, Flip, State, Coroutine, and structural-derivation regressions pass
      under JIT and `--no-jit` with no `DataValue` mismatch.
- [ ] The Coroutine Scheduler strictly reduces its recorded adapters and
      erase/unerase bridges without increasing another IR scale.
- [ ] `moon info`, `moon fmt`, `moon check --target native --warn-list +73`, and
      `moon test --target native` pass.
