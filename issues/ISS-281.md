# ISS-281: Make the explored Wasm stage the module that is actually emitted

## Description
The `wasm` stage of an Explore Report does not round-trip into a valid module,
so the IR explorer's view of the backend cannot be trusted or handed to other
tools.

Reproduction: run `lane explore -o report.html FILE:ENTRY`, take the `wasm`
stage text, and parse it with `wasm-tools`. The text is complete, carries no
truncation marker, and passes syntactic parsing, but fails validation:

```
examples/valid/78_structural_derivation.lane
  type mismatch: values remaining on stack at end of block  (offset 43090)
examples/valid/83_utf8_string_char_i32.lane
  type mismatch: expected i64, found i32                    (offset 2477)
```

Both programs run correctly through `lane run`, which executes generated
WebAssembly. Every Wasm engine validates before executing, so the emitted module
is necessarily valid. The rendered text is therefore not the emitted module: the
explorer's Wasm printer is a separate path from emission, and it is not
faithful.

`wat2wasm` from wabt rejects the same text earlier, on `(table ... (ref.null
func))` and on `tag`, because it predates those proposals; `wasm-tools` accepts
the syntax and rejects the types, which is the meaningful signal.

This was found while trying to attribute the slowdown in ISS-280 to either our
code generation or the Wasmoon engine. Compiling the same module with a second
engine is the decisive experiment, and this defect blocks it.

## Design
Render the stage from the module that is actually emitted rather than from an
independent printer: emit the module, then disassemble those bytes for display.
That makes the stage faithful by construction and removes a second
representation that can drift.

If a separate printer must stay, it needs a round-trip check: emit, print,
re-parse, validate, and compare against the emitted bytes.

Exposing the emitted bytes is worth considering alongside this, since attributing
backend behaviour to an engine requires feeding the real module to that engine.

## Acceptance Criteria
- [ ] The `wasm` stage text of an Explore Report parses and validates as a
      WebAssembly module.
- [ ] A test covers round-tripping the stage for a program whose module is
      non-trivial, including one with `tag` and a table initializer.
- [ ] The emitted module can be obtained for external analysis.
