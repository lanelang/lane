## Description
Field access on a type owned by a transitively imported module reports
`E3100 unknown field` in the language server while the same source compiles
cleanly through `lane check` and `lane compile`.

Reproduction: module `A` declares `pub struct TypeA { field : I64 }`, module `B`
imports `A` and exports a value or function whose type is `TypeA`, and a
downstream module imports only `B` and writes `x.field`. The batch compiler
accepts it. The language server rejects it.

Two front-end drivers each construct the interface environment a module
compiles against, and they disagree:

- `module/compile/frontend.mbt` passes direct imports to `resolve` and the
  transitive interface closure to `typecheck`, with values and optimization
  hints removed from non-direct interfaces.
- `analysis/semantic_workspace.mbt` builds one direct-imports-only environment
  and passes the same value to both stages.

Type checking builds `CheckedDeclarationEnvironment` by walking
`imported_environment.modules`. Under the analysis driver that environment
lacks `A`, so `checked_struct` finds no declaration for `TypeA`, the deferred
field branch in `synthesize_checked_field` fails its guard, and `UnknownField`
is reported.

The defect is not a missing closure call in one file. The rule "resolve sees
direct imports, semantic lookup sees the transitive interface closure, only
direct imports contribute values" is a language rule with no owner. It is
currently spelled out three times: twice as private helpers in
`module/compile`, and once as the `BuslaneLoweringImports` pair type in
`elaborate/buslane_lowering`. The analysis driver never spelled it out at all.

Two further consequences of the same root in the analysis driver:

- `imported_symbol_metadata` is direct-only, so the symbol registry lacks
  metadata for transitively reachable types even once the environment is fixed.
- Cache invalidation compares only direct imports against `changed_interfaces`,
  so editing `A` in a way that leaves `B`'s presentation fingerprint unchanged
  leaves downstream modules holding stale nominal shapes.

## Design
Move the rule into the `Milky2018/lanec/module` package as one explicit type
and make every driver consume it.

```
pub(all) struct ModuleImportEnvironments {
  direct : ImportedEnvironment     // name-visible imports; drives resolve
  available : ImportedEnvironment  // transitive interface closure
}
pub fn ModuleImportEnvironments::from_available(
  direct_module_paths : Array[String],
  available : ImportedEnvironment,
) -> ModuleImportEnvironments
pub fn ModuleImportEnvironments::typecheck_environment(
  self : ModuleImportEnvironments,
) -> ImportedEnvironment
```

Closure edges come from `ModuleInterface::type_references` and
`effect_references`. Those arrays already accumulate transitively during
interface construction, and they are derivable from interface artifacts alone,
so the rule holds for source-set compilation, separate compilation, and the
language server without needing a source-level import graph.

Value visibility stays a derived view rather than a stored field. Buslane
lowering walks `available` interface values to collect type dependencies, so
`available` must stay unstripped; only `typecheck_environment` hides values and
optimization hints from non-direct interfaces.

Non-goals: no change to interface artifact schema, no transparent re-export of
imported types, and no change to which modules a driver must be given.

## Close Notes
The import-environment rule now has one owner,
`@module_interface.ModuleImportEnvironments` in
`modules/lanec/module/import_environment.mbt`. It exposes `direct` for name
visibility, `available` for the transitive interface closure, and
`typecheck_environment()` as the derived view that hides values from non-direct
interfaces. The closure walks `ModuleInterface` type and effect references, so
it is derivable from interface artifacts alone.

Removed the duplicated spellings: `imported_interfaces`,
`imported_interface_closure`, `collect_imported_interface_paths`,
`direct_imported_interfaces`, and `typecheck_imported_interfaces` in
`module/compile/frontend.mbt`, `imported_interfaces_from_checked_modules` in
`module/compile/lowered.mbt`, and the `BuslaneLoweringImports` pair type in
`elaborate/buslane_lowering/model.mbt`.

The analysis driver now builds the shared type in `module_import_environments`,
feeds `direct` to resolve and `typecheck_environment()` to type checking,
derives symbol metadata from the closure, and invalidates against the closure.
`CachedModuleGraph::transitive_dependents_of_slot` replaces direct-dependent
propagation in `rebuild_dirty_modules`. Completion splits the two environments
explicitly: module-qualified candidates stay on `direct`, field candidates use
`available`.

In Buslane lowering, `seed_unimported_owner_visible_members` seeds field
selectors and variant data constructors for closure-reached types, and
`seed_imported_variant_constructors` is now shared with the direct-import path.
Struct data constructors stay direct-only because building a value names the
type, which still requires an import; this keeps the minimality asserted by
"transitive public dependencies add only required nominal imports".

Vocabulary added to `CONTEXT.md`: **Direct Import Environment**, **Reachable
Interface Closure**, and relationships tying **Owner-Visible Members** to the
closure.
