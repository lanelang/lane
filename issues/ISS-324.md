# ISS-324: Keep post-synthesis diagnostics inside the expression frame

## Description
`check_expr` and `check_function_implementation` report their consumer-facing
`TypeMismatch` after `synthesize_expr` has popped the current expression frame.
Normalization also happens after that frame. These diagnostics therefore lose
the expression node even though failures reported during synthesis retain it.

## Design
Give expression framing one owner. Split framed dispatch from the public
synthesis entry so synthesis, normalization, and consumer checks can all run
under exactly one `Expression` frame without producing duplicate frames.

## Acceptance Criteria
- [x] Consumer type mismatches retain the expression label.
- [x] Normalization failures retain the expression label.
- [x] Nested expressions still receive one expression frame each.
- [x] Existing diagnostic kinds and verification results are unchanged.

## Close Notes
`synthesize_expr_contents` now owns dispatch and normalization while its caller
owns the expression frame. Plain synthesis, consumability checks, and exact
function-implementation checks each enter one frame and keep it active through
their post-synthesis diagnostics.

Existing structured snapshots now show the concrete `TypeApply`, `Ref`,
`Literal`, `Function`, or `Call` node on consumer mismatches and normalization
failures; no diagnostic kind or verification decision changed.

Verified with `moon check --target native --warn-list +73`, `moon test
modules/buslane --target native` (87/87), the full `moon test --target native`,
`moon info`, and `moon fmt`.
