## Description
Rebuild the source-effect specialization boundary around an immutable,
demand-driven plan. The current implementation mixes reachability, retention
policy, instance discovery, metadata allocation, and expression rewriting. It
also retains an entire forwarding closure when any symbolic use is found, so a
definition cannot be both retained generically and specialized at concrete use
sites.

The completed phase must preserve the established source-effect representation:
each source effect parameter becomes a static residual effect plus an explicit
higher-kinded companion, and runtime layout remains determined only by a
normalized concrete type or an in-scope witness.

## Design
The target phase has four explicit steps: classify each reachable use after
substitution and normalization, compute a fixed-point `SpecializationPlan`,
allocate every planned declaration exactly once, and mechanically rewrite the
program from that immutable plan. Planning is read-only; rewriting cannot
discover instances or choose retention policy.

This epic does not change Lane source syntax, ordinary type-parameter
polymorphism, the CPS companion ABI, or the LoisVM instruction set.

## Close Notes

Rebuilt effect specialization as a four-stage compiler phase: classify uses
after substitution, compute a read-only fixed-point plan, allocate every
planned callable and nominal-data target exactly once, then mechanically
rewrite against those identities. Planning now covers top-level and lexical
definitions, recursive groups, mixed symbolic/concrete demand, and complete
nominal constructor families.

Moved the phase into `modules/lanec/effect_specialization`. Its public surface
is limited to `specialize` and its owner-local error contract; executable
elaboration only orchestrates the phase and adapts the error. Internal files
separate classification, planning, allocation, rewriting, substitution, and
their focused white-box tests.

The regression shield covers real examples 37 and 45 at the lifted boundary,
metadata ownership, missing-plan failures, higher-kinded companions, and
direct-versus-forwarded behavior across all three execution tiers.
