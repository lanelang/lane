# ISS-266: Make module compilation phases explicit in types

## Description
After type checking, module compilation constructs a `CompiledModule` whose
object contains empty Buslane metadata, terms, externals, entries, exports, and
imports. A later whole-set lowering pass replaces that placeholder with the
real object. The type therefore claims that a module is compiled before its
required lowered representation exists.

## Design
Introduce a private checked-module phase value containing the checked source,
interface, diagnostics, exported symbol metadata, and fingerprints needed by
later modules. Lowering consumes checked modules and is the only operation that
constructs a `CompiledModule` and complete `ModuleObject`.

Delete placeholder object construction and overwrite-style
`attach_lowered_object` plumbing. Preserve module ordering and imported
interface availability without weakening the phase distinction.

## Acceptance Criteria
- [ ] No `CompiledModule` or `ModuleObject` is constructed with placeholder empty lowered fields.
- [ ] A private checked-module type represents the post-typecheck/pre-lowering phase.
- [ ] Only successful Buslane lowering can construct a compiled module object.
- [ ] Imported interface and symbol visibility behavior is unchanged across module order.
- [ ] Object and interface fingerprints remain deterministic for identical inputs.
- [ ] Tests cover a multi-module success and a lowering failure without exposing a partial compiled module.
- [ ] `moon info`, `moon fmt`, focused tests, `moon test --target native`, examples, and `git diff --check` pass.
