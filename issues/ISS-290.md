## Close Notes
Not reproducible. Inference from arguments works for every shape tried:

- `fn[E : Effect] run_all(tasks : () -> Unit ! E) -> Unit ! E` applied to a
  function performing `Io`, inferring `E := { Io }`
- the same applied to a pure function, inferring `E := {}` — the case the
  reported `[{}]` workaround would have been for
- two arguments at different rows, inferring from both
- a function literal argument
- `fn[A, E : Effect] handle_probe(task : () -> A ! { Probe, E }) -> () -> A ! E`,
  where the parameter is one term of a union and inference has to subtract the
  known part

`E3010` does fire, and correctly, when a template row holds more than one
tracked row variable or a template singleton matches more than one actual term.
Both are genuinely ambiguous, and the message is specific rather than
misleading:

```
error[E3010]: cannot infer effect arguments uniquely for `both`
   |   both(probing)
   |        ^^^^^^^ effect row `{ E, F }` has multiple matches in `Probe`
   = note: Lane does not backtrack between multiple effect-row matches
   = help: pass explicit generic arguments for `both` to choose the intended
           effect instantiation
```

It names the template row, the actual row, why the match was not unique, and
what to do. The remaining possibility is that the reporter hit a genuinely
ambiguous signature and read the one-shot matching rule as a defect. That is a
design limit worth revisiting on its own evidence, not a diagnostic problem.
