## Description
Refactor name resolution so canonical imported module identity is not conflated
with the source-local qualifier name, then implement alias resolution and
fixed-sugar provider lookup on that model.

## Design
Maintain canonical imported modules keyed by complete ModulePath and lexical
Module Bindings keyed by their authored qualifier. Bindings point to imported
modules. Authored access uses bindings; structured compiler-generated targets
use canonical imported modules. Resolve both immediately to the same symbols.
Track alias conflicts and import uses without import-order ownership or
List/Tuple-specific lookup branches.

## Acceptance Criteria
- [x] `import M as X` permits `X.member` and rejects authored `M.member` unless another import binds `M`.
- [x] Module alias conflicts use ordinary module-name ambiguity rules; distinct aliases for one module are allowed.
- [x] Alias bindings coexist with type names and retain existing ambiguity behavior for conflicting value field chains.
- [x] Aliases never traverse shared ModulePath prefixes as module hierarchy.
- [x] List/Tuple sugar resolves through an aliased provider import and produces the same resolved symbols as authored alias access.
- [x] Canonical sugar use marks all imports providing its module target as used; authored access marks only its binding.
- [x] Resolved types, interfaces, artifacts, fingerprints, and link dependencies retain canonical module identity.
- [x] Resolve and compile regressions cover every rule above.
