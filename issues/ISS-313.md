## Description
Two complete, independent renderers own the Buslane surface syntax: pretty.mbt
implements `Pretty` for every core type (753 lines), and text/core.mbt defines
its own `type_doc`/`effect_doc`/`expr_doc` family (757 lines, 49 Document
builders, zero calls into the Pretty impls). Even the effect-flavor prefix
logic is written twice (`type_parameter_flavor_prefix` in pretty.mbt:178,
`type_parameter_flavor_doc` in text/core.mbt:361).

CONTEXT.md already states the law being violated: "Buslane display output and
canonical text should share one core-language syntax strategy rather than
defining separate expression languages." Under the one-owner-per-fact rule,
every future syntax change (as with the recent flavor addition) must be made
twice, and nothing tests that the two renderers agree.

## Design
Decide the owner: either the canonical text renderer is the single syntax
authority and the Pretty impls delegate to it (display may keep a compact mode
as a parameter, not a second implementation), or the Pretty impls are the
authority and text/core.mbt consumes them. Then delete the loser. If the two
surfaces intentionally differ (display omits uniques, say), the shared core
must still own every construct's spelling, with the difference expressed as a
rendering option in one place.

## Acceptance Criteria
- [ ] One function family owns each construct's spelling; the other surface delegates.
- [ ] The flavor prefix, and every future syntax addition, has exactly one definition site.
- [ ] A round-trip test covers the canonical path (parse . render == id) for a program exercising flavors, hidden witnesses, and handlers.
