# ISS-315: Propagate checked normalization through public semantic relations

## Metadata
- Type: bug
- Status: closed

- Assignee: codex

## Description
`Type::normalize` and `Effect::normalize` report non-terminating beta reduction
with `TypeNormalizationError`, but the five public metadata-aware semantic
relations erase that checked failure with `try!`. A legal caller can therefore
still turn a bounded normalization failure into a process abort by using
`types_definitionally_equal`, `type_is_consumable_as`,
`effects_definitionally_equal`, `effect_is_subeffect_of`, or
`canonicalize_effect`.

`ExpressionFactsQuery::has_empty_effect` repeats the same defect after
expression synthesis. Compiler phases consequently cannot distinguish malformed
or non-normalizing intermediate types from an ordinary negative semantic
answer, and they cannot attach phase-owned compiler-defect context.

## Design
Make each public semantic relation directly raise `TypeNormalizationError` and
remove the private checked/public panicking wrapper pairs. Propagate the checked
failure through phase internals, then translate it exactly once at the owning
phase boundary into a structured compiler-defect variant. The Buslane verifier
continues to recover locally, record `TypeNormalizationFailure`, and treat it as
a blocking diagnostic. `ExpressionFactsQuery::has_empty_effect` returns an
`Err` containing that diagnostic instead of aborting.

## Acceptance Criteria
- [x] All five public semantic relations expose `TypeNormalizationError` without `try!` or duplicate checked wrappers.
- [x] Every compiler phase propagates normalization failures and translates them to a structured compiler-defect at its public boundary.
- [x] The verifier records normalization failure as a blocking diagnostic.
- [x] `ExpressionFactsQuery::has_empty_effect` returns a normalization diagnostic in `Err`.
- [x] Black-box runaway-beta tests cover all five public semantic relation entry points and `has_empty_effect`.
- [x] `moon test --target native`, `moon info`, and `moon fmt` pass.

## Close Notes
Removed the five panicking public wrappers and made their checked normalization
failures part of the generated Buslane interface. The verifier now converts the
same error into a blocking `TypeNormalizationFailure`, including the
`has_empty_effect` query. Effect specialization, effect lowering, core
optimization, executable-entry validation, and LoisVM lowering preserve the
failure under phase-owned compiler-defect variants; the compile facade exposes
entry-effect classification as an explicit `Result`.

Added black-box runaway-beta regressions for all five semantic relations and
the expression-facts query. Validation passed `moon test --target native`
(1429/1429), `moon check --target native --diagnostic-limit 500`, `moon info`,
`moon fmt`, and `git diff --check`.
