## Description
The repository contains substantial native tests and a project-specific example
smoke script but has no checked-in CI configuration. Warning, formatting,
testing, example, artifact, and coverage regressions therefore depend on
developers running the complete local gate set manually.

## Design
Add one minimal GitHub Actions workflow for the repository's supported native
compiler path. It runs check, formatting, the full native suite, builds
`lane.exe` once, and passes that exact executable to the examples checker.

Checkout initializes the pinned Basic submodule recursively. The workflow does
not provide an ambient `LANE_HOME` or `LANE_SMOKE_BIN`; the examples checker
owns those values for the child process so the fixture cannot accidentally use
a developer installation.

## Acceptance Criteria
- [x] Pull requests and main-branch pushes run `moon check --target native --warn-list +73`.
- [x] CI runs `moon fmt --check` and `moon test --target native`.
- [x] CI builds one release `lane.exe` and passes it explicitly to `tools/check-lane-run-examples.sh`.
- [x] Checkout initializes the pinned Basic gitlink recursively and the examples checker rejects a missing, mismatched, or dirty fixture.
- [x] A clean runner initializes the MoonBit registry before resolving workspace dependencies.
- [x] CI does not depend on an ambient `LANE_HOME` or `LANE_SMOKE_BIN`.
- [x] Repository documentation lists the local commands corresponding to every CI gate.
