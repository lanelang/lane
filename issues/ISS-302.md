## Description
Move effect-parameterized type and data-constructor instance discovery into the
immutable specialization plan. Callable and nominal demands must share
reachability scheduling without being collapsed into one overly generic model.

## Design
Use a separate `DataInstanceDemand` keyed by source type and canonical concrete
effect bindings. Record the complete source constructor family for the
allocation phase so expression rewriting can eventually perform only lookups.

## Acceptance Criteria
- [x] Reachable nominal applications produce planned data instances.
- [x] Definitionally equal effect rows deduplicate to one data instance.
- [x] Every planned data instance records its complete source constructor family.
- [x] Planning performs no target allocation or metadata mutation.
- [x] The plan records every reachable retained constructor and operation declaration that needs type rewriting.
- [x] Unreachable declarations and their transitive metadata references contribute no specialization or retained-rewrite work.
- [x] Example 37 remains verified at every observed boundary.
