# ISS-326: Encode Buslane metadata allocator state in canonical text

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: area/buslane, area/text, round-trip, correctness, agent
- Assignee: codex
- Created: 2026-08-04
- Updated: 2026-08-04
- External ref: modules/buslane/pretty.mbt, modules/buslane/text/parser.mbty

## Description
Canonical text originally omitted the metadata name allocator. Follow-up review
also found that programmatic registries admitted negative uniques and represented
the next allocation as an unchecked `Int`; the maximum value therefore wrapped
negative on the next `define_*`. Those states could not round-trip through text
or the unsigned binary encoding.

## Design
Represent a unique with a checked `BuslaneUnique` and the allocator as
`Fresh(next) | Exhausted`. Encode that state explicitly in text and binary;
delete inference from declarations. Text import must collect declarations by
explicit ID and reject duplicate or sparse tables before constructing the
registry. Registry identity validation owns the program-wide unique and
allocator-state invariant, and the Buslane verifier consumes it as an
independent backstop. Every `define_*` performs checked allocation and leaves
the registry unchanged on exhaustion.

## Acceptance Criteria
- [x] Empty metadata with a nonzero `next_unique` round-trips exactly.
- [x] Canonical text explicitly carries allocator state.
- [x] The parser no longer derives allocator state from declarations.
- [x] Existing program round-trip tests remain green.
- [x] Text import rejects duplicate and sparse IDs in every metadata table.
- [x] Text import rejects duplicate name uniques and allocator state that can repeat a used unique.
- [x] Negative name uniques cannot be constructed or imported, and the verifier rejects an internally malformed negative unique.
- [x] The Buslane verifier rejects duplicate name uniques and allocator states that can repeat a used unique.
- [x] Allocating the maximum legal unique transitions the registry to `Exhausted` without overflow.
- [x] Allocation after exhaustion reports `MetadataNameExhausted` and leaves every metadata table unchanged.
- [x] Black-box text and binary regressions round-trip both the maximum fresh state and a valid exhausted state.
- [x] A black-box `parse -> verify -> define_* -> verify` regression proves subsequent allocation remains valid.

## Close Notes
The metadata block now starts with a mandatory `next_unique#N;` entry. The
lexer produces a typed `NEXT_UNIQUE(Int)` token, the grammar passes that value
directly to metadata construction, and the declaration-based reconstruction
function is deleted.

The black-box regression round-trips an empty registry with `next_unique = 7`.
All canonical text and structured pretty snapshots now expose the allocator
state that was already part of `MetadataRegistry` equality and the binary
codec.

Verified with `moon check --target native --warn-list +73`, `moon test
modules/buslane/text --target native` (27/27), the full `moon test --target
native` (1479/1479), `moon info`, and `moon fmt`.

### Reopened close (2026-08-04)

Canonical text import now collects each metadata family as explicit `(id,
declaration)` entries, sorts them, and rejects duplicate or sparse IDs before
constructing a registry. The old `set_at` path that filled holes with the
current declaration is gone.

`MetadataRegistry::identity_errors` is the single owner of the program-wide
name unique and allocator-bound invariant. Text import refuses registries that
violate it, while `verify_program` reports the same structured failures as an
independent backstop for programmatic and binary-decoded programs. The parser
also rejects negative `next_unique`, repeated name uniques, and allocator state
that is not strictly above every used unique.

Black-box regressions cover duplicate and sparse IDs across all six metadata
families, out-of-order dense declarations, duplicate uniques across namespaces,
and `parse -> verify -> define_value -> verify`, proving the next allocation is
fresh. Focused Buslane tests pass 121/121 and the full native suite passes
1488/1488. `moon info`, `moon fmt`, and `git diff --check` pass; the full `+73`
check reports only the pre-existing annotation warning in
`buslane/interpreter/interpreter_test.mbt`.

### Exhaustion close (2026-08-04)

`BuslaneUnique` now has checked construction over the nonnegative `Int` domain,
and `MetadataRegistry` stores `Fresh(next) | Exhausted` rather than an unchecked
integer. Allocating the maximum unique succeeds and atomically transitions to
`Exhausted`; every later `define_*` raises the structured
`MetadataNameExhausted` error before changing a metadata table. Compiler phases
propagate this failure as a structured compiler defect at their own boundary.

Canonical text uses `next_unique#exhausted`, binary codec version 7 encodes the
allocator state explicitly, and verifier identity checks share the same typed
domain. Black-box regressions cover negative text uniques, maximum allocation,
text and binary round-trip, verification after the final allocation, and stable
state after an exhausted allocation attempt.

Verified with `moon check --target native --warn-list +73`, focused Buslane
text (31/31), codec (12/12), and core (67/67) tests, the full `moon test
--target native` (1497/1497), `moon info`, `moon fmt`, and `git diff --check`.
